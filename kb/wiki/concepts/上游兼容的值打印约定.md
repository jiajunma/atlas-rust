# 上游兼容的值打印约定

Atlas 值层在 `value.rs` 与 `linear_values.rs` 中规定字符串、复合值、有理数、函数值及线性代数载荷的打印形式。源材料记录了上游格式与移植依据，但属于结构性阅读，不声称语言或数学验收；值打印兼容性仍以 HPC 语料门为准。^[atlas-core-value-layer.md:9-11, atlas-core-value-layer.md:13-52, atlas-core-value-layer.md:69-74]

## 字节保留与复合值

`AtlasString(Vec<u8>)` 保存原始字节，其 `Display` 仅提供 Unicode 编辑或调试预览，不能作为字节内容的权威表示。`Value::atlas_text` 与 `append_atlas_text` 提供不经过 Unicode 转换的打印路径：字符串原始字节置于引号内，Tuple 与 List 递归打印，Union 打印为 `value.injectorname`。相关约定见 [[AtlasString 字节保留串与原始字节打印]]。^[atlas-core-value-layer.md:20-24]

## 有理数与函数值

`Display for Value` 对 `Rational` 单独处理符号，因为 Malachite 将符号与非负分子分开存储。负值打印为 `-num/den`；即使分母为 1，也保留分母。^[atlas-core-value-layer.md:25-26]

闭包的 `Display` 只输出 `Function defined` 头部，因为此处无法取得源名表。完整多行形式由 `typed.rs` 中的 `closure_trace_string` 在回溯帧转储时渲染，对应源材料所引的 `axis.w:3254-3271`；内建函数打印为 `{print_name}`。相关主题见 [[源码位置与局部帧的回溯渲染]]。^[atlas-core-value-layer.md:27-29]

## 向量、矩阵与有理向量

`Vec32(Vec<i32>)` 保存机器 32 位整数项。向量与有理向量的分子部分共用 `write_bracketed`：各项按“最大项宽 + 1”右对齐，以逗号分隔，末项后接 `" ]"`，空时打印为 `"[ ]"`。有理向量在方括号部分后追加 `/denominator`；源材料将这些格式对应到上游 `global.w:2107-2158`。^[atlas-core-value-layer.md:45-52]

`Matrix` 以列主序保存整数项，打印时按列定宽，并使用 `"|"` 作为边框。当行数或列数为 0 时，采用 `The {}x{} matrix` 格式表示矩阵尺寸。^[atlas-core-value-layer.md:46-47]

`RatVec` 使用 `i64` 分子与 `u64` 分母，构造时对全部分子和分母取 gcd 进行规范化；分母为 0 时返回 `None`。其打印载荷因此具有构造阶段的规范化约束，详见 [[线性代数值载荷与有理向量规范化]]。^[atlas-core-value-layer.md:48-52]

## 验证与证据边界

源材料列出 11 个测试，其中 `value` 4 个、`linear_values` 3 个、`formula` 4 个。这是三个支撑模块的测试总数，不能视为打印兼容性已获验收；上游行号引用属于实现方的移植陈述，实际值打印兼容性以 HPC 语料门为准。^[atlas-core-value-layer.md:69-74]

源材料还保留了 `linear_values.rs` 关于“将在 phase-B stage B2 嵌入 `Value`”的模块自述，同时在 `Value` 变体中列出了 `Vector(Vec32)`、`Matrix` 与 `RatVector(RatVec)`。这两处记载应区分阅读，不能仅凭该自述判定当前集成状态。^[atlas-core-value-layer.md:15-19, atlas-core-value-layer.md:53-53]
