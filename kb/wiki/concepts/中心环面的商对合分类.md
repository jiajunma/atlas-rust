# 中心环面的商对合分类

中心环面的商对合分类是 [[内类布局（InnerClassLayout）]] 构造中的中心环面分支。`torus_ranks` 从根格的 Smith 基读取商对合，获得紧致（compact）、复型（complex）与分裂（split）的分类数据，再将对应字母追加到布局中。^[layout-restricted-roots.md:17-22, layout-restricted-roots.md:37-41]

## 构造与分类流程

布局使用 `InnerClass::distinguished_involution()`，依次构造单根扭转置换、进行 Dynkin 分类、判定半单因子的内类字母，随后处理中心环面。传入的 `IntegerLatticeBudget` 仅约束中心环面字母背后的 Smith 基计算，不用于半单数据。^[layout-restricted-roots.md:17-27, layout-restricted-roots.md:70-72]

`torus_ranks` 使用 `adapted_basis` 给出的根格 Smith 基，通过 `inverse.block × delta × basis.block` 读取商对合，计算中跳过零项。相关换基工具见 [[承载可观测量的适配基（adapted_basis）]]。^[layout-restricted-roots.md:37-38]

令商对合为 `inv`，实现计算 `tau1 = inv + I`，再由 `classify_plus_identity` 得到 `(compact, complex, split)`。环面字母按 `'c'`、`'C'`、`'s'` 的顺序追加，分别对应紧致、复型与分裂部分；分类主题可参见 [[整对合的 compact、complex、split 因子计数]]。^[layout-restricted-roots.md:39-41]

## 布局表示与接口边界

`InnerClassLayout` 的 Lie type 先按打印顺序排列半单因子，使 Complex 对相邻，再为每个中心环面维度安排一个 `T1`。内类字母按条目记录，其中一个 `'C'` 消耗两个 type 因子，因此字母条目与 type 因子并非始终一一对应。^[layout-restricted-roots.md:17-21]

布局与限制根系的实现互不调用。限制根系使用 `RootInvolutionData::involution()`，在构造中校验 datum 与格秩一致性，且不接收整数格预算；详见 [[内类布局与限制根系的接口边界]]。^[layout-restricted-roots.md:57-58, layout-restricted-roots.md:70-72]

## 测试锚点与证据边界

已有 GL(2) 样式的中心环面测试：商上的对合为 `-1`，最终布局得到字母 `'c','s'`，字符串表示为 `"A1.T1"` 与 `"cs"`。该例覆盖中心环面的分裂字母 `'s'`；其中的 `'c'` 不构成紧致中心环面的测试锚点。中心环面的 `'c'` 与 `'C'` 字母尚无测试锚点。^[layout-restricted-roots.md:43-46, layout-restricted-roots.md:79-82]

来源覆盖的 `layout.rs` 与 `restricted_roots.rs` 均无错误分支的失败路径测试。材料属于结构性阅读，不构成数学或正确性验收；包括 `tori.cpp:189-197` 在内的上游引用仅转录自代码注释，未核对上游原始字节。^[layout-restricted-roots.md:10-13, layout-restricted-roots.md:37-41, layout-restricted-roots.md:79-80]
