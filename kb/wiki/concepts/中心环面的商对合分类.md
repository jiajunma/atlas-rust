# 中心环面的商对合分类

中心环面的商对合分类是 [[内类布局（InnerClassLayout）]] 构造中的中心环面分支。`torus_ranks` 从根格的 Smith 基读取商对合，取得紧致（compact）、复型（complex）与分裂（split）的分类数据，再将对应字母追加到布局中。`IntegerLatticeBudget` 仅约束中心环面字母背后的 Smith 基计算，不用于半单数据。^[layout-restricted-roots.md:17-22, layout-restricted-roots.md:37-41]

## 商对合的构造与分类

布局构造使用 `InnerClass::distinguished_involution()`，依次完成单根扭转置换、Dynkin 分类与半单因子的内类字母判定，随后进入中心环面分支。布局与限制根系的实现互不调用；后者使用 `RootInvolutionData::involution()`，也不接收这一预算。^[layout-restricted-roots.md:24-27, layout-restricted-roots.md:70-72]

`torus_ranks` 使用 `adapted_basis` 给出的根格 Smith 基，通过 `inverse.block × delta × basis.block` 读取商对合，计算中跳过零项。这里的换基工具参见 [[承载可观测量的适配基（adapted_basis）]]。^[layout-restricted-roots.md:37-38]

令读出的商对合为 `inv`，实现形成 `tau1 = inv + I`，再调用 `classify_plus_identity` 得到 `(compact, complex, split)`。环面字母按照 `'c'`、`'C'`、`'s'` 的顺序追加，分别对应紧致、复型与分裂部分。^[layout-restricted-roots.md:39-41]

## 布局中的表示

`InnerClassLayout` 的 Lie type 先按打印顺序排列半单因子，并使 Complex 对相邻，随后为每个中心环面维度安排一个 `T1`。内类字母按条目记录，其中一个 `'C'` 消耗两个 type 因子；因此，字母条目与 type 因子并非始终一一对应。^[layout-restricted-roots.md:17-21]

## 测试锚点与证据边界

已有一个 GL(2) 样式的中心环面测试：商上的对合为 `-1`，最终布局得到字母 `'c','s'`，字符串表示为 `"A1.T1"` 与 `"cs"`。该例覆盖中心环面的分裂字母 `'s'`；其中的 `'c'` 不构成紧致中心环面的测试锚点。^[layout-restricted-roots.md:43-46, layout-restricted-roots.md:81-81]

中心环面的 `'c'` 与 `'C'` 字母尚无测试锚点，相关文件的错误分支也没有失败路径测试。来源属于结构性阅读，不构成数学或正确性验收；代码注释中的上游引用 `tori.cpp:189-197` 未核对原始字节，本次知识维护亦未执行 Atlas、Cargo、测试或 benchmark。^[layout-restricted-roots.md:10-13, layout-restricted-roots.md:37-41, layout-restricted-roots.md:79-81, layout-restricted-roots.md:89-93]
