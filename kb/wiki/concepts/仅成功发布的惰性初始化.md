# 仅成功发布的惰性初始化

仅成功发布的惰性初始化（success-only lazy initialization）用于按需构造 Weyl 上下文：初始化 cell 只发布完整、成功的结果；构造失败后，后续调用必须能够重试。失败的 `Diagnostic` 和首次调用的 `SourceSpan` 不应缓存到 cell 中，错误应定位到当前调用。^[weyl-context-identity-and-sharing.md:275-278, weyl-context-identity-and-sharing.md:294-297]

## 已落地的实现

Rust 的 `RootDatumHandle` 携带 `Arc<DatumWeylIdentity>`，其中为 `DatumWeylKernel`（`RootSystem`）和 `AbstractWeylGroup`（`WeylInterface`）设置两个仅成功发布的惰性 cell。进程级弱注册表按完整 datum 内容及 preference 驻留 identity，八个 handle 构造入口均经过私有 `interned` 构造器。该模型已通过 AFTER-v5 的 A1 限定验收，并以提交 `690c2b92` 落地。^[weyl-context-identity-and-sharing.md:249-261]

惰性状态同时影响可观察的共享语义：`dual(RootDatum)` 仅在 canonical target 尚未预热时，将 source 的 abstract group 安装到 target；已预热的 target 绝不被覆盖。二元 `=`、`!=`、`*` 先检查 abstract-group 的 `Arc` identity，关系检查在 `no_value` 级别也执行。因此，初始化时机与 [[dual 预热历史与 Weyl 群兼容性]] 直接相关。^[weyl-context-identity-and-sharing.md:252-255]

## 失败重试与诊断归属

仅成功发布要求将可复用的构造结果与调用相关的错误信息分开。一次失败不能让后续调用永久复用旧诊断，也不能让新的失败指向第一次调用的位置。来源特别指出，现有 `FallibleOnce` 的 poison 文本专属于 lazy real-form，不能未经修改直接复用于这里；相关问题见 [[可失败重试的惰性身份初始化]]。^[weyl-context-identity-and-sharing.md:294-297]

## 与所有权和共享设计的关系

后续共享提案将 datum 坐标下的 `RootSystem` 与抽象群的 `WeylInterface` 分为两个无反向引用的不可变层。`WeylEltContext` 持有 handle 及这两个层的 `Arc`，而两个层都不持有 handle；提案由此避免强引用环，并用 `Arc` 管理活对象、`Weak` 允许驻留槽失效、`OnceLock` 只发布完整成功结果。这一后续设计应与本轮已落地的语义修复区分，参见 [[Rust Weyl 内核与抽象群的无环所有权模型]]。^[weyl-context-identity-and-sharing.md:263-278]

这一设计针对具体的生命周期问题：`elliptic.at` 的 59 次调用只保留 characteristic polynomial 向量，临时 WeylElt 可在迭代间释放，因此仅缓存 `Weak` context 可能无法命中；反过来，把完整 context 强持有在 handle 中又会形成 `handle -> context -> handle` 强引用环。^[weyl-context-identity-and-sharing.md:222-227]

## 验证与适用边界

AFTER-v5 的接受范围是 A1 限定语义，并不授予缓存、性能、内存、高 rank 或更广数学 release。A1 fixture 也不能证明所有跨坐标生成元处理或仅由 WeylElt 维持 datum 生命周期的行为；这些仍需要额外见证与 HPC-only 的 `Weak`、work-count 单元守卫。^[weyl-context-identity-and-sharing.md:63-69, weyl-context-identity-and-sharing.md:313-318]

仅成功发布机制和自动内存管理本身不证明缓存键、共享范围或历史语义正确。后续应先完成递进语义 gate，再加入 one-build work-count 测试，最后开展同节点、交替顺序、fresh-process 的 time/CPU/RSS A/B；“59 次构造降至至多 5 次”仍是调用方层面的假设，不能作为已测加速结论，参见 [[Weyl 上下文共享的性能与内存证据边界]]。^[weyl-context-identity-and-sharing.md:294-297, weyl-context-identity-and-sharing.md:320-324]
