# 会话全流程回归测试

会话全流程回归测试通过 `session::run_source` 执行完整会话路径，在同一次回归中联合覆盖命令恢复、类型转换与求值。所述快照中的 `session_fixture_tests.rs` 共 450 行，包含 17 个测试；该模块刻意不保留已移除的动态求值器作为第二实现。^[atlas-core-regression-library.md:10-13, atlas-core-regression-library.md:30-32]

## 在测试库中的位置

全流程模块属于 [[atlas-core 回归测试库的家族组织]]。同一源包还涵盖 `session.rs` 的 201 个测试、`typed.rs` 的 133 个测试和 `domain_builtins.rs` 的 92 个测试，并按测试名称前缀描述其家族组织。全流程模块的特点是经统一会话入口联合执行上述处理阶段。^[atlas-core-regression-library.md:17-32]

`session_frame.rs` 的 18 个测试另归会话帧源包，不在本源包覆盖的四个模块之内；相关背景可参见 [[会话帧驱动的 CLI 执行模型]]。^[atlas-core-regression-library.md:9-13, atlas-core-regression-library.md:49-55]

## 原版背书与金标

[[原版背书的语言层回归测试]] 的典型模式是使用 `include_str!` 载入 `tests/math/generics/` 中的 fixture，并逐字节比对 `.oracle.stdout` 与 `.oracle.stderr`。源材料以 `session.rs` 中的 `weyl_context_core_cold_dual_original` 为例说明这一模式，没有逐项说明全流程模块中每个测试的比对方式。^[atlas-core-regression-library.md:9-13, atlas-core-regression-library.md:17-22]

每个 HPC 差分发现的差异都必须先落成回归测试。fixture 与 `.oracle.*` 金标保存在 `tests/math/generics/`，金标只能来自原版输出的完整捕获，不能使用 Rust 输出作为金标。语言层共有 244 处 `include_str!` 将 fixture 直接绑定到测试中；这一计数属于语言层整体，不是全流程模块单独的计数。^[atlas-core-regression-library.md:36-39]

## 验收与证据边界

[[HPC 验收证据链]] 包括 `tests/reference/hpc/` 下的分阶段证据 JSON、仅追加的验收账本 `tests/reference/hpc/math_acceptance_index_2026_10_01.json`，以及 `docs/HANDOFF.md` 的衔接记录。知识库不改写该验收账本。^[atlas-core-regression-library.md:40-42]

本页依据测试组织的结构性阅读，不包含逐测试内容，也不声称任何测试已经通过。测试数量与清单计数只标识 Git 基准 `964f0033` 对应的快照字节；测试的可执行正确性以 HPC 门验收为准，源材料列举的验收参照包括 632 项清单与 `atlas-core-test-inventory`。^[atlas-core-regression-library.md:9-13, atlas-core-regression-library.md:43-45]
