# 会话补全顺序与名字可见性分离

`CompletionCandidates` 将补全候选的顺序与可见性分开维护：名字按首次词法使用时的 intern 顺序登记，由独立的 active 位决定是否出现在补全结果中。候选顺序不是首次成功定义顺序；名字失效后重新激活，仍恢复到原来的 intern 位置。^[atlas-core-completions.md:22-36]

## 会话索引与存储

该类型位于 `frames` 的私有子模块 `crates/atlas-core/src/frames/completions.rs`，为补全查询维护会话拥有的名字顺序索引。模块不捕获全局缓存或运行时表，其契约规定只有命令发表（publication）改变可见性。^[atlas-core-completions.md:9-20]

`names: Vec<(Rc<str>, bool)>` 按 intern 顺序保存名字及 active 位；`indices: BTreeMap<Rc<str>, usize>` 用于去重和下标反查；`snapshot: OnceCell<Vec<String>>` 保存惰性快照。索引与有序条目共享同一个 `Rc<str>` 分配，并按需提供借用切片 API。^[atlas-core-completions.md:17-24]

## 登记、激活与快照

`intern` 遇到已有名字时直接返回下标，遇到新名字时追加一个 inactive 条目。该操作永不使快照失效，因此非 active 名字或局部名字的登记不会改变既有快照。^[atlas-core-completions.md:25-26]

`set_active` 仅在 active 位实际变化时调用 `snapshot.take()`，使快照失效。重复设置相同状态不会触发失效；测试通过指针相等检查这一行为。^[atlas-core-completions.md:27-28]

`snapshot` 使用 `get_or_init` 惰性生成结果，过滤出 active 名字并保持 intern 顺序。lexer 在名字首次出现时就进行 intern，因此顺序的建立独立于可见性；停用后重新激活不会将名字移到末尾。^[atlas-core-completions.md:29-36]

## 遗留替换接口

遗留公开 API `replace` 整体重置状态后，按调用方顺序重建，并通过 `OnceCell::from` 绕过索引直接保存传入的快照。这条路径保留调用方顺序，甚至保留重复名字：测试中的 `["b","a","b"]` 会原样返回。因此，不能把索引的去重性质直接套用于该接口保存的快照。^[atlas-core-completions.md:22-24, atlas-core-completions.md:32-34]

## 测试与证据边界

三个单元测试提供机制锚点：`no_snapshot_until_queried` 覆盖惰性生成、指针稳定性及仅在真实状态变化时失效；`visibility_and_revival_order` 覆盖可见性与恢复顺序，并检查 `Rc` 共享计数为 2；`legacy_snapshot_replacement` 覆盖替换接口的重置与保序。^[atlas-core-completions.md:40-42]

来源将惰性快照机制的行为验收归于 HPC completion AFTER 门（job `3868661`，限定范围已接受）与后续 command AFTER R2（job `3868782`，过载视图修订）。本页仅记录机制，不重述或扩展这些验收结论；相关主题参见 [[HPC 验收证据链]]。^[atlas-core-completions.md:43-45]

来源覆盖该模块全部 112 行，属于当前工作区字节的结构性阅读，不声称语言验收。关于原版 `buffer.w` 仅在查询时遍历 intern 表的描述，转述自模块注释与历史笔记，本次未独立重读上游；Git base 与字节哈希见来源所链接的阅读快照。^[atlas-core-completions.md:9-13, atlas-core-completions.md:17-20, atlas-core-completions.md:49-50]
