# 会话补全顺序与名字可见性分离

`frames/completions.rs` 是 `frames` 的私有子模块，为补全查询维护会话拥有的名字顺序索引。其核心规则是：名字按首次词法使用时的 intern 顺序排列，当前是否可见由独立的 active 位控制；名字失效后再激活，仍回到原来的位置。^[atlas-core-completions.md:9-12, atlas-core-completions.md:22-36]

## 数据结构与会话边界

`CompletionCandidates` 使用 `names: Vec<(Rc<str>, bool)>` 保存名字及 active 位，使用 `indices: BTreeMap<Rc<str>, usize>` 去重并反查下标，使用 `snapshot: OnceCell<Vec<String>>` 保存惰性快照。索引与有序条目共享同一个 `Rc<str>` 分配，借用切片 API 按需提供。^[atlas-core-completions.md:17-24]

模块不捕获全局缓存或运行时表，其契约规定只有命令发表（publication）改变可见性。名字进入索引与名字成为可见候选因此是分开的操作。^[atlas-core-completions.md:17-26]

## 顺序与可见性的更新

`intern` 遇到已有名字时直接返回下标；遇到新名字时将其追加为 inactive。该操作永不使快照失效，因此非 active 名字或局部名字的登记不会改变既有补全快照。^[atlas-core-completions.md:25-26]

`set_active` 仅在 active 位实际变化时调用 `snapshot.take()`，使下一次查询重新生成快照；重复设置相同状态不会使快照失效。测试通过指针相等检查固定了这一行为。^[atlas-core-completions.md:27-28]

`snapshot` 通过 `get_or_init` 惰性生成结果，过滤出 active 名字并保留 intern 顺序。这个顺序是首次词法使用顺序，而非首次成功定义顺序：lexer 在名字首次出现时就进行 intern，顺序的建立独立于可见性。名字被停用后重新激活，也不会被移到末尾。^[atlas-core-completions.md:29-36]

## 遗留替换接口

遗留公开 API `replace` 先整体重置，再按调用方顺序重建；随后通过 `OnceCell::from` 绕过索引，直接保存传入的快照。这条路径保留调用方顺序，也保留重复名字，测试中的 `["b","a","b"]` 会原样返回。^[atlas-core-completions.md:32-34]

## 测试与证据边界

三个单元测试分别提供机制锚点：`no_snapshot_until_queried` 覆盖惰性生成、指针稳定性及仅在真实状态变化时失效；`visibility_and_revival_order` 覆盖可见性变化与恢复顺序，并检查 `Rc` 共享计数为 2；`legacy_snapshot_replacement` 覆盖替换接口的重置与保序。^[atlas-core-completions.md:40-42]

来源将惰性快照机制的行为验收归于 HPC completion AFTER 门（job `3868661`，限定范围已接受）及后续 command AFTER R2（job `3868782`，过载视图修订）。本页只解释机制，不扩展这些验收结论；相关证据纪律见 [[HPC 验收证据链]]。^[atlas-core-completions.md:43-45]

本来源是对当前工作区字节的结构性阅读，不声称语言验收。关于原版 `buffer.w` 只在查询时遍历 intern 表的描述，转述自模块注释与历史笔记，本次未独立重读上游；Git base 与字节哈希由来源链接的阅读快照记录。^[atlas-core-completions.md:9-13, atlas-core-completions.md:17-20, atlas-core-completions.md:49-50]
