# 伴随纤维的资源预算与可恢复错误

伴随 Cartan 纤维通过 `AdjointFiberBudget` 限制整数格构造、持久存储和投影计算的资源需求，并以显式错误报告预算超限、算术溢出、分配失败及输入不一致。相关非测试代码没有 `panic` 或 `assert`。^[adjoint-fiber.md:50-62]

## 预算模型

`AdjointFiberBudget` 提供 `pub const fn new`。设 `ss` 为半单秩、`lr` 为源格秩，其预算包含三个维度：整数格预算 `integer_lattice`、持久条目上限 `max_persistent_entries` 和投影运算上限 `max_projection_operations`。^[adjoint-fiber.md:52-57]

`integer_lattice` 透传给后续整数格构造；伴随构建预检还会检查 `semisimple_rank > max_rank`，超限时以 `"semisimple rank"` 标识资源。整数格预算在 `LatticeInvolution::new` 与 `CartanFiber::build_owned` 阶段生效。^[adjoint-fiber.md:33-34, adjoint-fiber.md:52-53]

持久存储的预算需求为 \(16ss^2+ss\cdot lr\)。其中常量 `ADJOINT_PERSISTENT_SQUARES = 16` 对应 16 份方阵，另一项计入克隆源单根的存储。^[adjoint-fiber.md:54-55]

投影运算在构建期按 \(2lr^2ss\) 预检；运行期由 `check_projection_work` 按 `lr·target·vector_count` 计费。运行期预算是**每次调用独立检查**，没有跨调用累计；这一点属于源码阅读观察。^[adjoint-fiber.md:55-57]

## 检查顺序与投影行为

`AdjointCartanFiber::build` 先检查 datum 一致性，再检查源纤维对合一致性，随后调用 `validate_adjoint_build_budget`，通过后才构造投影和目标纤维。目标构造完成后，还要执行 `source.validate_induced_map(&fiber, &projection)`，验证投影能够下降到纤维商。预算检查因此处于输入一致性检查之后、主要构造步骤之前；完整流程见 [[伴随 Cartan 纤维的构建与下降验证]]。^[adjoint-fiber.md:25-37]

整数投影 `map_coweight` 先通过 `ensure_source` 检查投影模型身份，再检查预算，最后逐个计算源单根与余权的配对。`fiber_map()` 每次调用都会克隆源纤维、投影和目标纤维来构造 `FiberToAdjoint`，不缓存稠密 mod-2 矩阵，每次 `apply` 现算投影；相关接口见 [[FiberToAdjoint 的按需投影]]。^[adjoint-fiber.md:35-48]

## 可恢复错误

所有预算乘加都使用 `checked_product` 或 `checked_sum`，溢出返回 `ArithmeticOverflow`。分配使用 `try_reserve_exact`，失败返回 `AllocationFailed`；资源超限使用 `AdjointFiberResourceLimit`。这些失败路径通过错误值报告。^[adjoint-fiber.md:52-62]

输入与结构错误包括 `DatumMismatch`、`CartanFiberInvolutionMismatch`、`RankMismatch`、`InvalidRootAutomorphism` 和 `InvalidInvolution`。其中，根作用矩阵构造中的三处 `Option::None` 转为 `InvalidRootAutomorphism`，转置遇到非方阵对应 `InvalidInvolution`。这些错误与资源不足分别表达不同的失败原因。^[adjoint-fiber.md:27-32, adjoint-fiber.md:58-62]

`DatumMismatch` 还用于阻止跨投影复用余权坐标：绑定坐标的模型必须满足 `Arc::ptr_eq`，即使坐标数值相同，两次独立构建的投影也会互相拒绝。这一约束属于 [[余权坐标的投影出处绑定]]。^[adjoint-fiber.md:17-23]

## 测试与证据边界

源文件的 9 个测试中，预算相关测试覆盖持久条目和投影运算两条拒绝路径；rank-33 测试覆盖突破打包上限的动态秩情形。`AllocationFailed`、`ArithmeticOverflow`、`InvalidRootAutomorphism`、`InvalidInvolution` 以及构建入口的 `DatumMismatch` 错误分支尚未覆盖，不能将已有测试视为所有失败路径的验证。^[adjoint-fiber.md:64-75]
