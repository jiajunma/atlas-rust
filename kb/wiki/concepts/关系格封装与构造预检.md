# 关系格封装与构造预检

关系格封装是 `integer_lattice.rs` 精确整数格线性代数中的一组类型与构造接口，建立在 Malachite 大整数 `Integer` 之上。其构造纪律是：先校验形状或计算预算，再分配、复制或收集条目。^[integer-lattice.md:19-20, integer-lattice.md:47-53]

## 类型与接口

`RelationMatrix(IntegerMatrix)` 封装关系矩阵；`RelationBasis` 提供 `factors()` 与 `into_parts()` 接口；`RelationGenerator::try_collect` 负责生成元的受检收集；该类型族使用 `RelationError` 表示错误。^[integer-lattice.md:49-53]

底层 `IntegerMatrix` 是行主序精确整数矩阵，公开 `rows`、`columns` 与 `entries`。其 `from_i32_entries` 构造器先通过 `checked_shape` 校验形状，再分配存储并逐元素转换；形状不符时返回 `InvalidIntegerMatrixShape`。^[integer-lattice.md:31-35]

## 构造预检的时序

关系矩阵构造器的 `preflight_shape` 在分配或复制任何条目之前校验形状。`from_i32_iter` 则在推进迭代器或预留存储之前拒绝超大形状，使拒绝发生在读取输入条目和保留存储之前。^[integer-lattice.md:49-51]

`RelationGenerator::try_collect` 先检查借用生成元描述符的计数，以及这些描述符所蕴含的分子矩阵；只有两者通过关系格预算，才执行收集。预检因此不仅涉及描述符数量，也涉及其对应矩阵的规模。^[integer-lattice.md:52-53]

## 计算预算

`IntegerLatticeBudget` 表达计算资源约束，而非数学秩限制。它约束单次计算的每个矩阵维数（`max_rank`）、存活工作条目总量（`max_entries`）、初等操作次数（`max_steps`）及中间系数位长（`max_coefficient_bits`）。四个字段均为私有，通过 `pub const fn new` 构造。^[integer-lattice.md:22-27]

相关基计算也采用存储预算预检：`adapted_basis` 在计算前检查工作矩阵、基、逆与对角线的条目总量。该算法所选基承载下游可观测量，详见 [[承载可观测量的适配基（adapted_basis）]]；其派生函数族包括 `adapted_relation_basis`、`filter_relation_units`、`replace_relation_generators`、`annihilator_modulo` 与 `quotient_relation_basis`。^[integer-lattice.md:55-68]
