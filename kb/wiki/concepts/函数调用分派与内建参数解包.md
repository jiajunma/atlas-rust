# 函数调用分派与内建参数解包

函数调用由 `TypedExpr` 求值中的 `apply_function` 与 `apply_closure` 处理。`BuiltinCall`、`HungryBuiltinCall` 和 `FunctionCall` 属于 `evaluate_application` 族；值需求 `Level`（`NoValue` / `SingleValue`）沿求值过程下传，决定生产者构造多少值。参见 [[TypedExpr 六族求值与值需求层级]]。^[atlas-core-typed-eval.md:24-31, atlas-core-typed-eval.md:39-53]

## 分派与内建参数解包

`apply_function` 根据函数值分派：闭包交给 `apply_closure`，内建函数则在处理参数后调用 `builtin.run`。**变参数内建需要解开参数元组；bare 变量参数即使接收到元组，也按一个值消费。** 因此，是否解包取决于参数约定，而不只是传入值是否为元组。^[atlas-core-typed-eval.md:41-45]

## 闭包参数与调用帧

`apply_closure` 以一个值接收参数：多参数闭包按元组拆分，单参数闭包整体接收，无参闭包不压帧，遵守空层规则。全匿名参数表也不占帧，与分析期的层规则一致。^[atlas-core-typed-eval.md:46-49]

递归闭包在新帧的 0 号槽自绑定；新帧不在捕获链上，使 `Rc` 结构保持无环。`return` 在本次调用边界解开，将 `Err(Control::Return(value))` 经 `at_level(level, …)` 按当前值需求供值。^[atlas-core-typed-eval.md:48-51]

## 调用迹与错误传播

`apply_function` 本身不添加调用迹。调用节点将被调函数与参数的求值留在调用迹之外，随后通过 `function_origin` 附上函数值的出处：内建函数标为 `"built-in"`，闭包标为 `defined <loc>`。^[atlas-core-typed-eval.md:41-45]

运行时错误穿过带名槽的闭包调用时，会附加局部变量迹行；无参闭包不压帧，因此也没有该行。^[atlas-core-typed-eval.md:51-53]

源码位置由 `trace_location` 渲染：单行格式为 `at NAME:LINE:COL-COL`，行号从 1 开始、列号从 0 开始，结束位置为排他边界；跨行格式为 `at NAME:LINE:COL--ENDLINE:ENDCOL`，使用双破折号。`frame_dump` 则用于 let 组的被追踪帧，按绑定顺序打印帧槽名。^[atlas-core-typed-eval.md:55-62]
