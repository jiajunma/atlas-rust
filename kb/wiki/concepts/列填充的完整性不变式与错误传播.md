# 列填充的完整性不变式与错误传播

在扩展（twisted）KLV 多项式表中，`fill_columns` 以列为单位计算数据，并维持完整性不变式：`column[y]` 要么为空，要么完整。若计算某列时出错，Rust 实现会清空出错列并向调用方传播错误，避免保留部分填充的列。^[extended-kl.md:82-87]

## 列的存储与填充范围

`ExtKlTable<'a>` 为每个块元素 `y` 保存一列多项式池索引，并按 `x` 相对于 `y` 的 descent set 的 primitive 位置寻址。因此，列内容对应的是经 primitivisation 定位的多项式索引；其布局见[[扩展 KLV 多项式表的逐列存储]]。^[extended-kl.md:70-80]

`fill_columns(limit)` 计算所有满足 `y < limit` 的列；`limit == 0` 是特殊约定，表示填满整块。^[extended-kl.md:84-85]

## 完整性不变式

列填充必须保持以下状态约束：`column[y]` 为空，或者包含完整的列数据。错误处理与该约束直接相连：出现错误时，清空正在计算的出错列，使其回到空状态，再将错误传出。来源明确规定了出错列的处理，没有说明整个填充调用具有全表回滚语义。^[extended-kl.md:84-87]

## 与上游的错误处理差异

错误传播是 Rust 移植中的有意偏离：上游在对应路径使用 `catch(...)` 吞掉错误，Rust 则清空出错列并传播错误。两者的区别在于失败如何交给调用方处理；Rust 路径同时保持“列为空或完整”的不变式。相关移植取舍见[[扩展 KLV 的 Rust 移植边界与有意偏离]]。^[extended-kl.md:84-87]
