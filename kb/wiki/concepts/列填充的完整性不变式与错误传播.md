# 列填充的完整性不变式与错误传播

扩展（twisted）KLV 多项式表的 `fill_columns` 保持列完整性不变式：`column[y]` **要么为空，要么完整**。计算某列失败时，Rust 实现清空出错列并传播错误，避免留下部分填充的列。^[extended-kl.md:82-87]

## 列存储与填充范围

`ExtKlTable<'a>` 为每个块元素 `y` 保存一列多项式池索引，按 `x` 相对于 `y` 的 descent set 的 primitive 位置寻址。相关布局见 [[扩展 KLV 多项式表的逐列存储]]。^[extended-kl.md:70-80]

`fill_columns(limit)` 计算所有满足 `y < limit` 的列；`limit == 0` 是特殊约定，表示填满整块。^[extended-kl.md:84-85]

## 失败处理与移植差异

出错时的处理单位是当前出错列：清空该列，再向调用方传播错误。这一处理保持“为空或完整”的列状态约束。^[extended-kl.md:84-87]

错误传播是 Rust 移植中的有意偏离：上游对应路径使用 `catch(...)` 吞掉错误，Rust 则将错误传出。来源虽然将移植取舍总体描述为“不改变可观察结果”，但同时明确记录了这一失败路径差异；其他取舍见 [[扩展 KLV 的 Rust 移植边界与有意偏离]]。^[extended-kl.md:84-98]

列完整性本身不足以推出整个 `fill_columns` 调用具有全表回滚语义，也不足以确定失败后的重试行为。
