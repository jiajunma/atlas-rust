# 包含文件的搜索路径解析

Atlas CLI 通过会话帧在文件参数或 stdin 上运行共享会话。命令流中的 `<file` 包含请求先按可重复指定的 `--path=DIR` 目录前缀搜索，最后搜索工作目录；每个目录内先尝试原名，名字不带 `.at` 时再尝试追加 `.at`。^[atlas-cli-main.md:9-13, atlas-core-session-frame.md:29-42]

## 搜索顺序

`main` 将 `--path=DIR` 参数加入 `search_path`，其余参数作为文件参数。`SessionFrame` 保存的目录前缀均以 `/` 结尾，表示当前工作目录的空前缀排在最后。`resolve` 按此顺序逐个目录尝试候选文件。^[atlas-cli-main.md:26-29, atlas-core-session-frame.md:29-42]

后缀尝试发生在每个目录内部：先试该目录下的原名，再在原名不带 `.at` 时试追加后缀的名字，之后才进入下一目录。因此，较早目录中的追加后缀候选优先于较晚目录中的原名候选。^[atlas-core-session-frame.md:41-42]

## 解析与包含状态

路径搜索嵌入在 include-once 判定中：若输入的文件名已在 `completed` 集合中，包含操作直接静默跳过，不打开文件，也不打印框架行；否则调用 `resolve`。解析成功后，若解析后的路径已完成，同样跳过；若路径已在 `active` 包含栈中，则作为循环守卫静默跳过，并视为成功。^[atlas-core-session-frame.md:29-40]

通过上述检查且未超过深度限制后，会话帧打印 `Starting to read from file …`，将文件压栈并递归执行。文件正常完成时，才记入 `completed` 并打印 `Completely read file …`。包含深度上限为 `MAX_INCLUDE_DEPTH = 64`；`<<file` 提供强制重读入口。相关状态见 [[SessionFrame 会话帧与文件包含语义]]。^[atlas-core-session-frame.md:11-15, atlas-core-session-frame.md:34-40]

## 文件读取与失败语义

`FileProvider::read(path) -> Option<String>` 以 `None` 表示打开失败。CLI 的文件系统实现 `FsProvider` 使用有损 UTF-8 读取，使游离的非 UTF-8 字节不会被误当作文件打开失败；测试则使用内存映射提供文件。^[atlas-core-session-frame.md:20-22, atlas-cli-main.md:18-19]

搜索失败产生 Io 诊断 `failed to open input file …` 并返回 Abort，可导致包含栈中止及 [[嵌套包含的 abandon 级联]]。不过，打开失败与 abandon 级联本身不会将会话的 `clean` 标志置为 `false`；语法、类型或求值错误才会弄脏会话，并影响 CLI 退出状态。参见 [[clean 标志与 CLI 退出状态]]。^[atlas-core-session-frame.md:36-46, atlas-core-session-frame.md:66-70, atlas-cli-main.md:35-37]

## 与顶层输入的关系

CLI 文件参数刻意按普通命令流输入，不实现上游文件参数的 prelude-capture 语义。stdin 非终端时读入后执行，连接终端时进入 `run_interactive` 的 `atlas> ` 循环；这些入口共同使用位于 `atlas-core` 的会话机器。参见 [[会话帧驱动的 CLI 执行模型]]。^[atlas-cli-main.md:30-34, atlas-cli-main.md:41-43]

## 测试与证据边界

会话帧来源列出的单元测试锚点涵盖包含解析顺序、include-once 与强制重读、缺失文件中止、循环静默跳过及 abandon 级联。这些属于单元级行为证据，端到端文件命令兼容性仍以 HPC 语料门为准。^[atlas-core-session-frame.md:81-90]

两份来源均为结构性阅读，不声称语言验收。CLI 文件没有自身测试；上游行号及对应关系属于实现方的移植陈述，不能替代 HPC 差分语料验证。^[atlas-cli-main.md:9-14, atlas-cli-main.md:41-45, atlas-core-session-frame.md:9-16, atlas-core-session-frame.md:94-99]
