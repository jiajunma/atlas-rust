# 包含文件的搜索路径解析

Atlas CLI 通过会话帧在文件参数或 stdin 上运行共享会话。命令流中的 `<file` 包含请求先按可重复指定的 `--path=DIR` 目录前缀解析，再搜索工作目录。^[atlas-cli-main.md:9-13]

## 参数与搜索路径

`main` 将 `--path=DIR` 参数加入 `search_path`，其余参数作为文件参数。因此，搜索目录配置与顶层文件输入在参数处理阶段分别收集；包含文件的搜索次序为指定的目录前缀在前，工作目录在后。^[atlas-cli-main.md:9-13, atlas-cli-main.md:26-29]

包含操作依托位于 `atlas-core` 的会话机器，CLI 负责配置搜索路径并驱动输入。相关结构见 [[SessionFrame 会话帧与文件包含语义]] 与 [[会话帧驱动的 CLI 执行模型]]。^[atlas-cli-main.md:9-13, atlas-cli-main.md:41-43]

## 文件读取与失败语义

文件系统提供者 `FsProvider` 实现 `FileProvider`，采用有损 UTF-8 读取。游离的非 UTF-8 字节不得被当作文件打开失败。^[atlas-cli-main.md:18-19]

缺少包含文件本身不会使会话的 `clean` 标志变脏；语法、类型或运行时错误才会导致非零退出状态。文件包含失败与会话退出状态之间的区别，参见 [[clean 标志与 CLI 退出状态]]。^[atlas-cli-main.md:35-37]

## 与顶层输入的关系

CLI 将文件参数刻意作为普通命令流输入，上游文件参数的 prelude-capture 语义不在此实现目标内。stdin 非终端时读入后执行，连接终端时则进入 `run_interactive` 的 `atlas> ` 循环。^[atlas-cli-main.md:30-34]
