# 单命令输出重定向的执行纪律

`SessionFrame::run_redirect_command` 处理 `>file EXPR` 与 `>>file EXPR`。执行纪律是：**先解析命令体，解析成功后打开输出 sink，再求值，并无条件调用 `sink.close()`**。`FileSink` 提供 `open(path, append)`、`write_bytes` 与 `close` 接口。^[atlas-core-session-frame.md:23-25, atlas-core-session-frame.md:59-65]

## 解析与文件打开顺序

重定向体按**表达式**解析，源码包将其对应到上游 `parser.y:180-181` 的 `TOFILE expr`。例如，`> "x" set qfc = 10` 会在 `=` 处报告 `syntax error, unexpected '='`；这是 `eval/file_commands_b9` 覆盖的拒绝形状。解析失败时不会打开 sink，因此不会创建或截断输出文件。^[atlas-core-session-frame.md:23-25, atlas-core-session-frame.md:59-62]

解析成功后，sink 在求值之前打开。因此，求值失败仍可能留下文件及失败前产生的部分输出；失败不会撤销文件副作用，sink 仍须关闭。^[atlas-core-session-frame.md:23-25, atlas-core-session-frame.md:59-65]

## 输出事件分流

命令的 `Output` 与 `OutputBytes` 事件写入 sink，其余事件照常向上层传递。重定向因此保留了事件类别之间的区别，而不是把所有会话输出都写入文件。^[atlas-core-session-frame.md:63-65]

顶层执行层将非 void 的 `SessionEvent::Value` 打印为 `Value: <display>`，void（空元组）不打印；`ReportLine` 与 `ReportBytes` 按当前包含深度缩进，每层两个空格。`ReportBytes` 经 `SessionEvent::output` 保留字节，相关机制见 [[SessionEvent 与字节保留输出]]。^[atlas-core-session-frame.md:52-58]

## 失败行为与 clean 标志

输出文件打开失败时，向 stderr 输出一行裸消息 `Failed to open {name}`，跳过命令并保持会话 clean。语法、类型和求值错误则会将 `clean` 置为 false；打开失败与 abandon 级联本身刻意不弄脏会话，相关约定见 [[clean 标志与 CLI 退出状态]]。^[atlas-core-session-frame.md:43-46, atlas-core-session-frame.md:59-65, atlas-core-session-frame.md:86-87]

执行层遇到非 Io 的 `Diagnostic` 时，将会话标为不 clean，并使本命令 Abort；Io 诊断不弄脏会话。包含文件中的 abandon 由会话帧逐层报告，顺序为最内层优先，详见 [[嵌套包含的 abandon 级联]]。^[atlas-core-session-frame.md:56-58, atlas-core-session-frame.md:66-68]

## 测试与证据边界

文件内的重定向单元测试覆盖求值前打开 sink、类型环境、命令体先解析、求值失败后关闭 sink，以及打开失败时跳过命令且保持 clean；另有测试覆盖重定向保留嵌套值的原始字节。这些是单元级行为锚点，端到端文件命令兼容性仍以 HPC 差分语料门为准，参见 [[HPC 验收证据链]]。^[atlas-core-session-frame.md:81-90]

来源属于结构性源码阅读，不声称语言或数学验收。其中对 `buffer.w`、`main.w` 与 `parser.y` 的上游引用属于实现方的移植陈述，不能单独证明端到端兼容性。^[atlas-core-session-frame.md:9-16, atlas-core-session-frame.md:94-97]
