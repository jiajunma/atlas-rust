# 单命令输出重定向的执行纪律

单命令输出重定向由 `SessionFrame` 的 `run_redirect_command` 处理，支持 `>file EXPR` 与 `>>file EXPR`。核心顺序是：**命令体解析成功后才打开输出文件，随后求值，并无条件调用 `sink.close()`**。输出接口 `FileSink` 提供 `open(path, append)`、`write_bytes` 与 `close`。^[atlas-core-session-frame.md:23-25, atlas-core-session-frame.md:59-65]

## 解析与文件打开顺序

重定向命令体按**表达式**解析，源码包将其对应到上游 `parser.y:180-181` 的 `TOFILE expr`。解析失败不会创建文件。例如，`> "x" set qfc = 10` 在 `=` 处报告 `syntax error, unexpected '='`，是 `eval/file_commands_b9` 覆盖的拒绝形状。^[atlas-core-session-frame.md:59-62]

解析成功后，sink 在求值之前打开。因此，语法错误不会留下新建文件或触发截断；求值失败则仍会留下文件，其中可能包含失败前产生的部分输出。求值失败后仍须关闭 sink。^[atlas-core-session-frame.md:23-25, atlas-core-session-frame.md:59-65]

## 输出事件分流

重定向只将命令的 `Output` 与 `OutputBytes` 事件写入 sink，其余事件照常向上层传递。顶层执行层将非 void 的 `Value` 打印为 `Value: <display>`，对 void（空元组）抑制打印；`ReportLine` 与 `ReportBytes` 按当前包含深度缩进，每层两个空格。事件的字节保留机制参见 [[SessionEvent 与字节保留输出]]。^[atlas-core-session-frame.md:52-58, atlas-core-session-frame.md:63-65]

## 失败行为与 clean 标志

输出文件打开失败时，仅向 stderr 输出一行裸消息 `Failed to open {name}`，跳过命令并保持会话 clean。语法、类型和求值错误则会将 `clean` 置为 false；文件打开失败与 abandon 级联本身刻意不弄脏会话。相关退出状态约定见 [[clean 标志与 CLI 退出状态]]。^[atlas-core-session-frame.md:43-46, atlas-core-session-frame.md:59-65, atlas-core-session-frame.md:86-87]

执行层遇到非 Io 的 `Diagnostic` 时，将会话标为不 clean，并使本命令 Abort；Io 诊断不弄脏会话。包含文件中的放弃读取及外层级联由会话帧处理，参见 [[嵌套包含的 abandon 级联]]。^[atlas-core-session-frame.md:56-58, atlas-core-session-frame.md:66-70]

## 测试与证据边界

文件内的重定向单元测试覆盖求值前打开 sink、类型环境、命令体先解析、求值失败后关闭 sink，以及打开失败时跳过命令且保持 clean；另有测试覆盖重定向保留嵌套值的原始字节。这些是单元级行为锚点，端到端文件命令兼容性仍以 HPC 差分语料门为准，参见 [[HPC 验收证据链]]。^[atlas-core-session-frame.md:81-90]

源码包属于结构性阅读，不声明语言或数学验收。其中对 `buffer.w`、`main.w` 与 `parser.y` 的上游引用是实现方的移植陈述，不能单独作为端到端兼容性证明。^[atlas-core-session-frame.md:9-16, atlas-core-session-frame.md:94-99]
