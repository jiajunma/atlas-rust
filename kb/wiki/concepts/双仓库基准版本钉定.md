# 双仓库基准版本钉定

双仓库基准版本钉定通过 `tests/math/baseline.json` 记录原版 oracle 与 Rust 的版本锚点。其中，oracle 的当前 pin 为 `7e1b958c`；Rust 侧记录的 `05625c5d` 是建立基准时存档的 main 分支历史基线字节，**不是当前 HEAD**。^[tests-math-library.md:35-37]

## 版本与证据范围

这两个版本标识分别描述 oracle 的当前钉定版本和 Rust 的历史基准点，不能把 Rust 历史基线解释为当前实现版本。来源仅完成测试库的结构性阅读，不声称任何数学验收；目录规模也只是覆盖清单，不是正确率。^[tests-math-library.md:9-18, tests-math-library.md:35-37]

取证时，`tests/math/catalog.json`、`tests/math/generics/catalog.json` 与 `tests/math/README.md` 含维护者未提交修改，`tests/math/rank6/catalog.json` 尚未跟踪。来源记录的是这些工作区字节的结构，不能将其表述为已提交内容；README 的运行记录以最新 HANDOFF／回执优先于旧记录。^[tests-math-library.md:12-18]

## Oracle 与基准比较纪律

原版可执行文件是语言 oracle。金标必须在新鲜进程中捕获原版完整输出流，并保留拒绝与恢复标记；不得用 Rust 输出生成金标。语言探针 fixture 通过 `include_str!` 内嵌后，与 `.oracle.*` 文件逐字节比较，相关主题见 [[基于原版金标的差分回归]]。^[tests-math-library.md:50-56, tests-math-library.md:89-92]

`tests/math/benchmarks.json` 登记 E7、D6、D8 三个 KGB 计时用例，每引擎超时为 300 秒，共 4 轮。比较要求使用新鲜进程、交替引擎顺序并在同一节点执行；每轮完整输出必须一致，首次不一致即停止。分钟窗标定按引擎进行，不得将短用例填充为分钟级负载。^[tests-math-library.md:31-34]

## 与数学验收的关系

数学验收另由 `tests/reference/hpc/math_acceptance_index_2026_10_01.json` 这一仅追加账本种子承载。每条验收追加哈希链记录，绑定确切源码、报告、独立审查、选用例 ID、断言与限制；每个已发布后缀必须具有永久前缀检查点，否则仍是草稿。相关要求见 [[HPC 验收证据链]]。^[tests-math-library.md:79-87]

验收状态以账本与 HANDOFF 为准。harness 失败，例如 checker 自检失败或标签错配，不是数学失败，也不能充当数学证据；不可变失败阶段应保留冻结。版本钉定所在的结构性来源包不复制账本内容。^[tests-math-library.md:95-97]
