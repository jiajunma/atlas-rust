# 可嵌套注释

Atlas 使用 `{` 与 `}` 界定注释，允许注释内部继续嵌套注释，由 `consume_comment` 消费。可嵌套注释是扫描器刻意采用有状态设计的原因之一；解析器或 REPL 可以逐 token 消费输入，`tokenize` 则提供获取完整 token 流的便利接口。^[atlas-core-lex.md:9-13, atlas-core-lex.md:72-73]

## 与空白及命令边界的交互

`skip_space` 负责消费空白和注释。换行是否成为可观察 token 受 [[换行抑制状态机]] 控制：只有 `nesting` 为空且 `prevent_termination` 为空时才透出换行，否则将其消费。分组构造与续行 token 会抑制换行。^[atlas-core-lex.md:38-46]

注释可以出现在操作赋值算符的两个部分之间。`finish_operator` 在算符后跨过空白或注释遇到 `:=` 时，将两部分融合为一个 `OperatorBecomes` token，并设置 `:` 续行标记；探测过程中若消费注释失败，会回退。^[atlas-core-lex.md:17-20, atlas-core-lex.md:55-57]

命令首的文件指令也允许在文件名前插入注释：`consume_directive` 跳过文件名前的空白和注释，此处遇到换行表示空文件名。扫描器不消费该行其余部分，后续内容由会话帧校验，详见 [[命令首指令与文件名扫描]]。^[atlas-core-lex.md:68-71]

## 未闭合诊断与错误处理

注释未闭合时，`consume_comment` 报告 `Lexical` 错误，诊断文本为 “Comment that started on line X, column Y is never closed.”，指出注释起始的行与列。^[atlas-core-lex.md:72-73]

[[TokenCursor 单 Token 前瞻]] 像缓存 token 一样缓存词法错误，使 `peek` 与 `bump` 看到同一结果。词法器另提供 `recover_command`，用于丢弃当前物理行剩余内容，并重置续行、嵌套及命令首状态。^[atlas-core-lex.md:78-80]

批量扫描接口具有不同的错误处理契约：`tokenize` 是全有或全无的便利接口；`tokenize_with_diagnostics` 返回 `LexOutput { tokens, diagnostics }`，按遭遇顺序保留诊断，并保留所有可恢复的 token。^[atlas-core-lex.md:81-83]

## 测试与证据边界

源材料记录了覆盖词法状态机分支的 23 个测试，但仅声明完成结构性阅读，不声称语言验收。词法器不负责语义判定；文法适配、逐命令消费以及指令的包含与重定向语义分别由 `syntax.rs`、`session.rs` 和 `session_frame.rs` 承担。^[atlas-core-lex.md:9-13, atlas-core-lex.md:85-89]

源材料中的上游 `lexer.w` 行号属于实现方的移植陈述，词法兼容性仍以 HPC 语言语料门为准，参见 [[HPC 验收证据链]]。^[atlas-core-lex.md:90-91]
