# 命令首指令与文件名扫描

Atlas 词法器仅在命令首 token 位置将 `<`、`<<`、`>`、`>>` 识别为文件指令，生成 `Directive(DirectiveKind)`，并在 token 的 `value` 中携带扫描到的文件名。`Lexer` 以 `at_command_start` 记录命令首状态；来源将这一识别规则对应到上游词法器的 initial-state 行为。^[atlas-core-lex.md:21-25, atlas-core-lex.md:40-43]

## 指令种类

文件指令分为包含与输出两类，具体拼写和类型如下。词法器负责识别，包含与重定向的执行语义由 `session_frame.rs` 承担。^[atlas-core-lex.md:24-25, atlas-core-lex.md:87-89]

| 拼写 | `DirectiveKind` | 含义 |
| --- | --- | --- |
| `<` | `Include` | 包含文件，已完成则跳过 |
| `<<` | `ForceInclude` | 强制包含文件 |
| `>` | `ToFile` | 截断式文件输出 |
| `>>` | `AddToFile` | 追加式文件输出 |

命令首指令与关系算符采用不同的扫描规则。关系符扫描将字符集合 `<=>` 上的极大连续段识别为一个算符；单个尖括号同时可作为类型参数定界符，不抑制换行。关系符永不与 `:=` 融合，相关规则见 [[换行抑制状态机]]。^[atlas-core-lex.md:21-22, atlas-core-lex.md:59-62]

## 文件名扫描

`consume_directive` 在命令首遇到 `<` 或 `>` 时扫描指令，符号双写分别得到 `ForceInclude` 或 `AddToFile`。扫描文件名前跳过空白和注释，但此处换行意味着空文件名。文件名可以加引号，也可以裸写，扫描结果允许为空。^[atlas-core-lex.md:68-71]

裸文件名允许字母、数字以及 `FILE_NAME_CHARS = ".-+~_=!?@#$%&|"` 中的字符。该字符集不含斜杠，因此含子目录的路径必须加引号。^[atlas-core-lex.md:35-36]

文件名前跳过的 `{}` 注释支持嵌套。未闭合注释产生 Lexical 错误，诊断指出注释开始的行号和列号；相关机制见 [[可嵌套注释]]。^[atlas-core-lex.md:68-73]

## 会话处理与恢复边界

扫描完文件名后，`consume_directive` **不消费该行剩余内容**，而是留给会话帧校验。逐命令消费位于 `session.rs`，包含与重定向语义位于 `session_frame.rs`，参见 [[SessionFrame 会话帧与文件包含语义]]。^[atlas-core-lex.md:68-71, atlas-core-lex.md:87-89]

错误恢复由 `recover_command` 丢弃当前物理行的剩余部分，并重置续行、嵌套和命令首状态。^[atlas-core-lex.md:78-78]

## 测试与证据范围

来源记录了覆盖词法状态机分支的 23 个测试，但词法器本身不做语义判定。该材料属于结构性阅读，不声称语言验收；上游行号与对应关系是实现方的移植陈述，词法兼容性仍以 HPC 语言语料门为准。^[atlas-core-lex.md:9-13, atlas-core-lex.md:85-91]
