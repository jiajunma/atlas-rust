# 命令首指令与文件名扫描

Atlas 词法器仅在命令首 token 位置将 `<`、`<<`、`>`、`>>` 识别为文件指令，生成 `Directive(DirectiveKind)`，并在 token 的 `value` 中携带扫描到的文件名。这一规则对应上游词法器的 initial-state 行为；`Lexer` 通过 `at_command_start` 状态记录命令起始位置。^[atlas-core-lex.md:21-25, atlas-core-lex.md:40-43]

## 指令种类

四种指令的拼写与类型如下。词法器负责识别指令，包含与重定向的执行语义由 `session_frame.rs` 承担。^[atlas-core-lex.md:24-25, atlas-core-lex.md:87-89]

| 拼写 | `DirectiveKind` | 含义 |
| --- | --- | --- |
| `<` | `Include` | 包含文件，已完成则跳过 |
| `<<` | `ForceInclude` | 强制包含文件 |
| `>` | `ToFile` | 截断式文件输出 |
| `>>` | `AddToFile` | 追加式文件输出 |

命令首指令识别与关系运算符扫描应区分理解：关系符扫描将 `<=>` 上的极大连续段识别为一个算符；单个尖括号还可作为类型参数定界符，且不抑制换行。相关规则见 [[运算符扫描与复合赋值融合]]。^[atlas-core-lex.md:21-22, atlas-core-lex.md:59-62]

## 文件名扫描规则

`consume_directive` 在命令首遇到 `<` 或 `>` 时开始扫描，符号双写分别得到 `ForceInclude` 或 `AddToFile`。扫描文件名前会跳过空白和注释，但此处换行意味着空文件名。文件名可加引号，也可裸写，扫描结果允许为空。^[atlas-core-lex.md:68-71]

裸文件名的字符集为字母、数字以及 `FILE_NAME_CHARS = ".-+~_=!?@#$%&|"` 中的字符。该集合不含斜杠，因此含子目录的路径必须加引号。^[atlas-core-lex.md:35-36]

文件名前允许出现的注释支持 `{}` 嵌套；未闭合注释会产生 Lexical 错误，诊断指出注释开始的行号和列号。相关机制见 [[可嵌套注释]]。^[atlas-core-lex.md:68-73]

## 词法与会话处理的边界

扫描完文件名后，`consume_directive` 不消费该行剩余内容，而是留给会话帧校验。逐命令消费位于 `session.rs`，指令的包含与重定向语义位于 `session_frame.rs`；相关职责可参见 [[SessionFrame 会话帧与文件包含语义]]。^[atlas-core-lex.md:68-71, atlas-core-lex.md:87-89]

命令首状态也参与错误恢复：`recover_command` 丢弃当前物理行的剩余部分，并重置续行、嵌套和命令首状态。该接口与 [[词法诊断保留与命令恢复接口]] 相关。^[atlas-core-lex.md:78-78]

## 测试与证据范围

源材料记录了覆盖词法状态机分支的 23 个测试，但词法器本身不做语义判定。材料属于结构性阅读，不声称语言验收；上游词法器行号及对应关系是实现方的移植陈述，词法兼容性仍以 HPC 语言语料门为准。^[atlas-core-lex.md:9-13, atlas-core-lex.md:85-91]
