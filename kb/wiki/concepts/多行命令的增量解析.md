# 多行命令的增量解析

多行命令的增量解析是 Atlas 会话层在同一命令缓冲中逐步积累 token，并在解析器请求更多输入时延后求值的机制。词法分类依赖先前命令留下的状态，因此 `session.rs` 拥有逐命令执行的外层循环，不预先切分整个源文件。^[atlas-core-session.md:9-14, atlas-core-session.md:47-50]

## 命令缓冲与续行

`run_source` 为每个源创建全新的 `TypedContext`；`run_source_with_context` 则使用调用方持有的上下文。外层循环将普通 token 加入命令缓冲，遇到 `Newline` 时调用 `execute_tokens`，遇到 `Eof` 时执行剩余缓冲并退出。换行触发的是一次解析尝试，不保证当前命令已经完整。^[atlas-core-session.md:31-40, atlas-core-session.md:47-50]

`execute_tokens` 仅在终止符为 `Newline` 时将 `allow_more` 设为真，再调用 `parse_command_fragment_in(.., context.types(), allow_more)`。返回 `Ok(None)` 时，已有命令前缀被保留，不求值，也不产生诊断；后续输入继续在同一缓冲中累积。原始源输入与文件会话共用这条多行处理路径。^[atlas-core-session.md:47-50]

## 状态与源码边界

`next_session_token` 在实际消费 token 时调用 `context.note_completion_token` 记录标识符。这使被包含文件与后续命令中的标识符保留原始的首次使用顺序，相关主题见[[会话补全顺序与名字可见性分离]]。^[atlas-core-session.md:44-46]

真实词法终止符也用于确定命令的源码跨度。对于 `Command::SetType`，实现按终止符行列重建 span；终止符为 `Newline` 时列号加一，以对应上游将命令换行计入跨度的约定，而不是猜测语义 token 之后的列。详见[[SetType 命令的词法终止符跨度重建]]。^[atlas-core-session.md:51-53]

## 错误处理与职责边界

请求续行的 `Ok(None)` 不产生诊断。对于 `Unsupported(_)`，外层循环发出 `"unexpected token"` 的 Syntax 诊断，并调用 `lexer.recover_command()`；词法错误携带的诊断直接进入事件流。^[atlas-core-session.md:34-40, atlas-core-session.md:47-50]

文件包含由 `session_frame.rs` 负责，会话层直接遇到包含指令时发出 `"file inclusion is only available through a session frame"` 的 Io 诊断。转换与求值位于 `typed.rs`，词法与文法适配分别位于 `lex.rs`、`syntax.rs`。参见[[会话循环与文件会话帧的职责边界]]。^[atlas-core-session.md:37-39, atlas-core-session.md:72-74]

命令进入执行阶段后，如果 `context.execute` 返回错误，会话层先调用 `drain_failed_printed(span)` 排空已打印内容，再发送诊断，以保留求值失败前产生的输出。相关主题见[[打印、字符串转换与运行时错误的输出契约]]。^[atlas-core-session.md:54-56]

## 证据范围

来源是对 `session.rs` 的结构性阅读，不构成语言或数学验收。文件包含 201 个语言层回归测试；其中原版背书的回归采用 fixture 与 `.oracle.stdout`、`.oracle.stderr` 逐字节比对，可执行正确性由 HPC 门验证。这些说明提供整个文件的测试背景，不能据此声称多行命令机制已有独立的专项验收。^[atlas-core-session.md:9-14, atlas-core-session.md:58-68]
