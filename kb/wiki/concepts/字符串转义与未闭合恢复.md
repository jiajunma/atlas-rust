# 字符串转义与未闭合恢复

Atlas 词法器通过 `consume_string` 扫描字符串，采用双写引号的方式转义引号。换行会使字符串被视为未闭合；扫描器报告警告，并保留恢复出的 `String` token，使解析器仍能消费该 token 与后续命令。^[atlas-core-lex.md:74-77]

## 转义与 token 表示

字符串 token 的 `lexeme` 保存包含引号的精确源拼写，`value` 保存词法解码后的值；`Token` 还包含 `kind` 与 `span`。因此，双写引号的源文本表示与解码结果分别保留在不同字段中，相关结构见 [[Atlas 词法 Token 模型]]。^[atlas-core-lex.md:26-27, atlas-core-lex.md:74-77]

## 未闭合恢复

未闭合字符串产生类别为 `Lexical` 的 warning，诊断文本为 `"Closing string denotation."`。恢复出的 `String` token 被放入 `pending`，以支持 REPL 中报告诊断后继续解析的行为。^[atlas-core-lex.md:74-77]

字符串恢复与命令级恢复各有职责：前者保留恢复出的 token；`recover_command` 则丢弃当前物理行的剩余内容，并重置续行、嵌套和命令首状态。相关接口见 [[词法诊断保留与命令恢复接口]]。^[atlas-core-lex.md:74-78]

## 诊断与消费接口

[[TokenCursor 单 Token 前瞻]] 将词法错误像 token 一样缓存，使 `peek` 与 `bump` 看到同一结果。批量扫描时，`tokenize` 提供全有或全无的兼容接口；`tokenize_with_diagnostics` 返回 `LexOutput{tokens, diagnostics}`，按遭遇顺序保留诊断，并保留所有可恢复的 token。^[atlas-core-lex.md:79-83]

## 验证范围

源材料记录了 23 个测试，覆盖所述词法状态机分支，但材料属于结构性阅读，不构成语言验收。词法器本身不做语义判定；文法适配由 `syntax.rs` 承担，逐命令消费由 `session.rs` 承担，词法兼容性仍以 HPC 语言语料门为准。^[atlas-core-lex.md:9-13, atlas-core-lex.md:85-91]
