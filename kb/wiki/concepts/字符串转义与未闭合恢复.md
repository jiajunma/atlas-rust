# 字符串转义与未闭合恢复

Atlas 词法器通过 `consume_string` 扫描字符串，采用**双写引号**的方式转义引号。换行会使字符串未闭合；扫描器报告词法警告，同时保留恢复出的 `String` token，使解析器仍能消费该 token 与后续命令。^[atlas-core-lex.md:74-77]

## 转义与 token 表示

字符串的源拼写与解码值分别保存：`Token` 包含 `kind`、`lexeme`、`value` 和 `span`，其中 `lexeme` 保留包含引号的精确源拼写，`value` 保存词法解码后的字符串值。相关结构见 [[Atlas 词法 Token 模型]]。^[atlas-core-lex.md:26-27]

## 未闭合恢复

未闭合字符串产生类别为 `Lexical` 的 warning，诊断文本为 `"Closing string denotation."`。恢复出的 `String` token 被放入 `pending`，支持 REPL 在报告诊断后继续向解析器提供该 token 与后续命令。^[atlas-core-lex.md:74-77]

命令级恢复由 `recover_command` 执行：丢弃当前物理行的剩余内容，并重置续行、嵌套和命令首状态。字符串扫描中的恢复则保留恢复出的 token；相关状态背景见 [[换行抑制状态机]]。^[atlas-core-lex.md:40-46, atlas-core-lex.md:74-78]

## 诊断与消费接口

[[TokenCursor 单 Token 前瞻]] 将词法错误像 token 一样缓存，使 `peek` 与 `bump` 看到同一结果。批量扫描时，`tokenize` 提供全有或全无的兼容接口；`tokenize_with_diagnostics` 返回 `LexOutput{tokens, diagnostics}`，按遭遇顺序保留诊断，并保留所有可恢复的 token。^[atlas-core-lex.md:79-83]

## 验证范围

源材料记录了 23 个测试，覆盖所述词法状态机分支，但材料属于结构性阅读，不构成语言验收。词法器本身不做语义判定；文法适配由 `syntax.rs` 承担，逐命令消费由 `session.rs` 承担。上游行号引用属于实现方的移植陈述，词法兼容性仍以 HPC 语言语料门为准。^[atlas-core-lex.md:9-13, atlas-core-lex.md:85-91]
