# 定位器整单根像的正性与置换校验

`BlockLocator` 通过 Weyl 元素 `w`，将典范基本 alcove 的整子系统映到查询的实际姿态，并保持整正性。`simp_int` 保存按上游正根序排列的整单根像，`simple_pi` 将典范单生成元下标映到对应像在 `simp_int` 中的位置。背景见 [[Weyl 姿态定位器]] 与 [[典范整数据驻留]]。^[locator.md:19-25]

## 整单根像的正性检查

`int_item` 在取得典范整数据和姿态后，逐个计算典范单根的 `w.image(alpha)`。若像缺失，报告 `"provenance"` 不变量违规；若像不是正根，报告 `"integral image positivity"` 不变量违规。后者是上游 `assert(is_posroot)` 的受检形式。^[locator.md:63-66]

通过检查后，算法将这些像的排序副本保存为 `simp_int`，再以各像在其中的位置构造 `simple_pi`。因此，`simple_pi` 记录的是典范单生成元顺序到查询姿态下排序位置的映射。^[locator.md:23-25, locator.md:63-66]

## 排序与互异性边界

定位器列表采用上游 `RootNbr` 正根序，即按高度、简单坐标反字典序排序；crate 的 `RootId` 则采用环境字典序。来源将这一差异描述为有意的存储偏差，并声明语义不变；定位器统一采用上游顺序，使 `simple_pi` 可与 oracle 直接比较。参见 [[RootNumbering 根编号与 RootNbr 顺序]]。^[locator.md:27-29]

像互异检查使用 `debug_assert_eq!`，仅在 debug 构建中生效。因此，缺失像与非正像具有返回错误的检查，而像互异性的这一断言不提供非 debug 构建下的运行时校验。^[locator.md:63-66, locator.md:104-104]

## 相对姿态转换中的置换校验

`make_relative_to` 要求两个定位器具有相同的 `int_sys`，否则报告不变量错误。转换时，`w` 右乘基姿态之逆，`simple_pi` 与基定位器简单置换的逆右复合，具体为 `simple_pi[j] = old[inv[j]]`。逆置换构造使用 `usize::MAX` 哨兵检测越界或重复像；详见 [[定位器的相对姿态变换]]。^[locator.md:75-78]

测试锚点包含手算例子 `[2,1,0] ∘ [1,2,0]^{-1} = [0,2,1]`，以及 Weyl 元素右乘逆的例子：`s0·s1^{-1}` 的简约词为 `[0,1]`；还包含不同 `int_sys` 的拒绝测试。^[locator.md:92-93]

## 测试与证据边界

F4 半积分定位器测试（case107、HPC3832609）检查 `w.image` 作用于典范 item 的全部正根后，所得集合等于独立过滤的期望集合。该锚点涉及全部正根的像集合，范围超出整单根像本身。^[locator.md:84-85]

来源属于结构性阅读，不构成定位器层的数学验收；上游对应关系仅转录自代码注释，未核对上游字节。来源所述阶段，模块尚未接入 `RepTable::lookup`。测试仅覆盖 A2、B2、F4，可约根系、rank-0 边角及多条错误路径未测；本次知识维护也未执行 Atlas、Cargo、测试或 benchmark。^[locator.md:10-12, locator.md:98-105, locator.md:109-113]
