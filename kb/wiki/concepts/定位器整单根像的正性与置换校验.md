# 定位器整单根像的正性与置换校验

`BlockLocator` 用 Weyl 元素 `w` 将典范基本 alcove 的整子系统映到查询姿态，并保持整正性。其 `simp_int` 保存按上游正根序排列的整单根像，`simple_pi` 则把典范单生成元下标映到对应像在 `simp_int` 中的位置。相关背景见 [[Weyl 姿态定位器]] 与 [[典范整数据驻留]]。^[locator.md:19-25]

## 整单根像的校验

`int_item` 在得到典范整数据和姿态 `w` 后，逐个计算典范单根的 `w.image(alpha)`。若像缺失，返回 `"provenance"` 不变量违规；若像不是正根，返回 `"integral image positivity"` 不变量违规。后者是上游 `assert(is_posroot)` 的受检形式，将整单根像的正性要求落实为错误检查。^[locator.md:63-66]

通过上述检查后，算法将像的排序副本保存为 `simp_int`，并记录每个像在其中的位置，形成 `simple_pi`。因此，这一置换连接典范单根的生成元顺序与查询姿态下的排序顺序。^[locator.md:63-66]

## 排序与互异性边界

排序采用上游 `RootNbr` 的正根序，即按高度、简单坐标反字典序排列，而非 crate 中 `RootId` 的环境字典序。所有面向定位器的列表均采用上游顺序，使 `simple_pi` 可以与 oracle 直接比较；相关概念见 [[RootNumbering 根编号与 RootNbr 顺序]]。^[locator.md:27-29]

像互异性的检查使用 `debug_assert_eq!`，仅在 debug 构建中生效。因此，应区分返回错误的正性检查与仅在 debug 构建中执行的互异性断言。^[locator.md:63-66, locator.md:104-104]

## 相对姿态下的置换校验

`make_relative_to` 要求两个定位器具有相同的 `int_sys`，否则返回不变量错误。转换时，`w` 右乘基姿态的逆，`simple_pi` 则与基定位器简单置换的逆右复合，具体为 `simple_pi[j] = old[inv[j]]`。逆置换构造使用 `usize::MAX` 哨兵检测越界或重复像，详见 [[定位器的相对姿态变换]]。^[locator.md:75-78]

测试锚点包含置换合成的手算例子 `[2,1,0] ∘ [1,2,0]^{-1} = [0,2,1]`，以及 `w` 右乘逆的例子：`s0·s1^{-1}` 的简约词为 `[0,1]`；不同 `int_sys` 的定位器也有拒绝测试。^[locator.md:92-93]

## 测试与证据边界

F4 半积分定位器测试（case107、HPC3832609）检查 `w.image` 作用于典范 item 的全部正根后，所得集合等于独立过滤的期望集合。这一锚点覆盖全部正根的像集合，而不只涉及整单根。^[locator.md:84-85]

来源属于结构性阅读，不构成定位器层的数学验收；该模块尚未接入 `RepTable::lookup`。测试仅覆盖 A2、B2、F4，可约根系、rank-0 边角和多条错误路径尚未覆盖，不能据此声称所有正性与置换错误分支均已验证。^[locator.md:10-12, locator.md:98-105]
