# 对合类型的分层构造验证与错误优先级

[[扭曲对合（TwistedInvolution）]] 通过分层构造验证，确立 Weyl 平移 $w\theta$ 满足 $(w\theta)^2=1$ 的根论条件。构造器先检查 datum 同一性，再检查秩、复合矩阵，最后依次调用 [[格对合（LatticeInvolution）]] 与 [[根对合数据（RootInvolutionData）]] 的构造器；这一顺序决定输入存在多个问题时优先报告的错误。^[twisted-involution-trio.md:17-29]

## 构造层次与职责

`TwistedInvolution` 的两个字段 `weyl_action` 与 `root_involution` 均为私有。成功构造后，实例存储 `WeylAction` 和 `RootInvolutionData`，不保留中间的 `LatticeInvolution`。该类型只确立根论条件；[[扭曲对合的 Cayley/Cross 分解]]由 `CayleyCrossDecomposition` 承担，典范化由 `InnerClass::canonicalize` 承担。^[twisted-involution-trio.md:17-29]

## 验证顺序与错误优先级

`TwistedInvolution::new` 首先完成针对 `root_system`、`distinguished`、`weyl_action` 的三个 datum 同一性检查，任一不符即返回 `DatumMismatch`。这三个检查全部先于秩检查，因此来源不一致的错误具有更高优先级。^[twisted-involution-trio.md:22-25]

随后执行三个秩检查，不符时返回 `RankMismatch`。其中 `WeylAction` 使用 `rank()`，其余使用 `lattice_rank()`；错误的 `actual` 字段分别记录相应对象的实测值。^[twisted-involution-trio.md:23-25]

通过前置检查后，构造器分别复合 weight 与 coweight 矩阵，乘法方向均为 Weyl 矩阵在左、distinguished 矩阵在右。结果依次传入 `LatticeInvolution::new` 和 `RootInvolutionData::new`。对合性拒绝发生在这两个下层构造器内部；`TwistedInvolution::new` 本体没有直接构造 `InvalidInvolution` 的位置，测试观察到的是下层错误的传播。^[twisted-involution-trio.md:25-29]

## 矩阵复合的算术与诊断边界

`compose_matrices` 是 crate 内可见的辅助函数，也被 `global_tits` 等调用方复用。它采用受检 `i128` 累加，并通过 `i32::try_from` 将结果收窄到 `i32`。^[twisted-involution-trio.md:31-32]

形状检查存在明确的诊断字段问题：右矩阵行数不符、左矩阵行长度不齐、右矩阵行长度不齐，共用同一个条件分支，并一律把 `RankMismatch.actual` 设为 `right.len()`。因此，当右矩阵行数正确而某行长度错误时，消息可能呈现 `expected N, got N`。错误种类仍正确，但 `actual` 未反映真正不符的维度，详见 [[矩阵复合形状错误的诊断字段失真]]。^[twisted-involution-trio.md:31-37]

来源指出，合法调用点只传入同秩方阵，该守卫仅在数据损坏或误用时可达，因此上述问题属于诊断内容问题，没有数学影响。^[twisted-involution-trio.md:35-37]

## 整对合分类中的验证顺序

相关的 `classify_involution` 也采用固定顺序：先检查形状，再执行资源预算检查，然后验证对合性，构造 $\theta+I$，最后调用 `classify_plus_identity`。预算检查通过临时构造 `IntegerMatrix` 记账，并立即释放，避免抬高后续存活矩阵条目的记账值；对合性检验采用受检 `i128` 三重循环，首个不符即短路。^[twisted-involution-trio.md:48-52]

`classify_plus_identity` 是供中心环面商复用的 crate 内接口，调用方必须自行保证对合前提。它计算 [[整对合的 compact、complex、split 因子计数]]，三处受检减法若发生下溢，则返回 `IntegerLatticeInvariantViolation`。这一接口的前提责任与完整分类入口不同。^[twisted-involution-trio.md:53-57]

## 测试锚点与证据范围

来源列出四个扭曲对合测试：A1 反射平移得到两个实根；A2 的三阶元 `s0·s1` 被拒绝并返回 `InvalidInvolution`；同秩但不同 datum 的 A2 与 B2 返回 `DatumMismatch`；另有带中心环面的 distinguished 对合 $\operatorname{diag}(1,-1)$ 的复合测试。^[twisted-involution-trio.md:39-41]

整对合分类测试还锚定了前置检查顺序：行长度不齐的输入在形状检查阶段被拒绝；在 rank 上限为 1 的预算下，测试中的恒等矩阵返回 `IntegerLatticeResourceLimit { resource: "rank", limit: 1 }`，对应预算检查先于对合性检验的安排。^[twisted-involution-trio.md:64-68]

本页依据结构性阅读，不构成数学验收。来源没有展开两个下层对合构造器的内部验证顺序，也未提供 `compose_matrices` 的直接测试；本次知识维护未执行 Atlas、Cargo、测试或 benchmark，因此上述测试锚点不代表本次运行结果。^[twisted-involution-trio.md:10-13, twisted-involution-trio.md:25-29, twisted-involution-trio.md:87-88, twisted-involution-trio.md:92-96]
