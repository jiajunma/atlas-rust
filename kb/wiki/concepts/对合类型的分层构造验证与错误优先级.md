# 对合类型的分层构造验证与错误优先级

`LatticeInvolution`、`RootInvolutionData` 与 `TwistedInvolution` 逐层建立不同强度的不变量：配对保持的格对合、根置换与余根运输，以及 Weyl 平移后仍为对合的条件。构造器按固定顺序验证输入，因此多个条件同时失效时，先执行的检查决定首先报告的错误。^[involution-types.md:13-15, involution-types.md:67-71, involution-types.md:86-92, involution-types.md:108-112]

## 格对合：形状、对合性、配对保持

[[格对合（LatticeInvolution）]] 分别存储 character 与 cocharacter 格上的作用矩阵 \(W\) 和 \(C\)，并在构造时一起验证。配对保持是实例的不变量，但保持有限根系并非这一层的保证。^[involution-types.md:63-65]

`LatticeInvolution::new` 首先要求两个矩阵均为 `lattice_rank` 阶方阵，否则返回 `InvalidInvolution`。随后先检查 \(W^2=I\)，再检查 \(C^2=I\)；两项使用 `||` 短路求值，检验在 `i128` 中进行，算术溢出传播为 `ArithmeticOverflow`。最后才验证配对保持条件 \(W^TC=I\)，不成立时返回 `InvalidRootAutomorphism`。因此，形状与对合性检查先于配对保持检查。^[involution-types.md:67-71]

测试锚点区分了两种失败：\(W=\begin{pmatrix}-1\end{pmatrix}\)、\(C=\begin{pmatrix}1\end{pmatrix}\) 满足各自的对合条件，却返回 `InvalidRootAutomorphism`；\(W=\begin{pmatrix}2\end{pmatrix}\)、\(C=\begin{pmatrix}0\end{pmatrix}\) 则返回 `InvalidInvolution`。^[involution-types.md:120-122]

## 根对合：单根诊断先于全根诊断

[[根对合数据（RootInvolutionData）]] 在格对合之上验证根的像仍是根，并要求每个存储余根被运输到像根的余根。后一个条件不可省略：仅配对保持仍可能允许“固定所有根却移动余根中心环面坐标”的作用。^[involution-types.md:82-84]

`RootInvolutionData::new` 首先检查 datum 一致性，失败返回 `DatumMismatch`；随后检查秩，失败返回 `RankMismatch`。接着执行 `validate_simple_root_images`，最后进入逐根主循环。因此，单根级错误 `SimpleRootImageNotRoot { simple_root }` 与 `SimpleCorootImageMismatch { simple_root, image_root }` 优先于主循环的一般错误。主循环中，像非根返回 `InvalidRootAutomorphism`，余根运输不符返回 `InvalidRootDatumAutomorphism`。^[involution-types.md:86-92]

例如，测试中的作用矩阵为
\[
W=\begin{pmatrix}-1&0\\1&1\end{pmatrix},
\qquad
C=\begin{pmatrix}-1&1\\0&1\end{pmatrix}.
\]
它能够通过 `LatticeInvolution::new`，但在 `RootInvolutionData::new` 中返回 `SimpleRootImageNotRoot { simple_root: 0 }`。针对正、负单根的余根运输错误，另有 `SimpleCorootImageMismatch` 测试锚点。^[involution-types.md:126-129]

根类型分类也遵循固定顺序：像等于自身时为 `Imaginary`；否则，像等于负根时为 `Real`；其余为 `Complex`。负根通过逐坐标 `checked_neg` 计算，相关语义见 [[对合下的虚根、实根与复根分类]]。^[involution-types.md:91-92]

## 扭曲对合：上下文检查先于合成验证

[[扭曲对合（TwistedInvolution）]] 承载 \(w\theta\) 仍满足 \((w\theta)^2=1\) 的根论条件。本层不承担 Cayley/cross 分解或规范化；前者由 `CayleyCrossDecomposition` 负责，后者由 `InnerClass::canonicalize` 负责。^[involution-types.md:104-106]

`TwistedInvolution::new` 先完成三个 datum 一致性检查，任一不符即返回 `DatumMismatch`，优先于全部秩检查。随后按 `root_system`、`distinguished`、`weyl_action` 的顺序检查秩，再在两个格上计算 `compose_matrices(w, θ)`，其中 \(w\) 在左、\(\theta\) 在右。合成结果重新经过 `LatticeInvolution::new` 的完整验证，再由 `RootInvolutionData::new` 验证根置换与余根运输。结果不存储 distinguished 对合，但原样保留 `weyl_action` 并提供访问器。^[involution-types.md:108-112]

测试中，A1 的 `s0` 平移合法，A2 的三阶元 `s0·s1` 则返回 `InvalidInvolution`；混用不同但同秩的 datum（A2 与 B2）的 Weyl 作用返回 `DatumMismatch`。这些锚点分别体现合成后的对合性检查与 datum 身份检查。^[involution-types.md:130-132]

## 算术与诊断边界

`compose_matrices` 是 `pub(crate)` 辅助函数，采用标准三重循环，以 `i128` 检查算术并收窄至 `i32`。形状不符返回 `RankMismatch { expected: rank, actual: right.len() }`；即使真实问题是某行长度不符，`actual` 仍取 `right.len()`。这是来源明确记录的诊断细节。^[involution-types.md:114-116]

格作用方法 `act_on_weight` 与 `act_on_coweight` 经 `apply_matrix` 执行：行数不符返回 `RankMismatch`，某行长度不符却返回 `InvalidInvolution`。点积在 `i128` 中累加，再通过 `i32::try_from` 收窄，溢出返回 `ArithmeticOverflow`。形状错误的分类因此不能直接套用矩阵合成函数的约定。^[involution-types.md:75-78]

私有字段保证实例经过构造验证。`RootInvolutionData::new` 不独立检查根置换的平方是否为恒等，而是依赖 `LatticeInvolution` 已建立的代数对合条件；私有辅助函数中的裸下标访问则依赖调用点的方阵与秩预检。来源将潜在 panic 路径的判断明确归为阅读推断。^[involution-types.md:142-145]
