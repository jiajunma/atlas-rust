# 对合类型的分层构造验证与错误优先级

`LatticeInvolution`、`RootInvolutionData` 与 `TwistedInvolution` 分层建立不变量：配对保持的格对合、根置换与余根运输，以及 Weyl 平移后仍为对合的条件。各构造器按固定顺序验证输入，前面的检查失败会先返回错误；类型字段私有，使实例必须经过构造验证。^[involution-types.md:13-15, involution-types.md:67-71, involution-types.md:86-92, involution-types.md:108-112, involution-types.md:142-143]

## 格对合：先形状与对合性，再配对保持

`LatticeInvolution` 分别存储 character 与 cocharacter 格上的作用矩阵 \(W\) 和 \(C\)，并在构造时一起验证。配对保持是实例的不变量，但这一层不保证作用保持有限根系。^[involution-types.md:63-65]

`LatticeInvolution::new` 首先要求两个矩阵均为 `lattice_rank` 阶方阵，否则返回 `InvalidInvolution`。随后先检查 \(W^2=I\)，再检查 \(C^2=I\)；实现采用 `||` 短路求值，检查中的累加使用受检 `i128` 算术，溢出传播为 `ArithmeticOverflow`。最后验证配对保持条件 \(W^TC=I\)，不成立时返回 `InvalidRootAutomorphism`。因此，矩阵形状与对合性错误优先于配对保持错误。^[involution-types.md:67-71]

测试锚点区分了这两类失败：\(W=\begin{pmatrix}-1\end{pmatrix}\)、\(C=\begin{pmatrix}1\end{pmatrix}\) 返回 `InvalidRootAutomorphism`；\(W=\begin{pmatrix}2\end{pmatrix}\)、\(C=\begin{pmatrix}0\end{pmatrix}\) 返回 `InvalidInvolution`。^[involution-types.md:120-122]

## 根对合：单根诊断先于一般根诊断

`RootInvolutionData` 在格对合之上验证每个根的像仍是根，并要求每个存储余根被运输到像根的余根。余根运输条件用于建立根数据自同构性质：仅检查配对保持，仍可能放过“固定所有根却移动余根中心环面坐标”的作用。^[involution-types.md:82-84]

`RootInvolutionData::new` 先检查 datum 一致性，再检查秩，分别返回 `DatumMismatch` 与 `RankMismatch`。随后执行 `validate_simple_root_images`，最后进入逐根主循环。因此，单根级错误 `SimpleRootImageNotRoot { simple_root }` 和 `SimpleCorootImageMismatch { simple_root, image_root }` 优先于主循环中的一般错误。主循环中，像非根返回 `InvalidRootAutomorphism`，余根运输不符返回 `InvalidRootDatumAutomorphism`。^[involution-types.md:86-92]

例如，测试中的矩阵
\[
W=\begin{pmatrix}-1&0\\1&1\end{pmatrix},
\qquad
C=\begin{pmatrix}-1&1\\0&1\end{pmatrix}
\]
能够通过 `LatticeInvolution::new`，却在 `RootInvolutionData::new` 中返回 `SimpleRootImageNotRoot { simple_root: 0 }`。正、负单根的余根运输错误另有 `SimpleCorootImageMismatch` 测试锚点。^[involution-types.md:126-129]

验证过程中的根类型分类也有固定优先级：像等于自身时为 `Imaginary`；否则，像等于负根时为 `Real`；其余为 `Complex`。负根通过逐坐标 `checked_neg` 计算，相关概念见 [[对合下的虚根、实根与复根分类]]。^[involution-types.md:91-92]

## 扭曲对合：datum 检查先于全部秩检查

[[扭曲对合（TwistedInvolution）]] 承载 \(w\theta\) 满足 \((w\theta)^2=1\) 的根论条件。本层不负责 Cayley/cross 分解与规范化：前者由 `CayleyCrossDecomposition` 承担，后者由 `InnerClass::canonicalize` 承担。^[involution-types.md:104-106]

`TwistedInvolution::new` 首先完成三个 datum 一致性检查，任一不符即返回 `DatumMismatch`，优先于全部秩检查。随后按 `root_system`、`distinguished`、`weyl_action` 的顺序检查秩，再在两个格上调用 `compose_matrices(w, θ)`，合成方向为 \(w\) 在左、\(\theta\) 在右。合成结果重新经过 `LatticeInvolution::new` 的完整检查，再由 `RootInvolutionData::new` 验证根置换与余根运输。实例不存储 distinguished 对合，但原样保留并暴露 `weyl_action`。^[involution-types.md:108-112]

测试锚点包括：A1 的 `s0` 平移合法且得到两个实根；A2 的三阶元 `s0·s1` 返回 `InvalidInvolution`；不同但同秩 datum（A2 与 B2）的 Weyl 作用返回 `DatumMismatch`；带中心环面的 distinguished 对合 \(\operatorname{diag}(1,-1)\) 与 `s0` 合成合法。^[involution-types.md:130-132]

## 算术与诊断边界

`compose_matrices` 是 `pub(crate)` 辅助函数，采用标准三重循环，以受检 `i128` 算术计算后收窄至 `i32`。形状不符时报 `RankMismatch { expected: rank, actual: right.len() }`；即使实际问题是某一行长度不符，诊断中的 `actual` 仍为 `right.len()`。这一细节属于来源记录的阅读观察，不能将该字段一概理解为出错行的长度。^[involution-types.md:114-116]

`act_on_weight` 与 `act_on_coweight` 经 `apply_matrix` 执行，其形状错误分类不同：行数不符返回 `RankMismatch`，某行长度不符返回 `InvalidInvolution`。点积在 `i128` 中累加，再通过 `i32::try_from` 收窄，溢出返回 `ArithmeticOverflow`。^[involution-types.md:75-78]

[[对合的反不变秩|反不变秩]] 查询采用精确公式 \((\operatorname{rank}-\operatorname{trace}(\theta))/2\)，避免浮点运算。迹使用受检 `i128` 累加；若差值为负或为奇数，则返回 `InvalidInvolution`。^[involution-types.md:73-75]

## 不变量依赖与证据范围

`RootInvolutionData::new` 不独立检查根置换的平方是否为恒等，而是依赖 `LatticeInvolution` 已建立的代数对合条件。私有辅助函数中的裸下标访问依赖调用点的方阵与秩预检；来源将潜在 panic 路径的判断明确归为阅读推断。^[involution-types.md:142-145]

来源记录的测试缺口包括：`anti_invariant_rank` 的全部分支、`act_on_*` 的错误路径、`image()` 与 `kind()` 越界返回 `None` 的行为，以及直接触发 `compose_matrices` 的 `RankMismatch`。最后一种路径在 `TwistedInvolution::new` 内被前置秩检查阻挡，但辅助函数仍具有 crate 内可见性。^[involution-types.md:138-141]

本页依据三个对合实现文件的结构性阅读，不构成数学或正确性验收。来源中的上游引用仅转录自代码文档注释，未核对上游字节；该次知识维护未执行 Atlas、Cargo、测试或 benchmark。^[involution-types.md:9-15, involution-types.md:149-156]
