# 形变兼容性的证据边界

形变兼容性需要区分实现的结构性阅读、实现方的上游移植陈述与 HPC 差分验证。所提供的形变缓存机器文档完成了结构性阅读，但明确不声称数学验收；其中对上游行号的引用属于实现方移植陈述，形变兼容性仍以 HPC 差分门为准。^[atlas-core-deformation-cache.md:9-15, atlas-core-deformation-cache.md:62-64]

## 结构性阅读支持的结论

文档覆盖 `domain_builtins.rs` 中普通与扭曲全形变的入口、递归和缓存机器，以及矩阵辅助函数。它支持说明这些实现的控制流程与约束，但相关块机器、`RepContext`、`ExtRepContext` 和领域值系数契约分别由其他材料覆盖。^[atlas-core-deformation-cache.md:9-14, atlas-core-deformation-cache.md:59-61]

[[全形变缓存与递归环检测]]的实现纪律包括：以 canonical 单元 `(x, y_bits, gamma)` 为键，只在缓存读写瞬间持锁，不跨递归持有缓存或块属主锁；只缓存完整且按 canonical 项序排序的结果，并用 active 集显式检测递归环。[[形变计算的协作式截止]]在阶段间检查期限，超限返回 `None`，不缓存部分结果。^[atlas-core-deformation-cache.md:19-27]

## 普通全形变的对应关系

文档给出的普通全形变递推为
\(F(z)=L(z)+\sum_t c_t(1-s)F(t)\)，遍历每个可约点；它通过恒等式 \((1-s)^2=2(1-s)\)，说明该递推与原版整数递推 \(D(z)\mathrel{+}=c_tL(t)+2c_tD(t)\) 的对应关系。这是来源中陈述的算法对应关系，其兼容性判定仍受 HPC 差分门约束。^[atlas-core-deformation-cache.md:29-33, atlas-core-deformation-cache.md:62-64]

兼容性还涉及递归项的完整保留：scale-zero 基底保留全部 final 项，子项经过 `scale`、`deform_readjust`、表示查找与 `common_deformation_terms` 后，以 \(c(1-s)\) 因子继续递归。若停在前一个可约点并将其变为单个 K 型，会丢弃 Split 因子及其后代；因此，[[全形变中的 Split 因子与后代保留]]是理解实现行为的重要部分。顶层则对每个 final 组分形变、按系数缩放并合并，最终按 canonical `KTypePol` 项序排序。^[atlas-core-deformation-cache.md:36-42]

## 扭曲全形变的计时与系数边界

[[扭曲全形变计算流程]]先完成 `distinguished_twist`、`ExtRepContext` 和 `extended_finalise`，随后才开始计时，因此 setup 成本不在协作截止范围内。后续调用 `twisted_reducibility_lookup` 与 `twisted_deformation_with_cancel`；finalise 翻转不同时系数为 \(s\)，否则为 \(1\)，结果逐项合并排序。该计时边界在文档中引用了 `axis.w:8303–8308`，但上游行号引用仍属于移植陈述。^[atlas-core-deformation-cache.md:46-50, atlas-core-deformation-cache.md:62-64]

## 验收与快照的适用范围

来源将普通全形变弧的兼容验证指向 HPC 差分门 `3845838/3845872`，并要求参照根 `AGENTS.md` 的 “Ordinary full deformation” 条目。这提供了继续追查[[HPC 验收证据链]]的入口；来源自身的证据定位仍是结构性阅读，不是数学验收。^[atlas-core-deformation-cache.md:9-15, atlas-core-deformation-cache.md:62-64]

快照标注的 Git base 为 `964f0033`。文档明确限定，字节数与哈希只标识本快照字节，不能将这些标识本身视为形变兼容性的验证结果。^[atlas-core-deformation-cache.md:62-65]
