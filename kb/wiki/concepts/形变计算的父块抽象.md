# 形变计算的父块抽象

形变计算通过 `KlSumParent<'a>` 统一读取完整块与部分公共块，供 twisted KL 和及 twisted deformation 使用；递归驱动则通过拥有父块资源的 `DeformParent` 保持其生命周期，再借出计算所需的块视图。两种抽象同时保留了不同父块的参数重构方式。^[deformation-drivers.md:83-93]

## 借用视图：KlSumParent

`KlSumParent<'a>` 有两个变体：`Full { block: &BlockGraph, lambda_rho: &Weight }` 借用完整块及调用方提供的常量 `lambda_rho`；`Partial { block: &PartialBlock, modifier: Option<&BlockModifier> }` 借用部分公共块，并按 `common_block::sr` 的方式为每行重构自己的 `lambda_rho`。相关结构见 [[公共块的构造与元素编号（PartialBlock）]] 与 [[BlockModifier 块修正子]]。^[deformation-drivers.md:85-89]

### 完整块的参数约束

完整块接口中的常量 `lambda_rho` 是移植契约的简化，并不意味着完整块内所有元素天然共享该值。例如，SL(2,R) 在 $\gamma=2\rho$ 时，compact-Cartan 元素的 `lambda_rho` 为 `[1]`，split 元素为 `[0]`。因此，调用方必须确保所传参数的所有形变项共享该值；语言层使用 `rc.lambda_rho(p)`，与已验证的 `deform` 分支一致。^[deformation-drivers.md:29-33]

### 部分公共块的逐行重构

对于真积分子系统，父块使用 `PartialBlock`。每行参数重构结合自身存储的 `gamma_lambda` 与查找返回的 block modifier，通过 `RepContext::sr_with_modifier` 完成，与上游 `common_block::sr` 的做法一致。该路径保留逐行参数信息，可关联 [[块修正子的相对化与标准参数恢复]]。^[deformation-drivers.md:34-37]

## 拥有资源的父块：DeformParent

`DeformParent` 是递归 twisted deformation 在可约点查找时返回的拥有资源的版本，其变体为 `Full { Box<BlockGraph>, Weight }` 与 `Partial { Arc<PartialBlock>, BlockModifier }`。递归驱动通过 `as_kl_sum_parent` 将其转换为借用视图，并必须在 `twisted_deformation_terms` 借用块视图期间保持所选父块存活。^[deformation-drivers.md:89-93]

在 [[扭曲全形变计算流程]] 中，`lookup` 在具有积分 `gamma` 的可约点参数处，承担上游 `rt.lookup(zi, index, bm)` 与 `block.extended_block(bm, ...)` 的角色。rank-0 积分子系统对应单例，不贡献形变项，也不调用 `lookup`。^[deformation-drivers.md:124-134]

## 父块相关的计算语义

父块还决定部分计算的长度函数：`twisted_kl_column_at_s` 针对父块元素 `y0`，使用 `parent.length(eblock.z(x))` 确定交错符号；`twisted_kl_sum` 则使用扩展块自身的 `eblock.length`。这一差异不能在统一父块接口时被抹去，详见 [[twisted KL 和的长度函数选择]]。^[deformation-drivers.md:95-103]

奇异集的处理也依赖父块上下文。平凡 block modifier 下，`simple_singular_flags` 对应 `common_block::singular(gamma)`；扩展块将该集合折叠为 singular-orbit flags，部分父块则以同样方式折叠其子系统生成元的奇异集。^[deformation-drivers.md:77-81]

## 适用边界与证据范围

来源包在 `IntegralBlockScope::ProperSubsystem` 的说明中保留了移植边界：该处所述接口不支持 common-block 支撑，调用方必须显式失败，不能默默改用完整块计算；同一来源另行描述了 `PartialBlock` 父块及 `common_deformation_terms` 路径。因此，部分父块抽象的存在不能被理解为所有驱动入口都支持真积分子系统。^[deformation-drivers.md:73-75, deformation-drivers.md:85-93, deformation-drivers.md:112-114]
