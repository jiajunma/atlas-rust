# 形变驱动的冻结移植契约

形变驱动的冻结移植契约是 Rust `deform.rs` 移植上游 `gkmod/repr.cpp` 驱动时遵循的 `domain/deform` 约定，涵盖 `twisted_deformation_terms`、两个在 $s$ 处求值的 twisted KL 和、`block_deformation_to_height` 与递归 `twisted_deformation`。它明确参数重构、积分子系统、奇异集、递归预处理和缓存简化的适用边界。^[deformation-drivers.md:18-48]

## 参数重构与父块选择

完整块路径由调用方一次性提供 `lambda_rho`，不再逐元素从上游 `StandardReprMod` 池读取。这要求所有形变项共享所传的值；完整块本身并不保证这一点。例如，SL(2,R) 在 $\gamma=2\rho$ 时，compact-Cartan 元素的值为 `[1]`，split 元素为 `[0]`。语言层采用 `rc.lambda_rho(p)`，与来源所述已验证的 `deform` 分支保持一致。^[deformation-drivers.md:29-33]

真积分子系统使用 [[公共块的构造与元素编号（PartialBlock）|PartialBlock]]，每行结合自身存储的 `gamma_lambda` 与 lookup 返回的 [[BlockModifier 块修正子|BlockModifier]]，通过 `RepContext::sr_with_modifier` 重构参数。这对应上游 `common_block::sr`，不能套用完整块路径的常量 `lambda_rho` 假设。^[deformation-drivers.md:34-37, deformation-drivers.md:85-89]

[[形变计算的父块抽象]]由两个类型承载：`KlSumParent<'a>` 提供完整块或部分块的借用视图；`DeformParent` 是递归查找返回的拥有型版本。递归驱动必须在 `twisted_deformation_terms` 借用块视图期间保持父块存活，并通过 `as_kl_sum_parent` 获取借用。^[deformation-drivers.md:83-93]

## 积分子系统的门控

`integral_block_scope(rc, gamma)` 按余根与 `gamma` 的整配对情况分类：判断条件是 `coroot · gamma.numerator()` 能否被 `gamma.denominator()` 整除。无根整配对时为 `Singleton`；每个简单余根都整配对时为 `Full`；真积分子系统对应 `ProperSubsystem`。^[deformation-drivers.md:61-75]

rank-0 情形走单例 `{p}` 的快速路径：块元素长度为零，形变项为空，twisted KL 和在 $s$ 处为 `1*p`。递归形变中，这类单例不调用 `lookup`。^[deformation-drivers.md:38-39, deformation-drivers.md:68-70, deformation-drivers.md:130-132]

完整块驱动的移植面不支持把 `ProperSubsystem` 当作完整块处理；缺少相应 common-block 支撑时，调用方必须显式失败。来源以 A1、$\nu=[1]/2$ 为反例：完整块大小为 3，而积分块是单例。因此，真积分子系统需要前述部分块路径。^[deformation-drivers.md:34-37, deformation-drivers.md:71-75]

## 奇异集与长度函数

上游按 `block_modifier` 计算的 singular orbits，只有在 `bm` 平凡时，才与 `ExtBlock::singular_orbits` 使用的普通 simple-coroot singular set 一致。此时 `bm.simp_int` 按恒等索引排列，`bm.simple_pi` 为恒等置换；部分父块则折叠自身子系统生成元的 singular set。^[deformation-drivers.md:40-43, deformation-drivers.md:77-81]

两个 twisted KL 和必须保留不同的长度约定：`twisted_kl_sum` 对 extended-block 元素求交错列和，符号取自扩展块长度；`twisted_kl_column_at_s` 对父块元素处的参数求交错和，符号取自父块长度 `parent.length(eblock.z(x))`。这一差异见 [[twisted KL 和的长度函数选择]]。^[deformation-drivers.md:95-103]

## 递归预处理与缓存简化

当 `gamma.denominator() > 2^rank` 时，先执行 `weyl::alcove_center` 收缩，再进入递归 twisted deformation。上游 `Rep_table` 的 `deformation_unit`／`alcove_hash` 记忆化在此移植中由朴素重算替代；没有共享池时，每个结果都针对当前报告 flip 的参数计算，因此不需要 memo-hit flip 调整。^[deformation-drivers.md:44-48]

[[扭曲全形变计算流程|递归 twisted deformation]]接受 final、delta-fixed 参数，输出 `(KType, SplitInteger)` 项，并报告 shrink-wrap 到最后一个 reducibility point 所记录的 net flip；未发生 shrink-wrap 时，`flip == false`。可取消变体在递归或块级操作之间检查取消请求，取消时返回 `Ok(None)`，不发布部分多项式。^[deformation-drivers.md:124-134]

## 输出与块形变的适配

`twisted_deformation_terms` 的平凡 modifier 版本使用父块编号，按 reverse-accumulated finals 顺序返回 `(StandardRepr, int)`。wrapper 将系数 `c` 转为 `Split(c, -c)`，即 $c(1-s)$，再按 `SR_poly` 顺序排序。部分块的 `common_deformation_terms` 则采用上游 `contributions(block, block.singular(bm,gamma), y)` 路径。^[deformation-drivers.md:59-59, deformation-drivers.md:105-114]

`block_deformation_to_height` 返回高度不超过 `height_bound` 的项，顺序为 downward（reversed）block order；`u32::MAX` 对应上游负界表示的 maximal level。由于 Atlas 值不可变，上游原地 `queue.erase` 的效果改为用与 `accumulator` 平行的已消费项 flags 报告。上游借助 `plug_hole` 跳过部分 KL 表工作；来源说明多项式值不依赖这些 holes，因此移植版本填充整张表。^[deformation-drivers.md:115-122]
