# 换行抑制状态机

换行抑制状态机是 Atlas 有状态词法器控制命令终止的机制：只有能够终止当前命令的换行才成为可观察的 `Newline` token，分组构造与续行 token 会抑制换行。扫描器支持解析器或 REPL 逐 token 消费，`tokenize` 则提供获取完整 token 流的兼容接口。^[atlas-core-lex.md:9-12, atlas-core-lex.md:38-43]

## 状态与换行条件

`Lexer` 保存 `offset`、`ended`、`pending`、`nesting`、`prevent_termination`、`previous_termination` 和 `at_command_start`。其中，`nesting` 是由 `Group`、`Let`、`Block` 构成的嵌套栈。`skip_space` 在内部消费空白和注释；只有当 `nesting` 与 `prevent_termination` 都为空时，换行才透出，否则被消费。^[atlas-core-lex.md:40-46]

## 关键字与标点转换

`apply_keyword` 处理关键字引起的状态转换：`let` 压入 `Let`；`begin`、`if`、`while`、`for`、`case` 压入 `Block`；`in` 在栈顶为 `Let` 时弹栈并设置 `I`；`end`、`fi`、`od`、`esac` 执行弹栈。`and`、`or`、`not` 设置 `~`，`whattype`、`set`、`set_type` 分别设置 `W`、`S`、`T`。^[atlas-core-lex.md:47-50]

`apply_punctuation` 对 `(`、`[` 压入 `Group`，对 `)`、`]` 执行弹栈；`,`、`;`、`.`、`:` 分别设置以自身表示的续行标记，`~` 设置 `~`。^[atlas-core-lex.md:51-52]

## 算符的续行规则

`operator_termination` 检查前一个终止符：若它是 `.`，当前算符不再抑制换行，因此“`.` 后接算符”的序列不会吞掉换行；否则，以该算符字符设置抑制状态。^[atlas-core-lex.md:53-54]

`finish_operator` 尝试跨越空白和注释寻找 `:=`。若找到，则融合为一个 `OperatorBecomes` token，并设置 `:`；否则回退扫描偏移，输出带续行标记的普通算符。注释消费失败时也会回退。该融合行为属于 [[Atlas 词法 Token 模型]] 的一部分。^[atlas-core-lex.md:17-20, atlas-core-lex.md:55-57]

关系符采用独立规则：由 `<`、`=`、`>` 构成的极大连续段是一个算符；单个尖括号同时作为类型参数定界符，不吞换行。关系符永不与 `:=` 融合，而 `:=` 自身设置 `:`。裸 `!` 是 const 模式标记，既不是公式算符，也不能作为 operate-assign 的头；`->`、`~[`、`\%`、`##` 各有专门分支。^[atlas-core-lex.md:58-62]

## 错误恢复与局部扫描边界

不支持的字符会使词法器清空嵌套与抑制状态，让下一个换行能够终止命令。源材料将此对应于 oracle 报告语法错误并在下一换行恢复的行为。`recover_command` 则丢弃当前物理行的剩余部分，重置续行、嵌套和命令首状态。^[atlas-core-lex.md:63-64, atlas-core-lex.md:78-78]

字符串扫描遇到换行会判定字符串未闭合，报告词法 warning，并将恢复出的 `String` token 放入 `pending`，使 token 与后续命令仍可供解析器使用，详见 [[字符串转义与未闭合恢复]]。命令首指令在文件名前遇到换行则得到空文件名；扫描器不消费该行剩余部分，后续由会话帧校验，详见 [[命令首指令与文件名扫描]]。^[atlas-core-lex.md:68-77]

[[TokenCursor 单 Token 前瞻|TokenCursor]] 将词法错误像 token 一样缓存，使 `peek` 与 `bump` 看到同一结果。完整流接口中，`tokenize` 采用全有或全无的方式；`tokenize_with_diagnostics` 返回 `LexOutput { tokens, diagnostics }`，按遭遇顺序保留诊断，同时保留所有可恢复 token。^[atlas-core-lex.md:79-83]

## 实现分工与证据边界

源材料记录了覆盖上述状态机分支的 23 个测试，但仅声明完成结构性阅读，不构成语言验收。词法器不做语义判定：文法适配位于 `syntax.rs`，逐命令消费位于 `session.rs`，包含与重定向语义位于 `session_frame.rs`。上游行号引用属于实现方的移植陈述，词法兼容性仍以 HPC 语言语料门为准。^[atlas-core-lex.md:9-13, atlas-core-lex.md:85-91]
