# 整数矩阵算法的逐操作保真移植

整数矩阵算法的逐操作保真移植，要求保留上游算法的确切幺模操作序列、行列式符号簿记和具体选解。`matreduc.rs` 以此策略移植 `utilities/matreduc.cpp` 的 `diagonalise`、`gcd`、`has_solution` 与 `find_solution`：欠定系统 $Ax=b$ 的被选解在下游可观测，$\tau$/$t$ 坐标的奇偶性会进入 `ext_block::same_sign`，因此兼容目标是上游选出的那个解。^[matreduc.md:18-26]

## 算术与对角化契约

模块采用 wrapping `i32` 算术。来源将其描述为对上游 C++ `int` 行为的精确镜像，包括可能影响被选解的溢出行为域；这是模块声明的移植契约。^[matreduc.md:24-26]

内部类型 `IntMatrix` 以行主序存储矩形整数矩阵。`diagonalise(m)` 返回 `(row, col, diagonal)`，其中 `row`、`col` 为幺模矩阵，使 `row * m * col` 对角化，对角元素除第一项外均为正。对于 $0\times n$ 或 $n\times0$ 的空形状，算法提前返回。^[matreduc.md:28-33]

## 消元顺序与符号簿记

`divide(a, b)` 在正除数条件下执行下取整除法：非负被除数直接相除，负数使用 `-1 - ((-1 - a) / b)`，避免对 `i32::MIN` 取负。`gcd` 使用 `wrapping_abs` 选择最小绝对值主元；负主元取正时翻转 `flip`，并在记录矩阵中设置 `col.set(mindex, mindex, -1)`。随后通过 `divide` 消元，末尾交换列至 `dest` 时再次翻转 `flip`。详见 [[整数消元中的下取整除法与 gcd 主元选择]]。^[matreduc.md:37-41]

[[对角化的行列式符号簿记]]依赖具体的赋值和异或顺序：每列首次 `gcd` 的 `flip` **覆盖赋值**给 `row_minus`；内层交替执行行、列 `gcd`，分别将 `flip` 异或计入 `col_minus`、`row_minus`。循环退出后再执行 `row_minus ^= flip`：从行 `gcd` 的分支退出时，该值计入两侧；从列 `gcd` 的分支退出时，其净效果抵消。^[matreduc.md:42-45]

主元列未左对齐时，算法用稳定排列 `pull_back_columns` 调整位置，并按逆序对奇偶性异或置换符号。最后，当 `row_minus != col_minus` 时，将 `diagonal[0]` 取负，再依据两个符号标志分别对第 0 行、列乘以 −1 归一化。源码注释对行列式约束的表述存在差异；来源以测试为准，采用 `det(col) == 1`、`det(row)` 可为 −1 的口径。^[matreduc.md:45-49]

## 求解接口与失败行为

`has_solution(a, b)` 先对角化，再对 `b` 左乘 `row`，逐坐标检查可除性，以判定 $ax=b$ 是否有整数解。`find_solution(a, b)` 返回一个解，无整数解时返回 `None`；上游在此情形抛出异常，而 Rust 调用方预期已先运行 `has_solution`。^[matreduc.md:54-59]

矩阵接口使用断言检查形状、长度和索引，包括 `from_entries` 的形状、`apply_to`/`right_prod` 的长度、`transpose` 的方阵要求，以及 `row_apply`/`column_apply` 的边界。因此，向 `has_solution` 等接口传入长度不匹配的 `b` 会触发 panic，而非返回 `Err`。^[matreduc.md:50-52]

同一模块还包含来自其他上游文件的操作。`in_left_image`/`in_right_image` 对应 `ext_block.cpp` 的像判定；[[单位上三角整数矩阵求逆]]对应 `matrix.cpp`，使用 wrapping `i32` 回代，输入非方阵或某对角元不为 1 时返回错误。^[matreduc.md:60-64]

[[偶数指数的虚数单位幂计算]]对应 `arithmetic.h` 的 `exp_i(n)`，要求 $n$ 为偶数并返回 $i^n\in\{1,-1\}$。该前置条件在上游使用 `assert`，Rust 使用 `debug_assert!`；release 下奇数输入落入 `-1` 分支，没有防护。^[matreduc.md:65-67]

## 测试锚点与覆盖缺口

测试同时检查代数性质和具体输出。11 个重构用例检查 `|det(row)| == 1`、`det(col) == 1`、逐项对角结果及首项之外的正性；`find_solution` 覆盖满秩、秩亏和矩形三种形态。此外还有一维像判定、单位上三角逆的两个正常用例与两个拒绝用例，以及 `exp_i` 的五点测试。^[matreduc.md:69-74]

`oracle_reference_cases` 固定来自 C++ oracle 的精确结果：矩阵 $\begin{pmatrix}0&5\\0&0\end{pmatrix}$ 对应 `diagonal = [−5]` 及精确的 `row`/`col`，矩阵 $\begin{pmatrix}-4\end{pmatrix}$ 对应 `diagonal = [−4]`；另有主元列未左对齐的 $6\times6$ 秩亏案例，保留完整变换矩阵字面量与解 `[6,14,5,−37,−421,345]`。^[matreduc.md:71-74]

尚未覆盖的路径包括 wrapping 溢出域、矩形或秩亏情况下的 `in_*_image`、空形状 `diagonalise`，以及 `from_entries`/`apply_to` 的 panic 路径。文档声明可观测的溢出行为因此仍有明确的测试缺口。^[matreduc.md:74-76]

## 证据边界

来源记录了两次结构性阅读，两次所读源码字节及 SHA-256 相同。模块文档记载已与编译版 oracle 逐位验证，但本来源未重跑该验证；逐位保真证据属于模块自己的 [[HPC 验收证据链]]。^[matreduc.md:9-16]

上游文件位置均转述自源码注释，未独立重读上游，行号可能随版本演进而漂移。本来源未执行构建、测试或原版运行，不提供新的数学验收、性能或并行结论。^[matreduc.md:80-89]
