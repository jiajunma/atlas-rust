# 文件命令兼容性的证据边界

文件命令兼容性涉及文件包含、单命令输出重定向、框架提示行、字节输出、错误级联及会话退出状态。`session_frame.rs` 的来源材料完成了结构性阅读，覆盖 993 行代码及其中的 18 个测试；这一状态不代表语言或数学验收。^[atlas-core-session-frame.md:9-16]

## 证据层次

结构性阅读说明实现的组织与行为约定。源码中对上游 `buffer.w`、`main.w`、`parser.y` 的引用属于实现方的移植陈述，不能独立证明端到端可见行为兼容；该层面的判断以 HPC 差分语料为准，可关联 [[HPC 验收证据链]]。^[atlas-core-session-frame.md:94-97]

文件内的 18 个测试提供单元级行为锚点，涵盖原始字节输出、包含控制、重定向时序与失败处理、缩进、void 抑制、续行和物理行报告。端到端文件命令兼容仍以 HPC 语料门为准；材料特别指出，`eval/file_commands_b9` 是相关语料清单中唯一允许写入 `/tmp` 的用例。^[atlas-core-session-frame.md:81-90]

## 需要保留的兼容契约

文件包含不仅涉及能否读取文件，还涉及 include-once、强制重读、路径解析顺序、循环守卫及退出传播。已在活动包含栈中的文件会被静默跳过并视为成功；包含内的 `quit` 则结束整个会话。相关行为见 [[SessionFrame 会话帧与文件包含语义]] 与 [[包含文件的搜索路径解析]]。^[atlas-core-session-frame.md:11-15, atlas-core-session-frame.md:29-48]

[[单命令输出重定向的执行纪律]]要求命令体先按表达式解析，解析成功后、求值前才打开 sink。因此语法错误不创建文件，求值失败仍可能留下部分输出。打开失败只输出裸 stderr 行 `Failed to open {name}`，并保持会话 clean；命令的 `Output`/`OutputBytes` 写入 sink，其余事件照常上行，`sink.close()` 无条件执行。^[atlas-core-session-frame.md:23-25, atlas-core-session-frame.md:59-65]

错误处理必须区分诊断类别与会话状态：语法、类型和求值错误会使会话变脏，打开失败与 abandon 级联本身不会。词法 warning 只报告，不弄脏也不中止；真正的词法错误会置 dirty，并在包含内部触发 abandon 级联。各层 abandon 消息按最内层优先的顺序发出，可关联 [[会话 clean 标志与诊断分流]] 与 [[嵌套包含的 abandon 级联]]。^[atlas-core-session-frame.md:43-46, atlas-core-session-frame.md:66-70]

输出兼容还包括非 void 值的 `Value:` 前缀、void 抑制、每层两空格的报告缩进，以及 `ReportBytes` 的字节保留。输入读取采用有损 UTF-8，而输出路径有专门的原始字节保留测试；因此材料中的输入与输出字节约定需要分别理解。相关概念见 [[SessionEvent 与字节保留输出]]。^[atlas-core-session-frame.md:20-22, atlas-core-session-frame.md:52-55, atlas-core-session-frame.md:83-84]

诊断位置依赖预处理后的物理行映射：每行先剥除尾空白，再将以 `\` 结尾的行直接与下一行拼接，不插入额外内容。`line_map` 将重写行映射到首个物理行，供诊断和 abandon 行号使用；仅比较错误消息正文不足以涵盖这一位置约定。^[atlas-core-session-frame.md:72-79]

## 结论的适用范围

该材料支持说明实现约定和单元测试覆盖范围，但未给出端到端 HPC 差分通过结果。兼容性陈述应保留这一证据边界；快照字节数、哈希及 Git base `964f0033` 只用于标识所检查的字节，不能证明其正确性。^[atlas-core-session-frame.md:81-99]
