# 普通根系的确定性枚举

`RootSystem` 从 [[BasedRootDatum：带基根数据与构造不变量|BasedRootDatum]] 生成有限普通根系。最终编号由根的环境坐标字典序决定，根、余根和简单根坐标三张表保持索引对齐，同一个 `RootId` 同时索引三者。枚举使用调用方显式提供的资源预算，预算不保存在构造结果中。^[root-system.md:18-24]

## 枚举流程与顺序保证

`enumerate_with_budget` 首先按格秩、根数、坐标条目、反射步数的固定顺序检查预算，比较均使用严格的 `>`；随后通过 `datum.try_clone()` 创建自有快照。播种阶段为每个简单根插入正负两条记录，其简单根坐标分别为 \(\pm e_i\)，负根取反使用 `checked_neg`。^[root-system.md:55-58]

[[根系的 BFS 反射闭包枚举|反射闭包]]使用广度优先搜索：通过 `pending.pop_front()` 取出记录，对每个简单生成元 \(g\) 计算配对系数 `pair(root, coroot_g)`，以 `checked_sub` 更新简单根坐标的第 \(g\) 项，再分别用 `reflect_weight` 和 `reflect_coweight` 生成候选根与余根。^[root-system.md:58-61]

最终根序仅由闭包 `BTreeMap` 的键序决定，与 BFS 发现顺序无关。A2 六根的环境坐标字典序是这一确定性约定的测试锚点。^[root-system.md:61-62]

## 闭包插入的不变量

每次插入候选时，先检查自配对 \(\langle\alpha,\alpha^\vee\rangle=2\)，再检查根坐标是否重复；重复候选也必须通过自配对检查。相同根坐标对应的余根与简单根坐标必须逐字节一致，否则返回 `"coroot agreement"` 不变量错误。源码注释将这两项检查称为防御性检查，并说明已知公开 datum 构造路径不会触发它们；测试通过直接注入私有 `Closure` 覆盖拒绝路径。^[root-system.md:64-69]

重复候选不计入根数预算。对于新根，当 `seen.len() == max_roots` 时拒绝插入，返回 `RootSystemResourceLimit { resource: "roots" }`。^[root-system.md:66-67]

## 资源预算与兼容接口

[[根系枚举的显式资源预算|RootSystemBudget]] 包含格秩、根数、坐标条目数和反射步数四类限额。静态上界使用 `u128` 饱和算术，坐标条目估算覆盖借入的 datum、自有快照、映射、待处理队列及一个在途候选。纯环面半单秩为零，有效根数上界为零；静态检查与运行时根数拒绝属于不同路径，分别有测试锚定。^[root-system.md:30-31, root-system.md:71-74]

兼容接口 `enumerate(datum, max_roots)` 使用 `RootSystemBudget::complete_for` 将条目与步数限额设为饱和最坏值，使运行中只有根数限额能够触发预算拒绝。它将根数资源错误映射为历史错误 `ResourceLimitExceeded { limit }`，其他错误原样透传。^[root-system.md:50-53]

## 结果表示与查询

[[RootId 与根系索引对齐|RootId]] 是 `usize` 的 newtype，crate 外通过 `from_usize` 和 `index()` 构造或读回。除三张索引对齐表外，`RootSystem` 还保存正根标志、生成元顺序的简单根 ID，以及每根对应的根与余根梯子底表；访问器通过 `Option` 或 `Result` 处理越界。^[root-system.md:18-24]

`id_of` 对有序根表执行二分查找。正根判定读取预计算标志，判据是简单根坐标中存在正分量；由于根表按环境坐标排序，不能通过将表等分来区分正负根。`simple_root_ids()` 保留生成元顺序，供下降查询使用，避免逐次二分查找，参见[[根系正性判定与环境坐标排序的分离]]。^[root-system.md:78-82]

`bracket(root, coroot)` 采用根在左、余根在右的配对约定，任一 ID 越界均返回 `IndexOutOfRange`，两侧各用自己的表长作为上界。`action_permutation` 先检查 datum 一致性，再逐根作用并反查索引；`combine_roots` 使用逐坐标受检加减后查询成员资格，以 `Ok(None)` 表示结果不是根。^[root-system.md:78-85]

## 梯子底表与只读集合

构造时全量预计算[[根与余根的梯子底表|梯子底表]]，没有惰性选项。固定 \(\alpha\) 后，`min_roots[alpha]` 记录所有使 \(\beta-\alpha\) 不是根的 \(\beta\)，包含 \(\alpha\) 自身；`min_coroots` 在配对余根上定义同一关系。根成员查询使用二分查找；余根跟随根序，自身不保证有序，因此先建立坐标到下标的映射。^[root-system.md:89-92, root-system.md:128-129]

梯子底成员查询采用[[Rust ladder 成员查询的选择性溢出处理|溢出即非成员]]规则：`checked_sub` 溢出意味着精确坐标差超出 `i32` 范围，不可能等于任何已存根或余根，因此成员查询返回 `false`；分配等其他错误仍然传播。^[root-system.md:93-96]

集合以 [[RootSet 只读位图集合|RootSet]] 表示，依附稳定根序，构造后没有公开修改入口。`contains` 对越界返回 `false`，`iter` 按索引升序迭代；私有插入虽直接索引块，但内部调用保证 `beta < count`。^[root-system.md:106-109]

## 测试与证据边界

来源列出的测试锚点包括 A2 字典序与简单根坐标、根与余根配对、每根自配对为 2、A2 全部六个 Weyl 作用的运输一致性、预算边界与运行时根数拒绝、兼容包装器全字段结果一致性、秩 33 动态枚举，以及种子余根 `i32::MIN` 取反溢出。^[root-system.md:114-120]

梯子底表另有 B2/G2 oracle 集合、A2/B2/G2 暴力对照、越界 ID 和纯环面空表测试。坐标边界测试固定四个数值与两种配置，共八组；注释所称原 Atlas 接受全部十一个用例与此数量不同，来源将差异记录为待核，其余用例位于 HPC 证据侧。^[root-system.md:93-102]

这些记录属于结构性源码阅读，不构成根系层的数学验收。来源未核对注释引用的上游源码字节或 HPC 捕获数据，本次知识维护也未执行 Atlas、Cargo、测试或 benchmark；`DatumMismatch`、`InvalidRootAutomorphism`、`AllocationFailed` 及包装器中其他资源错误原样透传的分支，尚未见直接触发的测试。^[root-system.md:10-14, root-system.md:124-131, root-system.md:135-139]
