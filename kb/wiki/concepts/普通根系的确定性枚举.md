# 普通根系的确定性枚举

`RootSystem` 从 [[BasedRootDatum：带基根数据与构造不变量|BasedRootDatum]] 生成有限普通根系。输出按根的环境坐标字典序升序排列，`roots`、`coroots` 与 `simple_coordinates` 三张表保持索引对齐，同一个 `RootId` 同时索引三者。枚举由调用方显式提供资源预算，预算不保存在构造结果中。^[root-system.md:18-24]

## 枚举流程与确定性顺序

`enumerate_with_budget` 首先按格秩、根数、坐标条目、反射步数的固定顺序检查预算，均以严格的 `>` 判定超限；随后通过 `datum.try_clone()` 创建自有快照。播种阶段为每个简单根插入正负两条记录，简单根坐标分别为 $\pm e_i$，负根通过 `try_negate` 中的 `checked_neg` 进行受检取反。^[root-system.md:55-58]

反射闭包采用广度优先搜索（BFS）：通过 `pending.pop_front()` 取出记录，对每个生成元 $g$ 计算 `coefficient = pair(root, coroot_g)`，以 `checked_sub(coefficient)` 更新简单根坐标的第 $g$ 项，再通过 `reflect_weight` 与 `reflect_coweight` 生成候选根和余根并加入闭包。^[root-system.md:58-61]

**最终根序独立于 BFS 发现顺序**，仅由闭包 `BTreeMap` 的键序决定。A2 六根的环境坐标字典序是这一约定的测试锚点。^[root-system.md:61-62]

## 闭包插入的不变量

`Closure::insert` 先检查自配对 $\langle\alpha,\alpha^\vee\rangle=2$，再检查根坐标是否重复，因此重复候选也必须通过自配对检查。重复键对应的余根与简单根坐标必须逐字节一致，否则返回 `"coroot agreement"` 不变量错误。源码注释将这两道检查称为防御性检查，说明已知公开 datum 构造路径不可达；测试通过直接注入私有 `Closure` 覆盖这些拒绝路径。^[root-system.md:64-69]

重复候选不计入根数预算。对于新根，当 `seen.len() == max_roots` 时拒绝插入，返回 `RootSystemResourceLimit { resource: "roots" }`。^[root-system.md:66-67]

## 资源预算与兼容接口

`RootSystemBudget` 提供 `max_lattice_rank`、`max_roots`、`max_coordinate_entries` 和 `max_reflection_steps` 四类限额。预算公式采用 `u128` 饱和算术：`entry_bound = 2(r² + 2rn) + (R_eff+1)(4n+2r)`，`step_bound = R_eff · r`。条目上界覆盖借入 datum、自有快照、映射、待处理队列及一个在途候选；纯环面半单秩为零，取 `R_eff = 0`。静态预算检查与运行时根数拒绝是两条不同路径，分别有测试锚定。^[root-system.md:30-31, root-system.md:71-74]

兼容接口 `enumerate(datum, max_roots)` 使用 `RootSystemBudget::complete_for` 将条目与步数限额设为饱和最坏值，使运行中只有根数限额能够触发预算拒绝。它将 `RootSystemResourceLimit { resource: "roots" }` 映射为历史错误 `ResourceLimitExceeded { limit }`，其他错误原样透传。^[root-system.md:50-53]

## 结果表示与查询

[[RootId 与根系索引对齐|RootId]] 是 `usize` 的 newtype，crate 外通过 `from_usize` 和 `index()` 构造或读回。除三张索引对齐表外，`RootSystem` 还保存预计算的正根标志、生成元顺序的简单根 ID，以及每根对应的根与余根梯子底表；访问器通过 `Option` 或 `Result` 处理越界。^[root-system.md:18-24]

`id_of` 对有序根表执行二分查找。`is_positive` 读取预计算标志，正根判据为简单根坐标中存在正分量；根表按环境坐标排序，不能通过将表等分来区分正负根。`simple_root_ids()` 保留生成元顺序，供下降查询使用，避免逐次二分查找。^[root-system.md:78-82]

`bracket(root, coroot)` 采用根在左、余根在右的配对约定，任一 ID 越界均返回 `IndexOutOfRange`，两侧各用自己的表长作为上界。`action_permutation` 先检查 datum 一致性，再逐根作用并反查索引；`combine_roots` 逐坐标执行受检加减，再以 `id_of` 判断成员资格，`Ok(None)` 表示结果不是根。^[root-system.md:78-85]

## 梯子底表与只读集合

构造时全量预计算根与余根的梯子底表，每对 $(\alpha,\beta)$ 执行两次坐标差，没有惰性选项。`min_roots[alpha]` 记录所有使 $\beta-\alpha$ 不是根的 $\beta$，包含 $\alpha$ 自身；`min_coroots` 在配对余根上定义同一关系。根成员查询使用二分查找；余根跟随根序，自身不保证有序，因此先建立坐标到下标的映射。相关定义见 [[Root ladder bottom 集与固定宽度成员查询]]。^[root-system.md:89-92, root-system.md:128-129]

梯子底成员查询采用[[Rust ladder 成员查询的选择性溢出处理|溢出即非成员]]规则：`checked_sub` 溢出意味着精确坐标差超出 `i32` 范围，不可能等于任何已存根或余根，因此该成员查询按 `false` 处理；分配等其他错误仍然传播。^[root-system.md:93-96]

`RootSet` 是依附稳定根序的只读位图集合，没有公开构造或修改入口。`contains` 对越界返回 `false`，`iter` 按索引升序迭代。私有 `insert` 直接索引块，越界会 panic，但内部调用保证 `beta < count`。^[root-system.md:106-109, root-system.md:126-127]

## 测试与证据边界

来源列出的测试锚点包括 A2 字典序与简单根坐标、根与余根配对、每根自配对为 2、A2 全部六个 Weyl 作用的运输一致性、四类资源拒绝及限额边界、运行时根数拒绝、兼容包装器全字段结果一致性、秩 33 动态枚举，以及种子余根 `i32::MIN` 取反溢出。^[root-system.md:114-120]

梯子底表另有 B2/G2 oracle 集合、A2/B2/G2 暴力对照、越界 ID 和纯环面空表测试。坐标边界测试覆盖 $m\in\{0,2^{30}-1,2^{30},\mathrm{i32::MAX}\}$ 与两种配置，共八组，固定“不拒绝、两表均为全集合”的行为。注释所称原 Atlas 接受十一个用例与本文件八组测试的数量差异仍待核对，来源注明其余用例在 HPC 证据侧。^[root-system.md:93-102]

上述记录属于结构性源码阅读，不构成根系层的数学验收。来源未核对注释引用的上游源码字节或 HPC 捕获数据，本次知识维护也未执行 Atlas、Cargo、测试或 benchmark。`DatumMismatch`、`InvalidRootAutomorphism`、`AllocationFailed` 及包装器中其他资源错误原样透传的分支，尚未见直接触发的测试。^[root-system.md:10-14, root-system.md:124-131, root-system.md:135-139]
