# 有序强制转换注册表

有序强制转换注册表位于 `coercions.rs`，保存类型转换的注册信息并保持上游顺序。`coercion_between` 与 `row_coercion` 都采用**首中即返**的线性扫描，因此注册顺序直接影响转换选择。^[atlas-core-support-layer.md:40-45]

## 初始化与转换标签

注册表通过 `OnceLock` 单次构建，共有 29 条注册，测试固定了这一数量。每条注册的 tag 保留上游转换名，并在转换节点上打印为 `tag:expr`。例如，`QI` 表示 `int → rat`，`M[V]` 表示 `[vec] → mat`，`LT` 表示 `string → LieType`，`KpolK` 表示 `KType → KTypePol`，`PolP` 表示 `Param → ParamPol`。^[atlas-core-support-layer.md:47-54]

## 注册顺序与列表显示

`row_coercion(final_type)` 用于非行类型上下文中的列表显示：它查找第一个来源为行类型、目标为 `final_type` 的注册条目，返回来源行类型的分量类型，作为显示元素的类型。在 `mat` 上下文中，`[vec] → mat` 必须先于嵌套整数行到 `mat` 的转换被命中，因此得到的元素类型是 `vec`，而非 `[int]`。详见 [[列表显示的行转换选择]]。^[atlas-core-support-layer.md:42-45, atlas-core-support-layer.md:55-57]

## 类型邻近与宽窄关系

同一模块的 `is_close(x, y) -> u8` 用三个比特表示类型关系：`0x1` 表示左侧可转换为右侧，`0x2` 表示右侧可转换为左侧，`0x4` 表示邻近。相等时返回 `0x7`；这一判断包含 `void` 与递归身份，并先于边界检查和类型展开。^[atlas-core-support-layer.md:58-60]

`void` 与 `*` 只与自身邻近。相等检查之后，递归名的 `Tabled/Applied` 情形返回 `0`，其他递归情形展开一层再检查；原始类型端点查注册表，行类型逐分量处理，元组对各分量结果取按位 AND。^[atlas-core-support-layer.md:60-61]

`broader_eq(a, b)` 实现平衡序中的宽窄比较：`void` 最宽，`*` 最窄；原始类型吸收所有可转换到自身的类型，行与元组逐分量比较。函数类型的比较要求参数类型相等。^[atlas-core-support-layer.md:62-64]

## 职责与证据边界

本模块只回答转换是否适用，转换节点随类型化管线到达。测试引用了两项原版背书证据：`3856293` 对应零参重载原地替换，`3856744` 对应递归名的名义身份。^[atlas-core-support-layer.md:65-66]

来源材料属于结构性源码阅读，不声称语言或数学验收。上游注册位置 `global.w:2526-2552`、`atlas-types.w:9137-9144` 及其他上游行号属于实现方的移植陈述，行为兼容仍以 HPC 语料门为准；快照的字节数与哈希只标识对应字节，Git base 为 `964f0033`。^[atlas-core-support-layer.md:9-12, atlas-core-support-layer.md:42-45, atlas-core-support-layer.md:70-74]
