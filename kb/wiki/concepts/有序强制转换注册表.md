# 有序强制转换注册表

有序强制转换注册表位于 `coercions.rs`，记录类型之间可用的转换，并保持上游注册顺序。`coercion_between` 与 `row_coercion` 都采用首中即返的线性扫描，因此条目的顺序直接影响转换选择。^[atlas-core-support-layer.md:40-45]

## 注册内容与初始化

注册表通过 `OnceLock` 单次构建，共有 29 条注册，数量由测试固定。每条转换的 tag 保留上游转换名，并在转换节点中打印为 `tag:expr`。例如，`QI` 表示 `int → rat`，`M[V]` 表示 `[vec] → mat`，`LT` 表示 `string → LieType`，`KpolK` 表示 `KType → KTypePol`，`PolP` 表示 `Param → ParamPol`。^[atlas-core-support-layer.md:47-54]

## 顺序与列表显示

`row_coercion(final_type)` 为非行类型上下文中的列表显示寻找转换：它选择第一个来源为行类型、目标为 `final_type` 的条目，并返回该来源行类型的分量类型。因此，在 `mat` 上下文中，`[vec] → mat` 必须排在 `[[int]] → mat` 之前，使列表元素按 `vec` 处理，而不是按 `[int]` 处理。相关语义见 [[列表显示的行转换选择]]。^[atlas-core-support-layer.md:42-45, atlas-core-support-layer.md:55-57]

## 邻近与宽窄判定

同一模块提供 `is_close(x, y) -> u8`，用三个比特表达类型关系：`0x1` 表示左侧可转为右侧，`0x2` 表示右侧可转为左侧，`0x4` 表示邻近。类型相等时返回 `0x7`；这一判断包含 `void` 与递归身份，且先于边界检查和类型展开。`void` 与 `*` 只与自身邻近；递归名的 `Tabled/Applied` 情形返回 `0`，否则展开一层再检查。原始端点通过查表判定，行类型逐分量处理，元组按分量结果取按位 AND。^[atlas-core-support-layer.md:58-61]

`broader_eq(a, b)` 实现平衡序中的宽窄比较：`void` 最宽，`*` 最窄，原始类型吸收所有可转换到自身的类型，行与元组逐分量比较；函数类型的比较要求参数类型相等。这些规则与 [[Type 类型表示与语义等值]] 相关。^[atlas-core-support-layer.md:62-64]

## 职责与证据边界

该模块只回答转换是否适用；转换节点随类型化管线到达。测试引用了原版背书的零参重载原地替换与递归名名义身份证据，但源材料仅声明完成结构性阅读，不构成语言或数学验收；行为兼容仍以 HPC 语料门为准。相关背景见 [[原版背书的语言层回归测试]] 与 [[HPC 验收证据链]]。^[atlas-core-support-layer.md:9-12, atlas-core-support-layer.md:65-66, atlas-core-support-layer.md:70-74]
