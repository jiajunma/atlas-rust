# 有状态的逐命令会话执行

有状态的逐命令会话执行是 `session.rs` 的核心职责。Atlas 的词法分类依赖先前命令留下的状态，因此会话外层循环必须逐命令推进，不能预切分整个源文件。该模块属于 [[atlas-core 语言门面与兼容契约]] 所划分的可观察语言边界。^[atlas-core-session.md:9-14, atlas-core-root.md:9-13, atlas-core-root.md:49-50]

## 上下文与命令边界

`run_source` 为每个源创建全新的 `TypedContext`；`run_source_with_context` 则使用调用方持有的上下文。外层循环按 token 分流：遇到 `Newline` 时调用 `execute_tokens` 处理当前缓冲，遇到 `Eof` 时执行剩余缓冲并退出；普通 token 加入命令缓冲，词法错误产生的诊断直接进入事件流。^[atlas-core-session.md:29-40]

换行并不必然触发求值。终止符为 `Newline` 时，`execute_tokens` 将 `allow_more` 设为真，再调用 `parse_command_fragment_in(.., context.types(), allow_more)`。若返回 `Ok(None)`，则保留已有前缀、不求值、不发诊断，让后续输入继续累积到同一缓冲。原始源执行与文件会话共用这条[[多行命令的增量解析]]路径。^[atlas-core-session.md:47-50]

## 消费顺序与源码位置

`next_session_token` 在消费 token 的时刻调用 `context.note_completion_token` 记录标识符，从而保留被包含文件与后续命令之间原始的首次使用顺序。补全顺序由会话持有，并与当前名字可见性分离，参见[[会话补全顺序与名字可见性分离]]。^[atlas-core-session.md:44-46, atlas-core-root.md:41-42]

`Command::SetType` 的源码跨度依据真实词法终止符重建：上游 `parser.y` 将命令换行计入 `set_type` 的 `@$`，本实现按终止符行列重算，遇到 `Newline` 时列号加一，不猜测语义 token 之后的位置。详见 [[SetType 命令的词法终止符跨度重建]]。^[atlas-core-session.md:51-53]

## 事件输出与失败行为

会话通过六种带有源码跨度信息的 `SessionEvent` 变体表达结果：`Value`、`Output`、`ReportLine`、`OutputBytes`、`ReportBytes` 和 `Diagnostic`。其中，只有 `Value` 保留 void 标志，该标志从 `TypedCommandEvent::Value` 的 `type_.is_void()` 提升而来；诊断直接透传。^[atlas-core-session.md:16-27]

`SessionEvent::output()` 先尝试 `String::from_utf8`：合法 UTF-8 进入 `Output`，非法字节则原样进入 `OutputBytes`，不会被替换字符改写。这构成字节串从值到输出边界保持完整性的会话端点，详见 [[SessionEvent 与字节保留输出]]。^[atlas-core-session.md:22-26]

遇到 `Unsupported(_)` 时，循环产生内容为 `"unexpected token"` 的 Syntax 诊断，并调用 `lexer.recover_command()`。若 `context.execute` 失败，则先通过 `drain_failed_printed(span)` 排空已经打印的内容，再发送诊断，以保留求值中途产生的输出及其顺序。相关主题见[[打印、字符串转换与运行时错误的输出契约]]。^[atlas-core-session.md:36-36, atlas-core-session.md:54-56]

## 与会话帧的职责边界

会话循环本身拒绝文件包含指令：遇到 `Directive(_)` 时，产生 Io 诊断 `"file inclusion is only available through a session frame"`。文件包含与输出重定向由 `session_frame.rs` 负责；转换与求值位于 `typed.rs`，词法与文法适配分别位于 `lex.rs` 和 `syntax.rs`，领域内建位于 `domain_builtins.rs`。详见[[会话循环与文件会话帧的职责边界]]。^[atlas-core-session.md:37-39, atlas-core-session.md:72-74]

## 回归证据与限制

源快照中的 `session.rs` 共 3889 行，生产实现位于第 1–178 行，其余包含 201 个语言层回归测试。回归范式使用 `include_str!` 载入 `tests/math/generics/` 中的 fixture，并逐字节比较 `.oracle.stdout` 与 `.oracle.stderr`；HPC 差分发现的差异须先形成原版背书的回归。例如，`weyl_context_core_cold_dual_original` 绑定 A1 cold_dual 的冻结 goldens。参见[[原版背书的语言层回归测试]]。^[atlas-core-session.md:9-14, atlas-core-session.md:58-68]

本页依据的材料属于结构性阅读，不据此声称语言或数学验收。文件头与注释中的上游行号属于实现方的移植陈述，语义等值仍以 HPC 差分门为准；测试名、家族计数及哈希只标识相应快照，哈希本身不证明正确性。^[atlas-core-session.md:13-14, atlas-core-session.md:75-80]
