# 有状态词法分析与逐命令执行

Atlas 的 `lex.rs` 提供刻意有状态的词法器：注释可以嵌套，解析器或 REPL 可以逐 token 消费输入，`tokenize` 则是取得完整 token 流的兼容便利接口。词法器负责扫描及命令边界相关状态，`session.rs` 负责逐命令消费。^[atlas-core-lex.md:9-13, atlas-core-lex.md:87-89]

## 状态与命令边界

`Lexer` 保存扫描偏移 `offset`、结束标志 `ended`、待返回结果 `pending`、嵌套栈 `nesting`、续行状态 `prevent_termination`、前一终止状态 `previous_termination` 和命令首标志 `at_command_start`。核心不变量是：**只有能够终止当前命令的换行才成为可观察 token**；分组构造和续行 token 会抑制换行。^[atlas-core-lex.md:38-43]

`skip_space` 消费空白与注释，仅当嵌套栈为空且没有续行抑制时保留换行。`let` 压入 Let 层，`begin/if/while/for/case` 压入 Block 层，括号与方括号压入 Group 层；相应结束符更新嵌套状态。`in`、逻辑关键字及部分标点还会设置续行状态，详见 [[换行抑制状态机]]。^[atlas-core-lex.md:45-52]

算符通常会抑制后续换行，但存在明确例外：前一终止符为 `.` 时，随后算符不再抑制换行；单个 `<` 或 `>` 作为类型参数定界符时也不吞换行。普通算符后若跨空白或注释遇到 `:=`，可以融合成一个 `OperatorBecomes` token；关系符不参与这种融合。^[atlas-core-lex.md:53-62]

## 命令首指令与文件名

`<`、`<<`、`>`、`>>` 仅在命令首识别为指令，分别表示包含、强制包含、截断写入和追加写入。扫描器通过命令首状态区分这种识别位置，相关 token 表示见 [[Atlas 词法 Token 模型]]。^[atlas-core-lex.md:17-25]

`consume_directive` 在文件名前跳过空白与注释，但此处遇到换行意味着空文件名。文件名可以加引号，也可以按限定字符集裸读；裸文件名不允许斜杠，因此子目录路径必须加引号。扫描器不会消费该行剩余内容，后续校验交给会话帧，详见 [[命令首指令与文件名扫描]]。^[atlas-core-lex.md:35-36, atlas-core-lex.md:68-71]

## 逐 token 消费与错误恢复

`TokenCursor` 通过 `peek` 和 `bump` 提供单 token 前瞻，并将词法错误像 token 一样缓存，确保前瞻与消费看到同一结果。完整流接口 `tokenize` 采用全有或全无的行为；`tokenize_with_diagnostics` 则返回 `LexOutput{tokens, diagnostics}`，按遭遇顺序保留诊断，同时保留所有可恢复 token。参见 [[TokenCursor 单 Token 前瞻]]。^[atlas-core-lex.md:79-83]

注释使用可嵌套的 `{}`，未闭合时产生词法错误。字符串通过双写引号转义；遇到换行而未闭合时，扫描器报告 `"Closing string denotation."` 警告，并将恢复出的 `String` token 放入 `pending`，使解析器仍能取得该 token 和后续命令。相关细节见 [[可嵌套注释]]与[[字符串转义与未闭合恢复]]。^[atlas-core-lex.md:72-77]

不支持的字符会清空嵌套与续行抑制状态，使下一个换行能够终止命令。显式调用 `recover_command` 时，则丢弃当前物理行的剩余内容，并重置续行、嵌套和命令首状态。^[atlas-core-lex.md:63-64, atlas-core-lex.md:78-78]

## 词法、语法与会话的职责

词法器本身不做语义判定。`syntax.rs` 负责面向 LALRPOP 带源码跨度 token 流的文法适配，`session.rs` 负责逐命令消费，`session_frame.rs` 负责指令的包含与重定向语义。可结合 [[会话循环与文件会话帧的职责边界]]和[[SessionFrame 会话帧与文件包含语义]]理解这些层次。^[atlas-core-lex.md:87-89]

## 证据边界

本页来源是对 `lex.rs` 的结构性阅读，覆盖生产实现及 23 个测试；这些测试覆盖来源列出的状态机分支。该材料不声称语言验收，上游 `lexer.w` 行号属于实现方移植陈述，词法兼容性仍以 HPC 语言语料门为准，参见 [[HPC 验收证据链]]。^[atlas-core-lex.md:9-13, atlas-core-lex.md:85-91]
