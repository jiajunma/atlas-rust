# 有状态词法分析与逐命令执行

`atlas-core` 将有状态词法分析与逐命令执行相结合：Atlas 的词法分类依赖先前命令改变的状态，因此会话外层循环逐条执行命令，永不预先切分整个文件。这一约束是理解语言输入处理与会话状态关系的关键。^[atlas-core-root.md:49-50]

## 词法输入与语法适配

`lex.rs` 提供有状态词法器，支持[[可嵌套注释]]，并允许按 token 逐个消费输入；`tokenize` 则是兼容性便利接口。词法层的逐 token 消费能力与会话层的逐命令执行分别描述了输入处理的两个层次。^[atlas-core-root.md:31-31, atlas-core-root.md:49-49]

`syntax.rs` 的语法前端结合 LALRPOP 生成文法与独立适配层，后者将有状态词法流转换为带源码跨度的 token 流。相关结构可参见[[Atlas 语法前端与运算符优先级归约]]；`source.rs` 则提供自持源文本和从 1 开始的行列位置。^[atlas-core-root.md:32-32, atlas-core-root.md:48-48]

## 逐命令执行与职责划分

`session.rs` 承担有状态逐命令执行的外层循环，并拥有 `SessionEvent`，其事件包括 `Value`、`Output`、`ReportLine` 与 `ReportBytes` 等。由于先前命令可能改变后续输入的词法分类，不能将整个文件的命令划分视为独立于执行状态的预处理步骤。相关输出模型见[[SessionEvent 与字节保留输出]]。^[atlas-core-root.md:49-49]

`session_frame.rs` 承担会话帧职责，涵盖文件包含、输出重定向与顶层输出面。它与 `session.rs` 的外层执行循环形成职责划分，相关概念见[[会话循环与文件会话帧的职责边界]]和[[SessionFrame 会话帧与文件包含语义]]。^[atlas-core-root.md:49-50]

## 兼容目标与证据边界

`atlas-core` 的定位是面向兼容性的 Atlas 语言运行时，其公开模块对应可观察的语言边界，实现遵循 `docs/` 中的契约。导出的 `COMPATIBILITY_VERSION` 值为 `"atlas-language-v0"`，用于标记语言兼容契约版本，参见[[atlas-core 语言门面与兼容契约]]。^[atlas-core-root.md:9-13, atlas-core-root.md:24-25]

本页来源仅覆盖 crate 门面与模块角色地图，角色描述取自各文件头的实现方自述；它不提供 `session.rs` 或 `syntax.rs` 的内部算法证据，也不声称语言或数学验收。上游移植位置属于设计陈述，语义等值仍须以 HPC 差分门为准，参见[[HPC 验收证据链]]。^[atlas-core-root.md:9-13, atlas-core-root.md:27-29, atlas-core-root.md:55-63]
