# 有理权的公共分母表示与归一化

`RationalWeight` 以 `numerator: Vec<i64>` 和公共分母 `denominator: i64` 表示有理权，所有坐标共享同一个分母。格类型层刻意采用带检查的固定宽度存储，精确解释器值在领域边界转换；与之对应的 `RationalCoweight` 则逐坐标存储 `Rational`。^[lattice-types.md:17-25, lattice-types.md:73-79]

## 构造契约

`RationalWeight::new(numerator, denominator)` 在构造时执行 gcd 归一化，并要求分母严格为正。若 `denominator <= 0`，返回 `RepInvariantViolation { invariant: "rational weight denominator" }`。来源将这一约束与上游 `normalize` 拒绝零分母的行为作了对照。^[lattice-types.md:43-45]

`from_weight` 将整权转换为分母为 1 的有理权，`zero(rank)` 返回 `Result`。作为格类型纪律的一部分，`Weight` 与 `Coweight` 是不可互换的两个 newtype，即使所选基下的坐标表示相同，也仍须区分。^[lattice-types.md:22-25, lattice-types.md:46-47]

## 归一化时机

加减法 `add`、`sub` 均返回 `Result`；内部的 `combine` 通过交叉相乘形成公分母，再归一化结果。`scale(numerator, denominator)` 在标量乘法后归一化，其分母相关不变量标识为 `"rational weight scale denominator"`。^[lattice-types.md:46-47, lattice-types.md:56-58]

`halve` 仅将分母翻倍，刻意不执行归一化，归一化时机由调用方决定，这一约定与上游一致。`normalized` 则重新调用构造器的 gcd 归一化流程。^[lattice-types.md:51-53]

## 矩阵作用、整性检查与配对

`apply_matrix` 保持分母不变，仅对分子施加矩阵作用。`integral_coordinates` 检查各分子坐标能否被公共分母整除，将上游的 `assert(entry%denominator==0)` 转化为可检查条件，对应不变量标识 `"rational weight integrality"`。^[lattice-types.md:51-55]

`dot_coroot` 对应上游 `dot_Q`，返回已约分的 `(i64, i64)`。其秩失配错误使用 `expected: coroot.rank(), actual: self.rank()`，字段顺序与 `pair`、`combine` 的惯例相反。此外，`apply_matrix` 在矩阵行长失配时，也将 `actual` 填为 `matrix.len()`；这些诊断细节应按实际实现理解。^[lattice-types.md:59-66]

## 防御性检查与资源边界

构造器中 `i64::try_from(gcd)` 与 `checked_div` 的溢出分支在当前不变量下不可达，属于防御性检查。本文件的 `gcd_u64` 返回 `left.max(1)`，因此 `gcd(0,0)=1`；`global_kgb.rs` 的同名私有实现返回 `left`，因此 `gcd(0,0)=0`。来源指出，两者在各自调用点都因分母恒正而安全，但重复实现已出现语义漂移。^[lattice-types.md:67-71]

按输入长度新建 `Vec` 时，分配纪律要求使用 `try_reserve_exact`，并将分配失败映射为 [[StructureError 统一错误分类学|StructureError]] 中的 `AllocationFailed`；`halve`、`normalized` 与 `to_rationals` 使用裸 `clone()`，是该纪律的例外。^[lattice-types.md:35-39]
