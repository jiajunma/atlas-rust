# 有理权的公共分母表示与归一化

`RationalWeight` 使用 `numerator: Vec<i64>` 与公共分母 `denominator: i64` 表示有理权，各坐标共享同一个分母。它与 [[有理余权的逐坐标表示与 API 边界|RationalCoweight 的逐坐标有理数表示]] 不同。格类型层刻意采用带检查的固定宽度存储，精确解释器值在领域边界转换。^[lattice-types.md:17-25, lattice-types.md:75-79]

## 构造契约

`RationalWeight::new(numerator, denominator)` 在构造时执行 gcd 归一化，并要求分母严格为正。若 `denominator <= 0`，返回 `RepInvariantViolation { invariant: "rational weight denominator" }`。这一输入约束与源材料所述的上游 `normalize` 拒绝零分母有所区别。^[lattice-types.md:43-45]

`from_weight` 将整权表示为分母为 1 的有理权；`zero(rank)` 返回 `Result`。整权所属的类型体系可参见 [[权格与余权格的类型隔离]]。^[lattice-types.md:17-25, lattice-types.md:46-47]

## 归一化时机

加减法 `add`、`sub` 均返回 `Result`，内部通过 `combine` 交叉相乘形成公分母，再归一化结果。`scale(numerator, denominator)` 在标量乘法后归一化，其分母相关不变量标识为 `"rational weight scale denominator"`。^[lattice-types.md:46-47, lattice-types.md:56-58]

`halve` 仅将分母翻倍，刻意不进行归一化，将归一化时机交给调用方；这一行为与上游一致。需要重新归一化时，`normalized` 会重跑构造器的 gcd 归一化流程。^[lattice-types.md:51-53]

## 矩阵作用、整性与配对

`apply_matrix` 保持分母不变，仅对分子施加矩阵作用。`integral_coordinates` 检查各分子坐标能否被公共分母整除，把上游的整除断言转化为可检查条件，对应不变量标识 `"rational weight integrality"`。^[lattice-types.md:51-55]

`dot_coroot` 对应上游 `dot_Q`，返回已约分的 `(i64, i64)`。其秩失配错误使用 `expected: coroot.rank(), actual: self.rank()`，字段顺序与 `pair`、`combine` 的惯例相反。相关接口详见 [[有理权的矩阵作用、整性检查与余根配对]]。^[lattice-types.md:59-64]

## 实现边界

构造器中 `i64::try_from(gcd)` 与 `checked_div` 的溢出分支在当前不变量下不可达，属于防御性检查。本文件的 `gcd_u64` 返回 `left.max(1)`，因此 `gcd(0,0)=1`；`global_kgb.rs` 的同名私有实现则返回 `left`，令 `gcd(0,0)=0`。源材料指出，两者在各自调用点均因分母恒正而安全，但重复实现已出现语义差异。^[lattice-types.md:67-71]

分配纪律要求按输入长度新建 `Vec` 时使用 `try_reserve_exact`，并将分配失败映射为 `StructureError::AllocationFailed`；`halve`、`normalized` 与 `to_rationals` 中的裸 `clone()` 是例外。这一资源处理约定与 [[格坐标的固定宽度检查算术]] 共同构成格类型层的实现边界。^[lattice-types.md:22-25, lattice-types.md:35-39]
