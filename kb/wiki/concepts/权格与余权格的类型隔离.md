# 权格与余权格的类型隔离

权格与余权格的类型隔离，是指以两个独立的 Rust newtype 分别表示 character lattice $X^*$ 与 cocharacter lattice $X_*$：`Weight(Vec<i32>)` 与 `Coweight(Vec<i32>)`。两格之间存在完美配对（perfect pairing），但类型不可互换；即使所选基给出相同的坐标表示，也保留这一区别。^[lattice-types.md:17-25]

## 坐标表示与转换边界

格坐标刻意采用带检查的固定宽度存储。精确解释器值在领域边界处转换，而不改变每个根系矩阵条目的表示。类型区分与固定宽度存储共同构成该格类型层的设计约定。^[lattice-types.md:22-25]

## 配对与坐标检查

`pair(weight, coweight)` 实现规范的 character–cocharacter 配对。它先检查秩是否一致；失配时返回 `RankMismatch { expected: weight.rank(), actual: coweight.rank() }`。检查通过后，委托 `pair_coordinates` 使用带检查的 `i128` 累加，再通过 `i32::try_from` 收窄结果。^[lattice-types.md:29-31]

内部辅助函数 `pair_coordinates` 使用 `zip`，由调用方保证维度一致，避免截断。`checked_add_weights` 与 `checked_sub_weights` 在等秩坐标上执行带检查的逐项加减，并通过 `checked_mul(sign)` 拦截 `i32::MIN * -1` 一类溢出。^[lattice-types.md:32-34]

按输入长度新建 `Vec` 时，使用 `try_reserve_exact`，并将预留内存失败映射为 `StructureError::AllocationFailed`；`try_copy_coordinates` 也遵循这一错误映射。来源明确保留的例外是 `halve`、`normalized` 和 `to_rationals` 中直接调用的 `clone()`。相关错误分类可参见 [[StructureError 统一错误分类学]]。^[lattice-types.md:35-39]

## 有理权与有理余权

有理类型延续了权与余权的区分，但存储形式不同：`RationalWeight` 使用 `Vec<i64>` 分子与一个 `i64` 公共分母；`RationalCoweight` 使用逐坐标的 `Rational`。^[lattice-types.md:17-20]

`RationalWeight::new` 拒绝非正分母，并在构造时进行 gcd 归一化；非正分母触发 `RepInvariantViolation { invariant: "rational weight denominator" }`。`from_weight` 将整权转换为分母为 1 的有理权，`add`、`sub` 则交叉相乘形成公分母后再归一化。^[lattice-types.md:43-47]

归一化时机并非所有操作都相同：`halve` 只翻倍分母，刻意不归一化，由调用方决定何时调用 `normalized`；`apply_matrix` 保持分母、只作用分子。`integral_coordinates` 检查各分子坐标能否被分母整除，`dot_coroot` 返回已约分的 `(i64, i64)`。^[lattice-types.md:51-59]

`RationalCoweight::from_coordinates` 仅在 crate 内可见，公开接口为 `dimension()` 与提供精确坐标视图的 `to_rationals()`；该类型没有算术操作，也没有 `Hash`。来源注明第三方 malachite 类型不进入其公开 API，同时区分了解释器值层已公开使用 malachite 有理数这一情况。^[lattice-types.md:75-79]
