# 权格与余权格的类型隔离

权格与余权格的类型隔离，是指用独立的 Rust newtype `Weight(Vec<i32>)` 与 `Coweight(Vec<i32>)`，分别表示 character lattice \(X^*\) 与 cocharacter lattice \(X_*\)。两格之间存在完美配对（perfect pairing），但类型不可互换；即使所选基给出相同的坐标表示，也必须保留这一区别。^[lattice-types.md:17-25]

## 坐标表示与转换边界

格坐标刻意采用带检查的固定宽度存储。精确解释器值在领域边界处转换，而不改变每个根系矩阵条目的表示。类型隔离与存储宽度是这一设计中的两个约定：前者保留权与余权的区别，后者规定坐标算术及转换的边界。参见 [[格坐标的固定宽度检查算术]]。^[lattice-types.md:22-25]

## 配对与秩检查

`pair(weight, coweight)` 实现规范的 character–cocharacter 配对。它首先检查秩是否一致，失配时返回 `RankMismatch { expected: weight.rank(), actual: coweight.rank() }`；检查通过后，委托 `pair_coordinates` 使用带检查的 `i128` 累加，再通过 `i32::try_from` 收窄结果。^[lattice-types.md:29-31]

内部辅助函数 `pair_coordinates` 使用 `zip`，因此需要调用方保证维度一致，避免截断。`checked_add_weights` 与 `checked_sub_weights` 则在等秩坐标上执行带检查的逐项加减，并通过 `checked_mul(sign)` 拦截 `i32::MIN * -1` 一类溢出。^[lattice-types.md:32-34]

按输入长度新建 `Vec` 时，使用 `try_reserve_exact`，将预留内存失败映射为 `StructureError::AllocationFailed`；`try_copy_coordinates` 也采用这一映射。来源注明的例外是 `halve`、`normalized` 与 `to_rationals` 中直接调用的 `clone()`。相关错误类型见 [[StructureError 统一错误分类学]]。^[lattice-types.md:35-39]

## 有理类型中的权与余权

有理类型同样分别表示权与余权，但采用不同的存储形式：`RationalWeight` 使用 `Vec<i64>` 分子与一个 `i64` 公共分母；`RationalCoweight` 使用逐坐标的 `Rational`。^[lattice-types.md:17-20]

`RationalWeight::new` 拒绝非正分母，并在构造时进行 gcd 归一化；`from_weight` 将整权转换为分母为 1 的有理权。加减法通过交叉相乘形成公分母后再归一化，详见 [[有理权的公共分母表示与归一化]]。^[lattice-types.md:43-47]

有理权还提供矩阵作用、整性检查与余根配对：`apply_matrix` 保持分母、只作用分子；`integral_coordinates` 检查各分子坐标能否被分母整除；`dot_coroot` 返回已约分的 `(i64, i64)`。详见 [[有理权的矩阵作用整性检查与余根配对]]。^[lattice-types.md:51-59]

`dot_coroot` 的秩失配字段为 `expected: coroot.rank(), actual: self.rank()`，与 `pair`、`combine` 的惯例相反。这会交换诊断中 “expected” 与 “got” 的数值，但没有数学后果：合法调用中两侧秩均等于格秩，该错误仅作为腐败态守卫。^[lattice-types.md:63-67]

`RationalCoweight::from_coordinates` 仅在 crate 内可见；公开接口为 `dimension()` 与提供精确坐标视图的 `to_rationals()`，没有算术操作，也没有 `Hash`。来源明确区分了该类型不让第三方 malachite 类型进入公开 API 的边界，与解释器值层已公开使用 malachite 有理数的情况。详见 [[有理余权的逐坐标表示与 API 边界]]。^[lattice-types.md:76-82]
