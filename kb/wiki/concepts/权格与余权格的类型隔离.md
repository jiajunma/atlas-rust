# 权格与余权格的类型隔离

权格与余权格的类型隔离，是指用两个独立的 Rust newtype 分别表示权格（character lattice）$X^*$ 与余权格（cocharacter lattice）$X_*$：`Weight(Vec<i32>)` 与 `Coweight(Vec<i32>)`。两格之间存在完美配对，但类型不可互换；即使所选基使两者具有相同的坐标表示，也保留这一类型区别。^[lattice-types.md:17-25]

## 坐标表示与转换边界

格坐标刻意采用带检查的固定宽度存储。精确解释器值在领域边界处转换，而不改变每个根系矩阵条目的表示。这一存储策略与权、余权的类型区分共同构成格类型层的设计约束，相关算术纪律见 [[格坐标的固定宽度检查算术]]。^[lattice-types.md:22-25]

## 配对与检查责任

`pair(weight, coweight)` 实现规范的 character–cocharacter 配对。它先检查两者的秩是否一致；失配时返回 `RankMismatch { expected: weight.rank(), actual: coweight.rank() }`。检查通过后，委托 `pair_coordinates` 使用带检查的 `i128` 累加，再通过 `i32::try_from` 收窄结果。参见 [[权与余权的典范配对]]。^[lattice-types.md:29-31]

内部辅助函数 `pair_coordinates` 使用 `zip`，维度一致性由调用方保证，以避免截断。`checked_add_weights` 与 `checked_sub_weights` 则在等秩坐标上执行带检查的逐项加减，并通过 `checked_mul(sign)` 拦截 `i32::MIN * -1` 一类溢出。因此，类型区别之外，坐标运算仍有明确的维度与算术检查责任。^[lattice-types.md:32-34]

## 有理类型的表示区别

有理权与有理余权也采用不同类型，且存储形式不对称：`RationalWeight` 使用 `Vec<i64>` 分子与一个 `i64` 公共分母，`RationalCoweight` 使用逐坐标的 `Rational`。^[lattice-types.md:17-20]

`RationalWeight::new` 拒绝非正分母，并在构造时进行 gcd 归一化；`from_weight` 将整权转换为分母为 1 的有理权。`add`、`sub` 交叉相乘形成公分母后再归一化。`halve` 则只翻倍分母，刻意将归一化时机交给调用方，后者可调用 `normalized`。详见 [[有理权的公共分母表示与归一化]]。^[lattice-types.md:43-53]

`RationalCoweight` 的 `from_coordinates` 仅在 crate 内可见，公开接口为 `dimension()` 与提供精确坐标视图的 `to_rationals()`；该类型没有算术操作，也没有 `Hash`。来源注明第三方 malachite 类型不进入其公开 API，同时指出解释器值层已公开使用 malachite 有理数。详见 [[有理余权的逐坐标表示与 API 边界]]。^[lattice-types.md:75-79]
