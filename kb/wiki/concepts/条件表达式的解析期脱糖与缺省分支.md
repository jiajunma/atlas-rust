# 条件表达式的解析期脱糖与缺省分支

Atlas 语法前端使用 `Conditional` 表示条件表达式：`elif` 在解析阶段脱糖为嵌套条件表达式，缺少 `else` 时以 void 值作为缺省分支。这些规则属于语法树构造约定；`Expr` 的每个变体都带有源码跨度（span）。^[atlas-core-syntax.md:16-18, atlas-core-syntax.md:32-40]

## 解析期脱糖

`elif` 链在解析时转换为嵌套的 `Conditional`，而不是作为独立的 `elif` 节点保留。来源将这一处理明确放在解析阶段；AST 节点后续的语义判定、转换与求值由 `typed.rs` 负责。^[atlas-core-syntax.md:38-40, atlas-core-syntax.md:106-108]

语法由 LALRPOP 生成，独立适配层将有状态的 Atlas 词法流转换为解析器所需的带跨度 token 流，使词法器的上下文敏感规则不进入文法动作。相关词法背景可参见 [[Atlas 词法 Token 模型]]。^[atlas-core-syntax.md:9-14, atlas-core-syntax.md:93-96]

## 缺省分支

条件表达式缺少 `else` 时，缺省分支为 void 值；来源将该规则对应到上游 `parser.y:415`。这一约定描述的是缺失分支的值，不应据此直接断言整个条件表达式的最终类型；节点的语义判定仍在类型转换与求值层完成。^[atlas-core-syntax.md:38-40, atlas-core-syntax.md:106-108]

这一规则需要与 `IntCase` 的缺省行为区分：`IntCase` 按从 0 开始的索引选择分支，`then` 接收负索引，`else` 接收越界索引；两者都缺失时采用取模回绕。因此，`Conditional` 的缺省 void 分支不是所有分支结构共用的规则。^[atlas-core-syntax.md:47-50]

## 测试与证据边界

来源记录语法前端共有 51 个测试，覆盖表达式、命令与诊断形状，但未单独列出 `elif` 脱糖或缺省 `else` 的测试锚点。材料属于结构性阅读，不声称语言验收；文法与上游 `parser.y` 的逐条对应属于实现方移植陈述，语法兼容性仍以 HPC 语言语料门为准，可结合 [[CLI 兼容性的证据边界]] 阅读。^[atlas-core-syntax.md:9-14, atlas-core-syntax.md:104-110]
