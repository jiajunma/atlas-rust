# 构造管线的证据范围与兼容性验收

领域构造管线的证据来自对 `crates/atlas-core/src/domain_builtins.rs` 第 1628–2527 行的结构性阅读，覆盖根数据、中央商、显式根数据、内类、对偶内类及实形构造。这些记录说明实现结构、构造顺序与预算约束，不声称数学验收；构造兼容性仍以 HPC 差分门为准。^[atlas-core-domain-construction.md:9-14, atlas-core-domain-construction.md:73-75]

## 结构性阅读的覆盖范围

根数据构造记录了单连通情形使用权格基、伴随情形使用根格基，以及简单数据校验、同源类型判定和环面因子的排列约定。中央商构造覆盖中间商，显式根与余根矩阵构造保留空维矩阵的维数信息，相关概念见 [[BasedRootDatum：带基根数据与构造不变量]] 和 [[中央商与显式矩阵根数据构造]]。^[atlas-core-domain-construction.md:16-33]

内类上下文按固定顺序装配：分类、强实分类、外部形式排序、布局、对偶侧构造、展示数据，最后建立规范实形弱缓存的槽位表。记录明确标出分类预算、`FIBER_BUDGET` 与 `INTEGER_BUDGET` 的门控位置，并要求对偶侧只构造一次，详见 [[内类上下文的装配顺序与预算门]]。^[atlas-core-domain-construction.md:35-43]

内类与对偶内类的记录涵盖余权部分转置、格对合构造、从根数据对合进入内类的路径，以及对偶 datum 的余根偏好翻转和逐字母 Lie 类型对偶。等值内容的对偶 datum 经内容弱驻留共享 Weyl 身份，相关说明见 [[对偶内类与 Weyl 身份共享]]。^[atlas-core-domain-construction.md:45-54]

实形构造记录了外部形式号向内部编号的转换、非法编号错误，以及规范实形弱缓存命中时共享上下文的行为。自定义构造总是新建属主，并通过带预算的 `InvolutionTable`、基本 Cartan 和 `RealFormSeed::custom` 建立种子；上下文持有延迟初始化的 `kgb/rep` 与普通、扭曲两个形变缓存。^[atlas-core-domain-construction.md:56-65]

## 兼容性验收与快照身份

源材料将上游 C++、CWEB 的行号引用明确归类为**实现方的移植陈述**，并规定构造兼容以 HPC 差分门为准。因此，这些引用只能作为实现对应关系的陈述，不能直接作为兼容性验收结论。相关主题见 [[HPC 验收证据链]]。^[atlas-core-domain-construction.md:73-75]

快照记录给出 Git base `964f0033` 和 `domain_builtins.rs` 的 SHA-256 缩写 `e6987e7c…`，并注明其字节与已验收 after-v5 清单相同。材料同时限定：字节数与哈希只标识本快照的字节；这一身份信息不能替代构造兼容所要求的 HPC 差分门。^[atlas-core-domain-construction.md:73-75]

## 覆盖边界

该包未展开第 2657–2933 行的形变缓存机器，也将 `strong_components`、`RootNumbering`、`CenterClassifier`、`RootTable` 和 `validate/print_text` 列为待分包内容。身份机制与派发机制分别指向领域值包和派发包，本包不提供这些部分的完整说明。^[atlas-core-domain-construction.md:67-72]

实形构造部分提及 `FallibleOnce` 管理的 `kgb/rep` 和两个 `DeformationCache`，仅记录上下文的组件组成；形变缓存机器的详细机制仍在该包的覆盖范围之外。^[atlas-core-domain-construction.md:61-70]
