# 根与余根的梯子底表

根与余根的梯子底表是 `RootSystem` 在构造时全量预计算的成员集合，分别存于 `min_roots` 与 `min_coroots`。两张表使用统一的 `RootId` 索引，与根、配对余根及简单根坐标三张表对齐；根表按环境坐标字典序升序排列。^[root-system.md:18-24, root-system.md:128-129]

## 定义与索引

对每个根 \(\alpha\)，`min_roots[alpha]` 标记所有满足 \(\beta-\alpha\) 不是根的根 \(\beta\)，包含 \(\alpha\) 自身。`min_coroots[alpha]` 则在配对余根上定义相同关系，标记满足 \(\beta^\vee-\alpha^\vee\) 不是余根的对应成员。两张表分别通过 `min_roots_for` 与 `min_coroots_for` 访问。^[root-system.md:89-91]

成员集合采用 [[RootSet 只读位图集合|RootSet]]，位位置对应稳定根序，迭代按索引升序进行，构造后没有公开插入入口。`contains` 对越界索引返回 `false`，梯子底表访问器对越界 `RootId` 返回 `None`。索引对齐的背景见 [[RootId 与根系索引对齐]]。^[root-system.md:18-23, root-system.md:98-109]

## 构造与成员判定

构造时，对每对 \((\alpha,\beta)\) 分别计算根坐标差和余根坐标差，并判断其是否属于相应集合。根表已排序，成员查询使用二分查找；余根表跟随根序，本身不保证按余根坐标排序，因此先建立一次“坐标 → 下标”映射。两张表没有惰性构造选项。^[root-system.md:89-92, root-system.md:128-129]

`subtract_coordinates` 使用 `checked_sub`。若坐标差溢出，该次成员查询按 `false` 处理，使对应的 \(\beta\) 进入梯子底集合：已存坐标均为 `i32`，精确差若超出其范围，就不可能等于任何已存根或余根。分配失败等其他错误仍正常传播，参见 [[Rust ladder 成员查询的选择性溢出处理]]。^[root-system.md:93-96]

## 测试与证据边界

来源列出的测试锚点包括 B2、G2 的 oracle 梯子底成员集合，以及 A2、B2、G2 的逐对暴力对照：根差与 `combine_roots` 对照，余根差按坐标直接核查。测试还覆盖越界 `RootId(6)` 返回 `None` 和纯环面的空表。^[root-system.md:98-102]

坐标边界测试取 \(m\in\{0,2^{30}-1,2^{30},\mathrm{i32::MAX}\}\)，与两种配置组合成八组，固定验证构造不拒绝且两张底表均为全集合。代码注释称原 Atlas 接受全部十一个边界用例，而该文件实际固定八组；来源将数量差异记录为待核事项，并注明其余用例在 HPC 证据侧。^[root-system.md:93-102]

本说明依据结构性源码阅读，不构成根系层的数学验收。上游 `d_minRoots`、`d_minCoroots` 对应关系及 HPC 捕获编号仅转录自代码注释，来源未核对上游字节；本次知识维护也未执行 Atlas、Cargo、测试或 benchmark。^[root-system.md:9-14, root-system.md:89-91, root-system.md:124-125, root-system.md:135-139]
