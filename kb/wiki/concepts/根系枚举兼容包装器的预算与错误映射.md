# 根系枚举兼容包装器的预算与错误映射

`RootSystem::enumerate(datum, max_roots)` 是普通根系枚举的兼容包装器：它通过 `RootSystemBudget::complete_for` 配置预算，并保留历史根数超限错误。显式预算入口为 `enumerate_with_budget`；预算由调用方提供，不存入构造后的 `RootSystem`。^[root-system.md:18-24, root-system.md:37-38, root-system.md:50-53]

## 预算配置与检查顺序

`RootSystemBudget` 包含 `max_lattice_rank`、`max_roots`、`max_coordinate_entries` 和 `max_reflection_steps` 四项限额。兼容包装器使用 `complete_for` 将坐标条目与反射步数限额设为饱和最坏值，使运行中只有基数限额能够触发。^[root-system.md:30-31, root-system.md:50-53]

`enumerate_with_budget` 首先执行 `check_budget_consistency`，按格秩、根数、坐标条目、反射步数的固定顺序检查，全部采用严格 `>` 比较。检查之后才通过 `datum.try_clone()` 建立自有快照，再播种正负简单根并执行 BFS 反射闭包枚举。输入根数据的相关背景见 [[BasedRootDatum：带基根数据与构造不变量]]。^[root-system.md:55-62]

预算上界使用 `u128` 饱和算术，来源给出的公式为 $entry\_bound=2(r^2+2rn)+(R_{\mathrm{eff}}+1)(4n+2r)$ 与 $step\_bound=R_{\mathrm{eff}}\cdot r$。条目上界覆盖借入的 datum、自有快照、闭包 map、待处理队列以及一个在途候选；纯环面即半单秩为零时，$R_{\mathrm{eff}}=0$。^[root-system.md:71-74]

## 运行时根数限制

静态预算检查与运行时基数拒绝是两条不同路径。闭包插入时，自配对 $\langle\alpha,\alpha^\vee\rangle=2$ 的检查先于重复键检查；重复键还必须具有完全一致的余根和简单坐标，否则产生 `"coroot agreement"` 不变量错误。重复候选不计入基数；插入新根时，若 `seen.len() == max_roots`，则返回 `RootSystemResourceLimit { resource: "roots" }`。^[root-system.md:64-74]

## 兼容错误映射

包装器将 `RootSystemResourceLimit { resource: "roots" }` 转换为历史错误 `ResourceLimitExceeded { limit }`，其余错误原样传播。该转换保留了兼容入口的根数超限错误形式，同时让显式预算入口使用命名资源错误。^[root-system.md:50-53]

## 测试与证据边界

来源列出的测试锚点包括包装器的 `ResourceLimitExceeded` 映射、四种命名资源拒绝及限额边界、运行时基数拒绝，以及 `complete_for` 与包装器结果的全字段逐表比较。静态检查和运行时拒绝分别有测试锚定；包装器映射中“其他 resource 原样透传”的分支未见直接触发测试。^[root-system.md:71-74, root-system.md:114-120, root-system.md:130-131]
