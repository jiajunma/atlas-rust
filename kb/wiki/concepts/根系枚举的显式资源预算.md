# 根系枚举的显式资源预算

`RootSystem` 从 [[BasedRootDatum：带基根数据与构造不变量|BasedRootDatum]] 生成有限普通根系。枚举是调用方显式提供预算的操作，预算不保存在构造完成的 `RootSystem` 中；构造前的预算检查与运行时的新根数量限制是两条不同路径。^[root-system.md:18-24, root-system.md:71-74]

## 预算接口与检查顺序

`RootSystemBudget` 包含四项限额：`max_lattice_rank`、`max_roots`、`max_coordinate_entries` 和 `max_reflection_steps`，分别用于格秩、根数、坐标条目和反射步数。它提供 `new` 与 `complete_for` 构造方法，但没有字段读取器，也不自行校验。^[root-system.md:28-38, root-system.md:124-127]

`enumerate_with_budget` 首先执行 `check_budget_consistency`，按**格秩 → 根数 → 坐标条目 → 反射步数**的固定顺序检查，全部使用严格的 `>` 比较。检查通过后，才通过 `datum.try_clone()` 创建自有快照，以正负简单根播种，再用 BFS 构造简单反射闭包。^[root-system.md:55-62]

## 资源上界

坐标条目与反射步数上界使用 `u128` 饱和算术计算，公式为下述两式。^[root-system.md:71-74]

$$
\mathrm{entry\_bound}
=2(r^2+2rn)+(R_{\mathrm{eff}}+1)(4n+2r),
$$

$$
\mathrm{step\_bound}=R_{\mathrm{eff}}\cdot r.
$$

坐标条目上界覆盖借入的 datum、自有快照、闭包映射、待处理队列和一个在途候选。纯环面，即半单秩为零时，取 $R_{\mathrm{eff}}=0$。来源未进一步定义其余符号，此处保留原记号。^[root-system.md:71-74]

## 运行时根数限制

`Closure::insert` 在插入新根时检查基数：若 `seen.len() == max_roots`，返回 `RootSystemResourceLimit { resource: "roots" }`。重复候选不计入根数，因此达到限额并不意味着重复候选也会触发基数拒绝。^[root-system.md:64-67]

基数检查位于闭包不变量检查之后。插入首先验证自配对 $\langle\alpha,\alpha^\vee\rangle=2$，即使候选键重复也执行；随后要求重复键对应的余根与简单坐标逐字节一致，否则返回 `"coroot agreement"` 不变量错误。来源将这两道检查描述为防御性检查，已知公开 datum 构造路径不可达，测试通过直接注入私有 `Closure` 覆盖它们。^[root-system.md:64-69]

## 兼容入口与错误映射

`enumerate(datum, max_roots)` 是兼容包装器，使用 `RootSystemBudget::complete_for` 将坐标条目与反射步数限额设为饱和最坏值，使运行中只有基数限额能够触发资源拒绝。它将 `RootSystemResourceLimit { resource: "roots" }` 映射为历史错误 `ResourceLimitExceeded { limit }`，其他错误原样透传。^[root-system.md:50-53]

## 构造结果与预计算边界

成功枚举后，根按环境坐标字典序排列，顺序由闭包 `BTreeMap` 的键序决定，与 BFS 发现顺序无关。根、余根和简单坐标三张表保持索引对齐，同一 `RootId` 同时索引三张表，详见 [[RootId 与根系索引对齐]]。^[root-system.md:18-22, root-system.md:55-62]

构造还会全量预计算根与余根的梯子底表，对每对 $(\alpha,\beta)$ 执行两次坐标差计算，没有惰性选项。来源仅将这一成本作为结构性事实记录；集合含义与成员查询可参见 [[Root ladder bottom 集与固定宽度成员查询]]。^[root-system.md:87-96, root-system.md:128-129]
