# 根系枚举的显式资源预算

根系枚举通过调用方显式提供的 `RootSystemBudget` 限制资源使用。`RootSystem` 从 [[BasedRootDatum：带基根数据与构造不变量|BasedRootDatum]] 生成有限普通根系，但不保存预算；预算属于枚举操作的输入。^[root-system.md:18-24]

## 预算接口与检查顺序

`RootSystemBudget` 包含四个字段：`max_lattice_rank`、`max_roots`、`max_coordinate_entries` 和 `max_reflection_steps`，分别约束格秩、根数、坐标条目与反射步数。它提供 `new` 和 `complete_for` 构造方法，但没有字段读取器，也不自行校验。^[root-system.md:28-38, root-system.md:124-127]

`enumerate_with_budget(datum, budget)` 首先执行 `check_budget_consistency`，依次检查格秩、根数、坐标条目、反射步数，所有比较均为严格的 `>`。只有通过检查后，才调用 `datum.try_clone()` 创建自有快照，随后播种简单根及其负根并进行 BFS 反射闭包枚举。^[root-system.md:55-62]

## 资源上界

预算估算使用 `u128` 饱和算术。坐标条目上界与反射步数上界分别为：

\[
\mathrm{entry\_bound}
=2(r^2+2rn)+(R_{\mathrm{eff}}+1)(4n+2r),
\qquad
\mathrm{step\_bound}=R_{\mathrm{eff}}\cdot r.
\]

坐标条目估算覆盖借入的 datum、自有快照、闭包映射、待处理队列和一个在途候选。纯环面，即半单秩为零时，使用 \(R_{\mathrm{eff}}=0\)。来源给出了上述公式，但未在该段进一步定义其余符号。^[root-system.md:71-74]

静态预算检查与运行时根数拒绝是两条不同路径。闭包插入新根时，若 `seen.len() == max_roots`，便返回 `RootSystemResourceLimit { resource: "roots" }`；重复候选不计入根数。^[root-system.md:64-74]

## 插入检查与失败语义

资源限制不取代闭包的不变量检查。每次插入首先验证自配对 \(\langle\alpha,\alpha^\vee\rangle=2\)，重复键也须经过此检查；随后检查重复根对应的余根与简单坐标是否逐字节一致，不一致则报告 `"coroot agreement"` 不变量错误。新根的基数检查位于这些检查之后。^[root-system.md:64-69]

兼容入口 `enumerate(datum, max_roots)` 通过 `RootSystemBudget::complete_for` 将坐标条目和反射步数限额设为饱和最坏值，使运行中只有基数限额能够触发资源拒绝。它将 `RootSystemResourceLimit { resource: "roots" }` 转换为历史错误 `ResourceLimitExceeded { limit }`，其他错误原样透传。^[root-system.md:50-53]

## 枚举顺序与预计算边界

成功枚举后的根顺序由闭包 `BTreeMap` 的键序决定，按环境坐标字典序排列，与 BFS 的发现顺序无关。根、余根和简单坐标三张表保持索引对齐，可结合 [[RootId 与根系索引对齐]] 理解访问语义。^[root-system.md:18-22, root-system.md:55-62]

构造还会全量预计算梯子底表，对每对 \((\alpha,\beta)\) 计算两次坐标差，没有惰性选项。相关集合结构见 [[Root ladder bottom 集与固定宽度成员查询]]；来源仅陈述这一构造特征，不提供性能测量结论。^[root-system.md:128-129]

来源列出的测试覆盖四种命名资源拒绝及限额边界、运行时根数拒绝、兼容入口的错误映射，以及 `complete_for` 与兼容入口结果的全字段逐表比较。测试索引还包含秩 33 的动态枚举和纯环面空枚举。^[root-system.md:114-120]
