# 根系枚举的显式资源预算

根系枚举由调用方显式提供资源预算。`RootSystem` 从 [[BasedRootDatum：带基根数据与构造不变量|BasedRootDatum]] 生成有限普通根系，但不保存预算；预算属于枚举操作的输入。^[root-system.md:18-24]

## 预算接口与检查顺序

`RootSystemBudget` 包含 `max_lattice_rank`、`max_roots`、`max_coordinate_entries` 和 `max_reflection_steps`，分别限制格秩、根数、坐标条目和反射步数。它提供 `new` 与 `complete_for` 构造方法，没有字段读取器，也不自行校验。^[root-system.md:28-38, root-system.md:124-127]

`enumerate_with_budget` 首先执行 `check_budget_consistency`，按**格秩 → 根数 → 坐标条目 → 反射步数**的固定顺序检查，全部使用严格的 `>` 比较。检查通过后，才调用 `datum.try_clone()` 创建自有快照，播种正负简单根，并通过 BFS 计算简单反射闭包。^[root-system.md:55-62]

## 资源上界

预算采用 `u128` 饱和算术计算坐标条目与反射步数上界，公式如下。^[root-system.md:71-74]

\[
\mathrm{entry\_bound}
=2(r^2+2rn)+(R_{\mathrm{eff}}+1)(4n+2r),
\qquad
\mathrm{step\_bound}=R_{\mathrm{eff}}\cdot r.
\]

坐标条目上界覆盖借入的 datum、自有快照、闭包映射、待处理队列和一个在途候选。纯环面，即半单秩为零时，取 \(R_{\mathrm{eff}}=0\)。来源没有进一步定义公式中的其余符号，此处保留原记号。^[root-system.md:71-74]

## 运行时根数限制与检查优先级

静态预算检查与运行时根数拒绝是两条不同路径。闭包插入新根时，若 `seen.len() == max_roots`，便返回 `RootSystemResourceLimit { resource: "roots" }`；重复候选不计入根数。^[root-system.md:64-74]

根数限制位于闭包不变量检查之后。每次插入首先验证自配对 \(\langle\alpha,\alpha^\vee\rangle=2\)，重复键也接受此检查；随后检查重复根对应的余根与简单坐标是否逐字节一致，不一致时报 `"coroot agreement"` 不变量错误。来源将这两项检查描述为防御性检查，并记录了通过直接注入私有 `Closure` 覆盖它们的测试。^[root-system.md:64-69]

## 兼容入口与错误映射

兼容入口 `enumerate(datum, max_roots)` 使用 `RootSystemBudget::complete_for`，将坐标条目与反射步数限额设为饱和最坏值，使运行中只有基数限额能够触发资源拒绝。它将 `RootSystemResourceLimit { resource: "roots" }` 映射为历史错误 `ResourceLimitExceeded { limit }`，其他错误原样透传。^[root-system.md:50-53]

## 构造结果与预计算边界

成功枚举后，根按环境坐标字典序排列，顺序由闭包 `BTreeMap` 的键序决定，与 BFS 发现顺序无关。根、余根和简单坐标三张表保持索引对齐，参见 [[RootId 与根系索引对齐]]。^[root-system.md:18-22, root-system.md:55-62]

构造时还会全量预计算根与余根的梯子底表，对每对 \((\alpha,\beta)\) 进行两次坐标差计算，没有惰性选项。梯子底表标记差不属于相应根集或余根集的元素，其集合与成员查询语义可参见 [[Root ladder bottom 集与固定宽度成员查询]]；来源对预计算成本仅作结构性陈述。^[root-system.md:87-96, root-system.md:128-129]
