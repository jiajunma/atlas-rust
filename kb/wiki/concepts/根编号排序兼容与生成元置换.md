# 根编号排序兼容与生成元置换

根编号排序兼容用于协调 upstream 的正根编号与 Rust crate 的根编号差异。在 [[weyl-姿态定位器|Weyl 姿态定位器]] `BlockLocator` 中，根的存储编号与生成元的展示顺序分别处理；`simple_pi` 记录典范单生成元下标到排序后整单根位置的映射。^[locator.md:16-29]

## 两种根顺序

upstream 的正根 `RootNbr` 按“高度、简单坐标反字典序”排序，而 crate 的 `RootId` 按环境字典序排序。为保持 locator 的顺序兼容，所有面向 locator 的列表均按 upstream 正根序排列，使 `simple_pi` 可以直接与 oracle 比较。源码作者将此描述为有意的存储差异，并声明其不改变语义。相关概念见 [[RootNumbering 根编号与 RootNbr 顺序]]。^[locator.md:27-29]

## 从典范生成元到查询姿态

`IntegralDatumItem` 保存典范整数据的正根表、子系统单根及余根坐标缓存；`BlockLocator` 的 `int_sys` 标识该典范数据，`w` 将典范基本 alcove 的整子系统映到查询姿态，并保持整正性。典范正根表按 upstream 顺序排序后作为驻留键，命中时复用已有条目。^[locator.md:19-25, locator.md:61-62]

构造定位器时，依次计算每个典范单根的像 `w.image(alpha)`，再将这些像按 upstream 正根序排序为 `simp_int`。`simple_pi[j]` 表示第 `j` 个典范单根的像在 `simp_int` 中的位置，因此它连接的是典范生成元顺序与查询姿态下的排序位置。相关概念见 [[典范整数据驻留]] 与 [[Weyl 姿态定位器]]。^[locator.md:23-29, locator.md:63-66]

像缺失会触发 `"provenance"` 不变量违规，像不是正根会触发 `"integral image positivity"` 违规；后者是上游 `assert(is_posroot)` 的受检形式。不过，像互异的 `debug_assert_eq!` 检查仅在 debug 构建中生效。^[locator.md:63-66, locator.md:104-104]

## 相对姿态中的置换合成

`make_relative_to` 要求两个定位器具有相同的 `int_sys`，否则返回不变量错误。相对化时，`w` 右乘基姿态的逆，`simple_pi` 则与基定位器简单置换的逆右复合。若 `old` 是原置换、`inv` 是基置换的逆，更新规则为 `simple_pi[j] = old[inv[j]]`。逆置换的构造使用 `usize::MAX` 哨兵检测越界或重复像。相关概念见 [[定位器的相对姿态变换]]。^[locator.md:75-78]

测试包含手算示例 `[2,1,0] ∘ [1,2,0]^{-1} = [0,2,1]`，同时检查 Weyl 元素右乘逆的行为，以及不同 `int_sys` 的拒绝路径。这个例子明确了置换合成的方向。^[locator.md:92-93]

## 证据与使用边界

来源属于结构性源码阅读，不构成 locator 层的数学验收；其中上游行号来自代码注释，未核对上游字节。该模块还是未接线的移植，`RepTable::lookup` 尚未调用其中内容。^[locator.md:9-12, locator.md:16-19, locator.md:98-98]

测试覆盖限于 A2、B2 和 F4，可约根系、rank-0 边角及多条错误路径尚未测试。此外，`IntegralDatumTable` 不持有 `RootSystem`，跨调用换用不同根系不会报错，但结果无定义，因此驻留编号不能脱离其根系使用背景解释。^[locator.md:99-105]
