# 根论工具的整数算术与失败语义

`twisted_involution.rs`、`involution_classification.rs` 与 `root_reflection.rs` 互不调用，共享 `StructureError`，但整数算术策略并不统一：三者分别采用 checked 算术、checked／saturating／普通算术混用，以及 wrapping 算术。来源将这些差异记录为待查问题，未确定它们属于有意分层还是实现漂移。^[twisted-involution-trio.md:10-13, twisted-involution-trio.md:79-84]

## 扭对合构造：校验顺序与 checked 算术

`TwistedInvolution` 表示使 \(w\theta\) 仍为对合的 Weyl 平移，只确立根论条件 \((w\theta)^2=1\)。构造器先执行三次 datum 同一性检查，再依次执行三个秩检查，随后分别复合 weight 与 coweight 矩阵，乘法顺序为“Weyl 矩阵 × distinguished 矩阵”。最后调用 `LatticeInvolution::new` 与 `RootInvolutionData::new`；对合性拒绝由这两个构造器传播，`new` 本体没有直接构造 `InvalidInvolution` 的位置。参见 [[扭对合与 Weyl 平移]]、[[StructureError 统一错误分类学]]。^[twisted-involution-trio.md:17-29]

秩检查中，`WeylAction` 使用 `rank()`，其余对象使用 `lattice_rank()`，错误的 `actual` 字段各自报告实测值。矩阵复合函数 `compose_matrices` 则使用 i128 checked 累加，再以 `i32::try_from` 收窄；该函数也被 global_tits 等模块复用。其形状错误报告存在特殊约定：无论实际哪一行长度不规则，`RankMismatch.actual` 恒为 `right.len()`。^[twisted-involution-trio.md:22-33]

## 整对合分类：预算门与不变量错误

`classify_involution` 的执行顺序是形状检查、资源预算、对合验证、构造 \(\theta+I\)，最后调用 `classify_plus_identity`。预算门通过 `IntegerMatrix::from_i32_rows` 记账后立即释放临时矩阵，避免抬高后续 live-entry 记账；对合验证采用 i128 checked 三重循环，遇到首个不符合条件的项即短路；构造 \(\theta+I\) 时，对角元素使用 `checked_add(1)`。详见 [[整对合分类的预算门与检查顺序]]。^[twisted-involution-trio.md:44-48]

`classify_plus_identity` 由调用方负责保证对合前提，也供中心环面商在 Smith 基坐标下复用。令 \(r\) 为秩，\(p=r-\dim\ker(\theta+I)\)，其中核通过 `saturated_kernel` 计算；令 \(c\) 为 \((\theta+I)\bmod 2\) 的像秩，则 `complex = c`、`compact = p − c`、`split = r − p − c`。奇性检查采用 `entry % 2 != 0`，因此负奇数同样计入；三处 `checked_sub` 下溢均返回 `IntegerLatticeInvariantViolation`。这些计数对应 [[整对合的 compact、complex、split 因子计数]]。^[twisted-involution-trio.md:49-53]

## 纤维秩：饱和减法与普通算术

`fiber_rank` 计算 `dualPi0(−θᵀ)` 的 \(\mathbf F_2\) 维数。令 \(q=-\theta^{\mathsf T}\)，其值为 \(\dim\ker((q+I)\bmod 2)\) 减去 `plusBasis(q)` 模二后张成空间的维数，对应 `Cartan_info` 打印的纤维大小指数。参见 [[对偶分量群的 fiber rank]]。^[twisted-involution-trio.md:54-56]

这一函数的防御策略与分类函数不同：最终差值使用 `saturating_sub`，下溢时钳至零，而非返回不变量错误；`kernel_dim = rank − image.rank()` 使用普通减法。取负与加减一也采用普通 i32 算术，极端输入在 debug 模式下会发生溢出 panic，缺少相应防护。^[twisted-involution-trio.md:56-58]

## 环境根反射字：静默回绕与隐含前提

`reflection_word(rc, alpha)` 是上游 `RootDatum::reflection_word` 的唯一移植点，extended parameters 与 common block packet 生成共用这一字约定，模块注释禁止消费方另建私有副本。它计算 `to_dominant(reflection(α, 2ρ))`，再按上游约定将返回字反转一次。贪心循环每轮从生成元 0 开始扫描，选择首个负配对进行反射，随后重新扫描；没有迭代上限，终止性依赖数学性质。^[twisted-involution-trio.md:68-73]

`wrapping_dot` 与 `add_scaled` 全程采用 wrapping i32 算术，溢出时静默回绕，没有错误返回路径。长度一致性仅由 `debug_assert_eq!` 检查，release 模式下按 `zip` 截断。^[twisted-involution-trio.md:73-75]

## 测试与证据边界

扭对合模块的四个测试覆盖 A1 反射平移、A2 阶三元素被拒、同秩不同 datum 被拒，以及带中心环面的 distinguished 复合。分类模块的六个测试覆盖恒等与 A2 反对合分类、奇偶差异、非对合拒绝、不规则形状拒绝及秩预算错误；来源将形状拒绝与预算错误用例分别作为形状检查优先、预算门先于对合验证的锚点。^[twisted-involution-trio.md:35-37, twisted-involution-trio.md:60-64]

`fiber_rank` 整体没有测试，`compose_matrices` 缺少直接测试，`reflection_word` 全函数也属于未测路径。来源材料经过维护者逐条源码核对，但仅属于结构性阅读，不声称数学验收；上游位置引用转录自代码注释，本次知识维护没有执行 Atlas、Cargo、测试或 benchmark。^[twisted-involution-trio.md:9-13, twisted-involution-trio.md:83-84, twisted-involution-trio.md:88-92]
