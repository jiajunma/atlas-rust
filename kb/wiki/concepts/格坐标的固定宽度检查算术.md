# 格坐标的固定宽度检查算术

格坐标层刻意采用受检（checked）的固定宽度存储：`Weight(Vec<i32>)` 表示特征格 $X^*$ 的元素，`Coweight(Vec<i32>)` 表示余特征格 $X_*$ 的元素。精确解释器值在领域边界处转换，而不改变每个根系矩阵条目的表示。两个类型是独立的 newtype；两格虽有完美配对，即使所选基下坐标相同，也不可互换，参见 [[权格与余权格的类型隔离]]。^[lattice-types.md:17-25]

## 配对与逐坐标运算

`pair(weight, coweight)` 先检查双方秩是否一致，失配时返回 `RankMismatch { expected: weight.rank(), actual: coweight.rank() }`。检查通过后，委托 `pair_coordinates` 使用 `i128` 受检累加，再通过 `i32::try_from` 检查结果能否收窄为 `i32`。内部辅助函数 `pair_coordinates` 使用 `zip`，长度一致须由调用方保证，以避免截断。^[lattice-types.md:29-32]

`checked_add_weights` 与 `checked_sub_weights` 对等秩权向量执行受检的逐坐标加减。其中符号乘法使用 `checked_mul(sign)`，能够拦截 `i32::MIN * -1` 这类溢出情形。^[lattice-types.md:33-34]

## 有理权的固定宽度表示

`RationalWeight` 使用 `Vec<i64>` 分子和 `i64` 公共分母。构造器 `new` 要求分母严格为正，并执行 gcd 归一化；非正分母返回 `RepInvariantViolation { invariant: "rational weight denominator" }`。`from_weight` 将整权转换为分母为 1 的有理权；`zero(rank)`、`add` 和 `sub` 返回 `Result`，其中加减通过 `combine` 交叉相乘取得公共分母，再归一化。详见 [[有理权的公共分母表示与归一化]]。^[lattice-types.md:17-20, lattice-types.md:43-47]

归一化时机由操作约定决定：`apply_matrix` 保持分母、只作用于分子；`halve` 只翻倍分母，刻意不归一化；`normalized` 重新执行构造器的 gcd 归一化；`scale` 在标量乘法后归一化。`integral_coordinates` 将上游逐项整除断言转化为可检查的整性条件，`dot_coroot` 返回已约分的 `(i64, i64)`，参见 [[有理权的矩阵作用整性检查与余根配对]]。^[lattice-types.md:51-59]

`RationalCoweight` 则使用逐坐标的 `Vec<Rational>`，没有采用有理权的公共分母表示。其构造入口 `from_coordinates` 为 `pub(crate)`，公开 API 提供 `dimension()` 与精确坐标视图 `to_rationals()`；该类型不提供算术操作或 `Hash`。详见 [[有理余权的逐坐标表示与 API 边界]]。^[lattice-types.md:76-82]

## 分配与错误边界

按输入长度新建 `Vec` 的路径使用 `try_reserve_exact`，将预留失败映射为 `StructureError::AllocationFailed`；`try_copy_coordinates` 也采用这一错误映射。来源明确记录的例外是 `halve`、`normalized` 和 `to_rationals` 中的裸 `clone()`，因此可失败预留并未覆盖这些复制操作。相关错误体系见 [[StructureError 统一错误分类学]]。^[lattice-types.md:35-39]

秩失配诊断存在字段顺序差异：`dot_coroot` 使用 `expected: coroot.rank(), actual: self.rank()`，与 `pair`、`combine` 的惯例相反。这会互换 `expected {expected}, got {actual}` 中的两个值，但没有数学后果；合法调用点两侧秩都等于格秩，该错误仅作为腐败态守卫。另一个诊断细节是，`apply_matrix` 在矩阵行长失配时也将 `actual` 填为 `matrix.len()`。^[lattice-types.md:63-69]

构造器中的 `i64::try_from(gcd)` 与 `checked_div` 属于防御性检查，在当前不变量下相应溢出出口不可达。本文件的 `gcd_u64` 返回 `left.max(1)`，因此 `gcd(0,0)=1`；`global_kgb.rs` 中同名私有副本返回 `left`，因此 `gcd(0,0)=0`。两处调用点的分母恒正，所以各自使用均安全，但重复实现已出现语义漂移。^[lattice-types.md:70-74]
