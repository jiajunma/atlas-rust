# 格坐标的固定宽度检查算术

格坐标层刻意采用带检查的固定宽度存储：`Weight(Vec<i32>)` 表示特征格 $X^*$ 的元素，`Coweight(Vec<i32>)` 表示余特征格 $X_*$ 的元素。精确解释器值在领域边界处转换，而不改变每个根系矩阵条目的表示。两者是独立的 newtype；即使坐标表示相同，也不能互换，参见 [[权格与余权格的类型隔离]]。^[lattice-types.md:17-25]

## 配对与逐坐标运算

`pair(weight, coweight)` 计算[[权与余权的典范配对]]，先检查秩是否一致，失配时返回 `RankMismatch { expected: weight.rank(), actual: coweight.rank() }`。检查通过后，内部函数 `pair_coordinates` 使用 `i128` 检查式累加，再通过 `i32::try_from` 检查结果能否收窄为 `i32`。内部函数使用 `zip`，坐标长度一致的前提由调用方保证，以避免截断。^[lattice-types.md:29-32]

`checked_add_weights` 与 `checked_sub_weights` 对等秩权向量执行逐坐标检查式加减。符号乘法使用 `checked_mul(sign)`，会拦截 `i32::MIN * -1` 这类溢出情形。^[lattice-types.md:33-34]

## 有理权的固定宽度表示

`RationalWeight` 使用 `Vec<i64>` 分子与 `i64` 公共分母。构造器 `new` 要求分母严格为正，并执行 gcd 归一化；非正分母产生 `RepInvariantViolation { invariant: "rational weight denominator" }`。`from_weight` 将整权转换为分母为 1 的有理权；`zero(rank)`、`add` 和 `sub` 返回 `Result`，其中加减通过 `combine` 交叉相乘取得公共分母，再归一化。参见 [[有理权的公共分母表示与归一化]]。^[lattice-types.md:17-20, lattice-types.md:43-47]

不同操作具有不同的归一化时机：`apply_matrix` 只作用于分子并保持分母；`halve` 只将分母翻倍，刻意不归一化；`normalized` 重新执行构造器的 gcd 归一化；`scale` 在标量乘法后归一化。`integral_coordinates` 将上游逐项整除断言转化为可检查的整性条件，`dot_coroot` 返回已约分的 `(i64, i64)`。^[lattice-types.md:51-59]

有理余权采用不同表示：`RationalCoweight` 保存逐坐标的 `Rational`，公开提供 `dimension()` 与 `to_rationals()`，不提供算术操作或 `Hash`。其接口边界见 [[有理余权的逐坐标表示与 API 边界]]。^[lattice-types.md:73-79]

## 分配与错误边界

按输入长度新建向量的路径使用 `try_reserve_exact`，并将预留失败映射为 `StructureError::AllocationFailed`；`try_copy_coordinates` 也遵循这一错误映射。来源明确记录的例外是 `halve`、`normalized` 和 `to_rationals` 中的裸 `clone()`。相关错误类型参见 [[StructureError 统一错误分类学]]。^[lattice-types.md:35-39]

诊断字段保留了实现上的差异：`dot_coroot` 的秩失配使用 `expected: coroot.rank(), actual: self.rank()`，与 `pair`、`combine` 的惯例相反；`apply_matrix` 在矩阵行长失配时，也将 `actual` 填为 `matrix.len()`。^[lattice-types.md:63-66]

构造器中的 `i64::try_from(gcd)` 与 `checked_div` 属于防御性溢出检查，在当前不变量下相应失败出口不可达。本文件的 `gcd_u64` 返回 `left.max(1)`，因此 `gcd(0,0)=1`；`global_kgb.rs` 中同名私有实现则返回 0。由于各自调用点的分母恒正，两种实现目前均安全，但重复实现已存在语义差异。^[lattice-types.md:67-71]
