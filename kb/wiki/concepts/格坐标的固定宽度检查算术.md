# 格坐标的固定宽度检查算术

格坐标层刻意采用带检查的固定宽度存储：`Weight(Vec<i32>)` 表示特征格 $X^*$ 中的元素，`Coweight(Vec<i32>)` 表示余特征格 $X_*$ 中的元素。精确解释器值在领域边界处转换，而不改变每个根系矩阵条目的表示。两个类型以独立 newtype 区分；即使所选基下坐标相同，两格之间存在完美配对也不意味着它们可以互换。^[lattice-types.md:17-25]

## 配对与整数坐标运算

`pair(weight, coweight)` 计算典范的特征—余特征配对。它先检查秩是否相同，失配时返回 `RankMismatch { expected: weight.rank(), actual: coweight.rank() }`；检查通过后，委托 `pair_coordinates` 使用 `i128` 检查式累加，再通过 `i32::try_from` 检查结果能否收窄为 `i32`。内部辅助函数 `pair_coordinates` 使用 `zip`，因此调用方必须保证坐标长度一致，避免截断。^[lattice-types.md:29-32]

`checked_add_weights` 与 `checked_sub_weights` 对等秩权向量逐坐标执行检查式加减。符号乘法也经过 `checked_mul(sign)`，因此会拦截 `i32::MIN * -1` 这类溢出情形。^[lattice-types.md:33-34]

## 有理权的表示与归一化

`RationalWeight` 使用 `Vec<i64>` 分子与 `i64` 公共分母。构造器 `new` 要求分母严格为正，并执行 gcd 归一化；非正分母产生 `RepInvariantViolation { invariant: "rational weight denominator" }`。`from_weight` 将整权转换为分母为 1 的有理权；`zero(rank)`、`add` 和 `sub` 返回 `Result`，其中加减通过 `combine` 交叉相乘构造公共分母，再归一化。^[lattice-types.md:17-20, lattice-types.md:43-47]

各操作保留不同的归一化时机：`apply_matrix` 只作用于分子并保持分母；`halve` 只将分母翻倍，刻意不归一化，由调用方决定何时调用 `normalized`；`scale` 在标量乘法后归一化。`integral_coordinates` 将上游逐项整除断言转化为可检查的整性条件，`dot_coroot` 则返回已约分的 `(i64, i64)`。^[lattice-types.md:51-59]

`RationalCoweight` 采用逐坐标 `Rational` 表示，与有理权的公共分母表示不同。它提供维数查询与精确坐标视图，但不提供算术操作或 `Hash`，因此不能将 `RationalWeight` 的运算接口直接套用于有理余权。^[lattice-types.md:73-79]

## 分配与错误边界

除整数运算检查外，格坐标层也检查按输入长度创建向量的分配请求：这些路径使用 `try_reserve_exact`，并将预留失败映射为 `StructureError::AllocationFailed`；`try_copy_coordinates` 同样遵循这一约定。记录中的例外是 `halve`、`normalized` 和 `to_rationals` 使用裸 `clone()`。相关错误分类可参见 [[StructureError 统一错误分类学]]。^[lattice-types.md:35-39]

错误字段存在需要保留的实现细节：`dot_coroot` 的秩失配使用 `expected: coroot.rank(), actual: self.rank()`，与 `pair`、`combine` 的惯例相反；`apply_matrix` 在矩阵行长失配时也将 `actual` 填为 `matrix.len()`。这些字段不能统一解释为相同的参数顺序或失配维度。^[lattice-types.md:63-66]

构造器中的 `i64::try_from(gcd)` 与 `checked_div` 保留了防御性溢出检查，但在当前不变量下相应失败出口不可达。本文件的 `gcd_u64` 规定 `gcd(0,0)=1`，而 `global_kgb.rs` 中同名私有实现返回 0；由于各自调用点的分母恒正，两种实现目前均安全，但重复实现已出现语义差异。^[lattice-types.md:67-71]
