# 模二线性代数的测试锚点与验收边界

`mod_two.rs` 是服务 Cartan 纤维结构层的动态 $\mathbb{F}_2$ 线性代数实现。来源记录了 12 个测试，涉及位打包边界、子空间消元、商代表、子商坐标与典范截面。这些记录来自结构性源码阅读；来源未执行构建、测试或原版运行，不包含数学验收、性能或并行结论。^[mod-two.md:9-13, mod-two.md:85-93, mod-two.md:103-108]

## 动态维数与位打包边界

测试覆盖 130 维动态子空间、零维、跨字边界、重复下标抵消及跨多字的依赖消元。130 维用例超越 Atlas 打包秩上限，体现了 [[F₂ 上的位打包向量（ModTwoVector）]] 的动态表示范围。`from_ones` 按下标逐次 toggle；测试输入 `[0,63,64,127,128,63]` 中，位 63 因出现两次而为 `false`。^[mod-two.md:24-25, mod-two.md:85-89]

资源边界测试包含 `usize::MAX` 输入的溢出或分配拒绝，不做不可失败分配。不过，多数 `ArithmeticOverflow` 与 `AllocationFailed` 分支仍未覆盖。^[mod-two.md:88-91]

## 子空间与子商不变量

子空间测试覆盖依赖检测、维数不匹配、确定性商代表与陪集判定，并在插入后直接读取私有 `pivots`，断言 RREF 不变量保持。对应实现以最低置位作为主元：先约化输入，再从旧行中消去新主元，使基保持与插入顺序无关的典范 RREF，详见 [[最低主元索引的典范 RREF 子空间]]。^[mod-two.md:32-40, mod-two.md:85-87]

测试还覆盖右核计算与 [[F₂ 子商的低主元坐标（ModTwoSubquotient）|子商低主元坐标]]。右核实现为每个自由坐标生成向量并插入新子空间；子商坐标按补基最低置位读写。`ModTwoSubquotient` 刻意保持 crate 私有，其坐标用于当前 Cartan-fiber 结构层；公开 API 是数学意义上的 `CartanFiber` 包装，而非序列化格式。^[mod-two.md:44-49, mod-two.md:64-74, mod-two.md:87-89]

## 典范截面的穷举锚点

[[保留首批独立列的典范截面（CanonicalModTwoSection）]] 保留首批独立输入列并丢弃依赖列，即使依赖列的源标记在增广空间中独立，也不会保留。`solve(target)` 在目标属于保留列张成空间时返回 `Some(掩码)`，否则返回 `None`。穷举测试遍历全部 $2^{12}$ 个 $3\times4$ 映射及每个映射的 8 个目标，锚定这一范围内有解时返回数值最小源掩码的确定性行为。^[mod-two.md:53-60]

源坐标打包进 `u64` 掩码，超过 64 列时报 `ResourceLimitExceeded { limit: 64 }`，目标向量仍为动态表示。测试分别覆盖 64 列通过、65 列拒绝，以及 130 维动态目标。^[mod-two.md:55-60, mod-two.md:88-89]

## 未覆盖的错误与映射下降路径

除多数算术溢出和分配失败分支外，来源明确列出的覆盖缺口还包括五处 `ModTwoSubquotientInvariantViolation`、`NotInModTwoSubspace`，以及 `CartanFiberMapDoesNotDescend` 的 `"numerator"` 和 `"denominator"` 两种 relation 值。`dot` 无文件内直接测试，`validate_induced_map_to` 在文件内无调用方；这两项描述均限定于该文件。^[mod-two.md:89-93]

`validate_induced_map_to` 要求源分子每个基向量的像属于目标分子，源分母每个基向量的像属于目标分母。源码注释说明，仅检查商基代表可能掩盖源分母向量在目标商中具有非零类的问题，使正规形选择“看似”定义了映射。这是上述两种映射下降错误对应的校验条件。^[mod-two.md:75-79]
