# 求值帧链的共享尾部与词法寻址

求值帧链是 `crates/atlas-core/src/frames.rs` 中类型化管线 phase B 的求值环境。它以堆上的 `Rc` 链连接局部绑定帧，使闭包能够捕获并共享链尾；局部变量则通过分析期确定的 `(depth, offset)` 定位。^[atlas-core-frames.md:9-14, atlas-core-frames.md:18-22]

## 帧结构与词法寻址

每个 `Frame` 包含指向外层帧的 `next: Option<Rc<Frame>>`，以及由 `RefCell` 管理的槽向量。槽的类型是 `Option<SharedValue>`，其中 `SharedValue = Rc<Value>`；`None` 表示已声明但未初始化，也可以是 `take_local` 搬出值后留下的状态。^[atlas-core-frames.md:18-26]

局部地址 `(depth, offset)` 在分析期固定，`frame_at` 从当前链头逐跳寻找目标帧。**空绑定层不分配帧**，分析器计算深度时也跳过这些层，因此深度计数必须与实际帧链一致。每个实际存在的帧至少有一个槽，`with_frame_traced` 以 `debug_assert!(!slots.is_empty())` 检查这一约束。^[atlas-core-frames.md:21-26]

## 闭包捕获与共享尾部

`capture()` 通过克隆当前链头的 `Rc` 捕获环境，使被捕获的链在帧弹出后继续存活。调用闭包时，`with_context(captured, body)` 将当前上下文整体替换为捕获的链，并在返回时恢复调用方的链。^[atlas-core-frames.md:36-45]

共享尾部保留的是可共享修改的帧。来源中的单元测试覆盖了捕获链在弹出后仍然存活，并验证经上下文切换将槽写入 `9` 后，另一个持有者能够看到该值。这是 shared-tail 语义的测试锚点。^[atlas-core-frames.md:68-71]

## 借用纪律与槽操作

帧链的借用纪律要求：读取时在短借用内克隆共享值；写入时先完成右侧表达式求值，再取得短借用；任何借用都不跨嵌套求值持有。Rust 实现通过 `Result` 路由控制流，并在作用域函数中恢复上下文，对应上游依赖 C++ RAII 的异常恢复方式。^[atlas-core-frames.md:28-32]

`local`、`set_local` 与 `take_local` 分别提供读取、写入和移出操作。`take_local` 将值搬出并留下未初始化槽，是上游 pilfering local identifier 的安全 Rust 对应物，与类型化求值的饥饿目的地取值配合使用；相关说明见 [[局部槽的移出与未初始化状态]]。^[atlas-core-frames.md:46-48]

## 作用域退出与回溯

`with_frame(slots, body)` 压入新帧执行 `body`，并在**每一个非 panic 出口**恢复旧链，包括通过 `?` 传播的 break、return 和运行时错误。该恢复保证的明确边界是非 panic 控制流。^[atlas-core-frames.md:38-39]

`with_frame_traced` 还向调用方提供被压入的帧，供错误沿调用栈展开时转储局部槽。`slot_snapshot` 在展开之后才进行短借用读取，因此出错前重新赋值的槽会显示当前值；参见 [[回溯局部槽快照的展开后读取]]。^[atlas-core-frames.md:40-43]

## 测试与证据边界

来源列出的相关单元测试覆盖深度走链读写、坏 offset 与不存在的深度、捕获链的存活与共享突变、`?` 传播错误时两层帧的恢复，以及 `take_local` 后槽留空并可再次赋值。^[atlas-core-frames.md:66-71]

这些说明来自当前工作区字节的结构性阅读，不代表语言验收。来源中的上游 CWEB 行号转述自源码注释，未独立重读上游；帧链行为的兼容性仍以 HPC 语料门为权威，参见 [[HPC 验收证据链]]。^[atlas-core-frames.md:9-14, atlas-core-frames.md:73-77]
