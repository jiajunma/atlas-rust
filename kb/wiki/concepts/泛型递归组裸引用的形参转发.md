# 泛型递归组裸引用的形参转发

泛型递归组裸引用的形参转发由 `typed/type_groups.rs` 中的 `forward_formals` 实现：符合条件的组内裸类型名会被改写为携带所在组全部形参的类型应用。例如，`MathGenericList` 会变为 `MathGenericList<A>`，而不是作为无参构造器调用处理。^[atlas-core-type-groups.md:36-43]

## 触发条件与重写规则

转发要求表达式为 `Named`、`arity ≠ 0`，且名字查表所得编号属于正在定义的局部名集合 `locals`。满足条件时，表达式被重写为 `Applied`，参数依次为索引位于 `0..arity` 的 `Variable { index }`，从而转发所在组的全部形参。^[atlas-core-type-groups.md:38-43]

`forward_formals` 会递归处理 `Row`、`Function`、`Tuple`、`Union` 和 `Applied` 的子表达式，其他叶节点保持不变。^[atlas-core-type-groups.md:44-44]

## 验证与解析顺序

组内名解析发生在递归图构造之前。`resolve_spec` 采用两遍结构：第一遍进行广度优先验证；第二遍 `resolve` 克隆表达式，先执行 `forward_formals`，再执行 `resolve_in`，并将 `resolve_in` 的错误种类改写为 `Program`。^[atlas-core-type-groups.md:9-13, atlas-core-type-groups.md:17-32]

验证以别名的右侧表达式或 struct/union 的各字段类型为根。处理 `Function` 时，结果类型先于参数类型入队；处理 `Applied` 时，先将参数入队，再校验应用本身，因此应用本身的校验先于其参数的校验。^[atlas-core-type-groups.md:19-22]

### 裸引用与显式类型实参

验证阶段将 `Named` 视为 `supplied=0` 的非显式应用，而 `Applied` 表示显式携带参数。正在定义的局部名永不接受显式参数，即使实参数量恰好等于 arity，也会报告 `Type '{name}' being defined cannot be given type arguments`。裸引用的形参转发则在第二遍内部重写中完成。^[atlas-core-type-groups.md:23-32, atlas-core-type-groups.md:38-43]

非局部名字按类型构造器的 arity 检查参数数量，不匹配时报告 `Type constructor '{name}' called with {supplied} type arguments, expected {expected}`；查表失败则报告 `Identifier '{name}' does not refer to any type`。这些验证诊断均属于 `Program` 类。^[atlas-core-type-groups.md:23-30]
