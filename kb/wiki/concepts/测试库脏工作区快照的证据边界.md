# 测试库脏工作区快照的证据边界

测试库脏工作区快照记录取证时实际读取的文件状态，包括未提交修改与未跟踪文件。它可以支持目录结构、schema 和覆盖清单的说明，但不能将这些字节表述为已提交内容，也不构成数学验收。`tests-math-library.md` 明确将本次工作限定为结构性阅读，并关联快照 `snapshots/2026-10-10-tests-math-library.json`。^[tests-math-library.md:9-18]

## 快照中的工作区状态

取证时，`tests/math/catalog.json`、`tests/math/generics/catalog.json` 与 `tests/math/README.md` 存在 owner 未提交修改，`tests/math/rank6/catalog.json` 尚未被跟踪。`generics/` 目录还包含若干未跟踪新文件。因此，材料描述的是这一取证窗口中的脏工作区结构，而非某个已提交版本的完整测试库状态。^[tests-math-library.md:12-18, tests-math-library.md:50-56, tests-math-library.md:69-77]

版本钉定也有独立的时间含义：`baseline.json` 记录 oracle pin `7e1b958c`，Rust 侧的 `05625c5d` 则是基准建立时保存的 main 分支历史基线，不是当前 HEAD。解读快照时应保留这一差别，相关概念见 [[双仓库基准版本钉定]]。^[tests-math-library.md:35-37]

## 清单数量不等于正确性

目录统计与用例登记反映不同层面的覆盖规模。例如，`generics/catalog.json` 登记 273 个用例，而目录中有 363 个 `.atlas` 源文件及 52 个 `.oracle.*` 金标；`tests/fixtures/` 则有 353 个 `.atlas` 和 1 个 `.at` 文件。可执行三元组 fixture/event/meta 的精确计数及路径敏感清单，以 HANDOFF 的冻结迁移清单为准。^[tests-math-library.md:50-56, tests-math-library.md:79-87]

README 自述的 405 个 Atlas 输入、32 个目录和 798 条 pre-index HPC JSON 记录同样只是覆盖清单，不能解释为正确率或通过比例。[[数学测试目录的参数化覆盖清单]] 所描述的库规模，与数学验收状态必须分别读取。^[tests-math-library.md:91-97]

## 期望载体与 oracle 来源

渐进秩测试使用两类期望载体：`.expect.json` 保存结构化断言，`.oracle.stdout` 保存原版逐字节流。语言探针中的 fixture 通过 `include_str!` 内嵌，并与 `.oracle.*` 逐字节比较；金标必须来自原版完整流，不能由 Rust 输出充当。^[tests-math-library.md:50-67]

原版可执行文件是语言 oracle，捕获须使用新鲜进程，完整流应包含拒绝与恢复标记。这一来源纪律是 [[基于原版金标的差分回归]] 的证据前提；目录中存在金标文件这一事实，本身不提供某次比较通过的结论。^[tests-math-library.md:91-94]

## 验收账本与记录优先级

`tests/reference/` 保存 oracle 元数据与 HPC 证据。其中，`tests/reference/hpc/math_acceptance_index_2026_10_01.json` 是仅追加的验收账本种子：每条验收追加哈希链记录，绑定确切源码、报告、独立审查、选用例 ID、断言及限制。每个已发布后缀必须具有永久前缀检查点，否则仍属草稿；相关概念见 [[HPC 验收证据链]]。^[tests-math-library.md:79-87]

owner 的 README 是逐弧线运行日志，其自述规则为“最新的 HANDOFF/回执优先于旧记录”。源包不复制账本内容，验收状态以账本与 HANDOFF 为准，不能从结构性快照或旧运行记录推定当前验收结论。^[tests-math-library.md:16-18, tests-math-library.md:95-97]

checker 自检失败、标签错配等 harness 失败，不是数学失败，也不能充当数学证据；不可变失败阶段须保留冻结。对测试库快照的解读应保留这种失败分类，避免把测试基础设施状态转述为数学结论。^[tests-math-library.md:95-97]
