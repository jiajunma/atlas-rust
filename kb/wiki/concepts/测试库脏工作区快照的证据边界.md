# 测试库脏工作区快照的证据边界

测试库脏工作区快照记录取证时实际读取的文件字节，包括未提交修改与未跟踪文件。本次材料覆盖 `tests/math/`、`tests/fixtures/` 与 `tests/reference/` 的目录结构、JSON schema 和证据纪律，关联快照 `snapshots/2026-10-10-tests-math-library.json`。其性质是**结构性阅读**，不代表相关字节已提交，也不声称数学验收。^[tests-math-library.md:9-18]

## 工作区状态与版本含义

取证时，`tests/math/catalog.json`、`tests/math/generics/catalog.json` 和 `tests/math/README.md` 存在 owner 未提交修改，`tests/math/rank6/catalog.json` 尚未被跟踪。`generics/` 目录另有未提交修改与若干未跟踪新文件。因此，快照描述的是该取证窗口中的工作区结构，不能将其表述为已提交版本的内容。^[tests-math-library.md:12-18, tests-math-library.md:50-56, tests-math-library.md:69-77]

`baseline.json` 中的版本记录具有不同含义：oracle pin 为 `7e1b958c`；Rust 侧的 `05625c5d` 是基准建立时保存的 main 分支历史基线，并非当前 HEAD。^[tests-math-library.md:35-37]

## 清单规模不等于正确性

目录文件数、登记用例数与可执行三元组计数是不同口径。`generics/catalog.json` 登记 273 个用例，目录中则有 363 个 `.atlas` 源文件和 52 个 `.oracle.*` 金标；`tests/fixtures/` 有 353 个 `.atlas` 与 1 个 `.at` 文件。fixture/event/meta 可执行三元组的精确计数及路径敏感清单，以 HANDOFF 的冻结迁移清单为准。^[tests-math-library.md:50-56, tests-math-library.md:79-87]

README 自述的 405 个 Atlas 输入、32 个目录和 798 条 pre-index HPC JSON 记录同样属于覆盖清单，不是正确性百分比。相关结构可参见 [[数学测试目录的参数化覆盖清单]]；这些数量本身不构成数学验收结论。^[tests-math-library.md:16-18, tests-math-library.md:91-97]

## 期望载体与 oracle 来源

渐进秩测试区分两种期望载体：`.expect.json` 保存结构化断言，`.oracle.stdout` 保存原版逐字节流。语言探针 fixture 通过 `include_str!` 内嵌，与 `.oracle.*` 逐字节比较；金标只能来自原版完整流，不能由 Rust 输出充当。^[tests-math-library.md:50-67]

原版可执行文件是语言 oracle，金标须在新鲜进程中捕获，完整流包括拒绝与恢复标记。这是 [[基于原版金标的差分回归]] 的来源纪律。^[tests-math-library.md:91-92]

## 验收账本与记录优先级

`tests/reference/` 保存 oracle 元数据与 HPC 证据。其中，`tests/reference/hpc/math_acceptance_index_2026_10_01.json` 是仅追加的验收账本种子：每条验收追加哈希链记录，绑定确切源码、报告、独立审查、选用例 ID、断言及限制。每个已发布后缀必须具有永久前缀检查点，否则仍属草稿，参见 [[数学验收账本的哈希链与永久前缀检查点]] 与 [[HPC 验收证据链]]。^[tests-math-library.md:79-87]

owner 的 README 是逐弧线运行日志，其自述规则为“最新的 HANDOFF/回执优先于旧记录”。本源包不复制账本内容，验收状态以账本与 HANDOFF 为准；结构性阅读本身不提供数学验收结论。^[tests-math-library.md:16-18, tests-math-library.md:95-97]

checker 自检失败、标签错配等 harness 失败，不是数学失败，也不能充当数学证据；不可变失败阶段须保留冻结。解读快照时应保留这一失败分类。^[tests-math-library.md:95-97]
