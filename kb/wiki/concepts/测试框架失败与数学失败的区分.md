# 测试框架失败与数学失败的区分

测试框架（harness）失败与数学失败必须分别判断。检查器自检失败、标签错配等属于测试框架失败，不能据此认定数学失败，也不能将其充当数学证据；不可变的失败阶段应保留冻结。^[tests-math-library.md:89-96]

## 失败分类与证据保留

来源明确将 checker 自检、标签错配列为框架失败的例子，并要求保留冻结的失败阶段。解释这类记录时，应保留其框架故障性质，避免将其改述为数学断言不成立或数学验证结果。^[tests-math-library.md:95-96]

数学验收状态以正式账本与 HANDOFF 为准，来源包不复制账本内容。README 是逐弧线的运行日志，其自述规则为“最新的 HANDOFF/回执优先于旧记录”，因此旧日志不能单独代表当前验收状态。^[tests-math-library.md:16-18, tests-math-library.md:97-97]

## 数学验收所需的证据链

`tests/reference/` 保存 oracle 元数据与 HPC 证据，其中 `tests/reference/hpc/math_acceptance_index_2026_10_01.json` 是只追加的验收账本种子。每条验收追加哈希链记录，绑定确切源码、报告、独立审查、选用例 ID、断言与限制。每个已发布后缀必须具有永久前缀检查点，否则仍是草稿；相关概念见 [[HPC 验收证据链]]。^[tests-math-library.md:79-87]

语言行为的 oracle 是原版可执行文件。金标必须在新鲜进程中捕获原版完整流，包括拒绝与恢复标记，不能由 Rust 输出生成。语言探针通过 `include_str!` 内嵌 fixture，并与 `.oracle.*` 金标逐字节比较，参见 [[基于原版金标的差分回归]]。^[tests-math-library.md:50-56, tests-math-library.md:91-92]

期望结果也有不同载体：渐进秩门中的 `.expect.json` 表达结构化断言，`.oracle.stdout` 保存原版逐字节流。阅读失败记录时，应明确对应的是哪一种期望载体及其检查内容。^[tests-math-library.md:58-67]

## 清单规模与阅读状态的边界

测试数量是覆盖清单，不是正确性百分比。README 所列的 405 个 Atlas 输入、32 个目录和 798 条 pre-index HPC JSON 记录，不能作为数学正确率的依据；目录组织可结合 [[数学测试目录的参数化覆盖清单]] 阅读。^[tests-math-library.md:93-94]

本来源仅完成结构性阅读，不声称数学验收。取证时部分 catalog 与 README 含有未提交修改，rank6 catalog 尚未跟踪，因此记录描述的是当时的工作区字节，而非全部已提交内容。解释框架失败、覆盖范围或验收状态时，必须保留这一证据范围。^[tests-math-library.md:9-18]
