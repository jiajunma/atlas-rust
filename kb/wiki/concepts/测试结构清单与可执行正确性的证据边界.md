# 测试结构清单与可执行正确性的证据边界

测试结构清单描述测试模块的组织、数量与回归接入方式；可执行正确性则以 HPC 门验收为准。结构性阅读与测试计数不能作为测试通过的证据，来源包也明确不声称任何测试通过。^[atlas-core-regression-library.md:9-13, atlas-core-regression-library.md:43-45]

## 结构清单的覆盖范围

本次清单覆盖 `atlas-core` 语言层的四个测试模块：`session.rs`（201 个测试）、`typed.rs`（133 个）、`domain_builtins.rs`（92 个）和 `session_fixture_tests.rs`（17 个）。阅读范围是模块组织，不含逐测试内容；这些单元与清单计数仅标识 git base `964f0033` 所对应的本快照字节。^[atlas-core-regression-library.md:9-13, atlas-core-regression-library.md:43-45]

模块内的名称前缀提供了测试家族地图：`session.rs` 包含 `named`、`while`、`polynomial` 等家族；`typed.rs` 以 `convert*`、`overload*`、`evaluate*` 等组织；`domain_builtins.rs` 包含提取助手 `as_*`、构造 `build_*` 及块、打印、Weyl 等家族。此类组织可结合 [[atlas-core 回归测试库的家族组织]] 阅读。^[atlas-core-regression-library.md:17-29]

`session_fixture_tests.rs` 的 17 个测试经 `session::run_source` 贯穿命令恢复、类型转换与求值，刻意不保留已移除的动态求值器作为第二实现。这说明了 [[会话全流程回归测试]] 的执行路径与设计边界，但不构成运行通过的记录。^[atlas-core-regression-library.md:30-32, atlas-core-regression-library.md:43-45]

## 原版金标与回归接入

[[原版背书的语言层回归测试]] 使用 `include_str!` 载入 `tests/math/generics/` 中的 fixture，并逐字节比对 `.oracle.stdout` 与 `.oracle.stderr`。语言层共有 244 处 `include_str!` 将 fixture 直接绑定进测试。^[atlas-core-regression-library.md:20-22, atlas-core-regression-library.md:39-39]

每个 HPC 差分发现的差异必须先落成回归测试。fixture 与 `.oracle.*` 金标保存在 `tests/math/generics/`，金标只能来自原版的完整捕获，不能使用 Rust 输出作为金标；Weyl A1 的 v8 冻结 goldens 是来源列举的实例。^[atlas-core-regression-library.md:36-38]

## 可执行正确性的验收依据

[[HPC 验收证据链]] 由 `tests/reference/hpc/` 下的分阶段证据 JSON、只追加的验收账本 `tests/reference/hpc/math_acceptance_index_2026_10_01.json`，以及 `docs/HANDOFF.md` 的衔接记录组成。知识库不改写验收账本；测试的可执行正确性以 HPC 门为准，来源列举了 632 项清单与 `atlas-core-test-inventory`。^[atlas-core-regression-library.md:40-45]

因此，在使用本结构清单时，应保留其快照与阅读范围限制：它支持关于测试数量、家族组织和回归接入方式的描述，不能据此报告测试已经通过。^[atlas-core-regression-library.md:9-13, atlas-core-regression-library.md:17-32, atlas-core-regression-library.md:43-45]

## 文档覆盖边界

各测试覆盖的生产代码由所属专题包解释，包括会话、类型转换、求值、领域值、构造、形变、派发、校验打印与子群等。`session_frame.rs` 的 18 个测试归入会话帧包，不属于上述四模块清单的覆盖范围。^[atlas-core-regression-library.md:49-55]
