# 测试结构清单与可执行正确性的证据边界

测试结构清单描述测试模块的组织、数量和回归接入方式；可执行正确性则须由 HPC 门验收。来源材料完成的是结构性阅读，不包含逐测试内容，也明确不声称任何测试通过。^[atlas-core-regression-library.md:9-13, atlas-core-regression-library.md:43-45]

## 结构清单的范围

清单覆盖 `atlas-core` 语言层的四个测试模块：`session.rs` 有 201 个测试，`typed.rs` 有 133 个，`domain_builtins.rs` 有 92 个，`session_fixture_tests.rs` 有 17 个。这些单元与清单计数仅标识 git base `964f0033` 对应的本快照字节，不能视为其他版本的统计或通过记录。^[atlas-core-regression-library.md:9-13, atlas-core-regression-library.md:43-45]

名称前缀构成 [[atlas-core 回归测试库的家族组织|测试家族地图]]：`session.rs` 包括 `named`、`while`、`polynomial` 等家族；`typed.rs` 包括 `convert*`、`overload*`、`evaluate*` 等家族；`domain_builtins.rs` 包括提取助手 `as_*`、构造 `build_*`，以及块、打印和 Weyl 等家族。^[atlas-core-regression-library.md:17-29]

`session_fixture_tests.rs` 的 17 个测试通过 `session::run_source` 贯穿命令恢复、类型转换与求值，并刻意不保留已移除的动态求值器作为第二实现。这说明了 [[会话全流程回归测试]] 的执行路径与设计边界，本身不构成测试通过的证据。^[atlas-core-regression-library.md:30-32, atlas-core-regression-library.md:43-45]

## 原版金标与回归接入

[[原版背书的语言层回归测试]] 使用 `include_str!` 载入 `tests/math/generics/` 中的 fixture，并逐字节比对 `.oracle.stdout` 与 `.oracle.stderr`。来源记录语言层共有 244 处 `include_str!` 将 fixture 直接绑定进测试。^[atlas-core-regression-library.md:20-22, atlas-core-regression-library.md:39-39]

每个 HPC 差分发现的差异都必须先在测试库中落成回归。fixture 与 `.oracle.*` 金标位于 `tests/math/generics/`；金标只来自原版的完整捕获，永不使用 Rust 输出作为金标。Weyl A1 的 v8 冻结 goldens 是来源列举的实例。^[atlas-core-regression-library.md:36-38]

## 可执行正确性的验收依据

[[HPC 验收证据链]] 由 `tests/reference/hpc/` 下的分阶段证据 JSON、只追加的验收账本 `tests/reference/hpc/math_acceptance_index_2026_10_01.json`，以及 `docs/HANDOFF.md` 的衔接记录组成。知识库不改写该验收账本。^[atlas-core-regression-library.md:40-42]

测试的可执行正确性以 HPC 门为准，来源列举的验收入口包括 632 项清单与 `atlas-core-test-inventory`。结构清单中的数量只描述指定快照，不能据此报告测试已通过；本来源也没有作出任何测试通过声明。^[atlas-core-regression-library.md:43-45]

## 文档覆盖边界

测试所覆盖的生产代码由各自所属专题包解释，包括会话、类型核心、表达式转换、求值、领域值、构造、形变、派发、校验打印与子群等。`session_frame.rs` 的 18 个测试另归会话帧包，不属于本清单覆盖的四个模块。^[atlas-core-regression-library.md:49-55]
