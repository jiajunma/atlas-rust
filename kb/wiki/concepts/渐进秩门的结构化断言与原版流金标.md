# 渐进秩门的结构化断言与原版流金标

`tests/math/progressive/` 是渐进秩门的 fixture 集合，来源清点为 22 项，以 rank-1 验证材料为主，也包含 `cartan_rank2`。该目录使用两种期望载体：`.expect.json` 保存结构化断言，`.oracle.stdout` 保存原版逐字节输出流。两者的证据含义应分别保留。^[tests-math-library.md:58-67]

## 期望载体与覆盖范围

结构化期望配套于 `unitarity_rank1_parameters`、`av_ann_rank1_finite_cycle`、`cartan_classes_rank1` 等材料，目录还包含 `loading_rank1.expect.json`。来源明确将 `.expect.json` 定义为结构化断言载体，但未展开其字段或具体断言内容。^[tests-math-library.md:60-67]

原版流金标配套于 `full_deform_rank1_{control,split}`，以 `.oracle.stdout` 保存原版 stdout，供逐字节比较。它与结构化断言文件是不同的期望表示，不能仅因都属于测试期望而混同。^[tests-math-library.md:65-67]

渐进秩门还包括 `unitarity_forms_rank1.json`、`hodge_rank1_{control,padding,specialization,trace}`、`load_av_ann_rank1`、`load_unitarity_rank1`、`cartan_rank1/rank2`、Cartan 类拒绝件及 `type_equivalence_language.json`。这些名称描述目录覆盖范围，不表示相关数学功能已经通过验收；整体目录背景可参见 [[数学测试目录的参数化覆盖清单]]。^[tests-math-library.md:58-67, tests-math-library.md:93-97]

## 原版金标的来源纪律

语言 oracle 是原版可执行文件。金标必须在新鲜进程中捕获原版完整流，并保留拒绝与恢复标记；不能用 Rust 输出生成金标，再以此证明 Rust 与原版一致。这一纪律与 [[基于原版金标的差分回归]] 相关。^[tests-math-library.md:52-56, tests-math-library.md:89-92]

来源在 `generics/` 部分说明了 fixture 经 `include_str!` 内嵌后与 `.oracle.*` 逐字节比对的机制；对于 `progressive/`，材料只列出期望载体及对应 fixture，未说明其具体加载或比较实现。因此，不能据此断言渐进秩门也采用相同的内嵌机制。^[tests-math-library.md:50-67]

## 验收与证据边界

该来源属于目录结构与证据纪律的结构性阅读，不声称数学验收。取证时部分目录清单和 README 存在未提交修改，rank6 清单尚未跟踪；来源记录的是当时工作区字节，不能视为全部已提交内容。22 项渐进秩门材料以及其他库规模数字均是清单信息，不是正确率。^[tests-math-library.md:9-18, tests-math-library.md:58-67, tests-math-library.md:93-94]

checker 自检失败、标签错配等 harness 失败不等同于数学失败，也不能充当数学证据；不可变失败阶段应保留冻结。验收状态以账本与 HANDOFF 为准，README 的旧记录须服从最新 HANDOFF 或回执。^[tests-math-library.md:16-17, tests-math-library.md:95-97]

正式结果须进入 [[HPC 验收证据链]]：`tests/reference/hpc/math_acceptance_index_2026_10_01.json` 是仅追加的验收账本种子，每条记录通过哈希链绑定确切源码、报告、独立审查、选用例 ID、断言与限制。每个已发布后缀都须有永久前缀检查点，否则仍只是草稿；拥有 fixture 或期望文件本身不构成这一验收记录。^[tests-math-library.md:79-87]
