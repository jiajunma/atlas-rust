# 渐进秩门的结构化断言与原版流金标

`tests/math/progressive/` 是渐进秩门的测试夹具集合，来源清点为 22 项，以 rank-1 材料为主，也包含 `cartan_rank2`。目录使用两种期望载体：`.expect.json` 承载结构化断言，`.oracle.stdout` 承载原版逐字节输出流。^[tests-math-library.md:58-67]

## 期望载体与覆盖范围

结构化期望配套于 `unitarity_rank1_parameters`、`av_ann_rank1_finite_cycle` 和 `cartan_classes_rank1`，另有 `loading_rank1.expect.json`。来源未展开这些文件的字段或具体断言，因此这里只能确认其载体形式与配套关系。^[tests-math-library.md:60-67]

原版 stdout 金标配套于 `full_deform_rank1_{control,split}`，使用 `.oracle.stdout` 保存逐字节流。它与 `.expect.json` 的结构化断言属于不同的期望表示。^[tests-math-library.md:65-67]

其他覆盖材料包括 `unitarity_forms_rank1.json`、`hodge_rank1_{control,padding,specialization,trace}`、`load_av_ann_rank1`、`load_unitarity_rank1`、`cartan_rank1/rank2`、Cartan 类拒绝件及 `type_equivalence_language.json`。这些名称记录目录覆盖范围，不表示对应功能已经通过验收；整体背景见 [[数学测试目录的参数化覆盖清单]]。^[tests-math-library.md:58-67, tests-math-library.md:93-97]

## 原版流金标的来源纪律

语言 oracle 是原版可执行文件。金标必须在新鲜进程中捕获原版完整流，包括拒绝与恢复标记；不得使用 Rust 输出充当金标。相关比较纪律见 [[基于原版金标的差分回归]]。^[tests-math-library.md:52-56, tests-math-library.md:89-92]

来源在 `generics/` 部分描述了 fixture 经 `include_str!` 内嵌后与 `.oracle.*` 逐字节比对的机制；对 `progressive/` 则只列出期望载体及配套材料，未说明具体加载或比较实现，因而不能据此认定渐进秩门采用相同的内嵌机制。^[tests-math-library.md:50-67]

## 验收与证据边界

来源属于目录结构、JSON schema 与证据纪律的结构性阅读，不声称数学验收。取证时，顶层与 generics 清单、README 存在未提交修改，rank6 清单尚未跟踪；所记录的工作区字节不能视为全部已提交内容。22 项渐进秩门材料及其他库规模数字均是清单信息，不是正确率。^[tests-math-library.md:9-18, tests-math-library.md:58-67, tests-math-library.md:93-94]

checker 自检、标签错配等 harness 失败不等同于数学失败，也不能充当数学证据；不可变失败阶段须保留冻结。验收状态以账本与 HANDOFF 为准，README 的历史记录须服从最新 HANDOFF 或回执。^[tests-math-library.md:16-17, tests-math-library.md:95-97]

[[HPC 验收证据链]] 中的 `tests/reference/hpc/math_acceptance_index_2026_10_01.json` 是仅追加的验收账本种子。每条验收通过哈希链绑定确切源码、报告、独立审查、选用例 ID、断言与限制；每个已发布后缀须有永久前缀检查点，否则只是草稿。^[tests-math-library.md:79-87]
