# 环境根反射字的共享约定

环境根反射字由 `root_reflection.rs` 中的 `reflection_word(rc, alpha)` 统一生成。它是上游 `RootDatum::reflection_word`（`rootdata.cpp:1092-1095`）的唯一移植点；模块注释禁止消费方另建私有副本，扩展参数与公共块 packet 生成共用这一字约定。相关主题见 [[扩展参数值类型 ExtParam]] 与 [[公共块的构造与元素编号（PartialBlock）]]。^[twisted-involution-trio.md:66-75]

## 构造与顺序约定

源材料将构造概括为 `reflection_word(rc, alpha) = to_dominant(reflection(α, 2ρ))`：先对 \(2\rho\) 施加根 \(\alpha\) 的反射，再对所得向量进行优势化，最后按上游约定将生成的字**反转一次**后返回。返回前的反转属于共享接口的顺序约定。^[twisted-involution-trio.md:68-72]

优势化采用贪心循环：每轮从生成元 `0` 开始扫描，选择第一个配对为负的生成元施行反射，反射后重新从头扫描。循环没有迭代上限；其终止性依赖数学性质，实现中没有额外的迭代护栏。^[twisted-involution-trio.md:71-75]

## 算术与维度边界

`wrapping_dot` 与 `add_scaled` 全程采用 wrapping `i32` 算术，溢出时静默回绕，没有错误返回路径。长度一致性仅由 `debug_assert_eq!` 检查；release 模式下，长度不一致会按 `zip` 的行为截断。^[twisted-involution-trio.md:73-75]

同一来源包中的算术策略存在差异：`twisted_involution` 全部采用 checked 算术，`involution_classification` 混用 checked、saturating 和普通算术，`root_reflection` 则全部采用 wrapping 算术。来源将这种差异属于有意分层还是实现漂移保留为待核问题，未给出确定结论。^[twisted-involution-trio.md:79-84]

## 接口关系与证据边界

`root_reflection.rs` 服务于表示层，消费方涉及 [[RepContext 借用上下文与一致性约束|RepContext]]。它与同包的 `twisted_involution.rs`、`involution_classification.rs` 互不调用。^[twisted-involution-trio.md:77-84]

本页依据结构性源码阅读，不构成数学验收；上游位置仅转录自代码注释。`root_reflection.rs` 没有文件内测试，来源也将 `reflection_word` 全函数列为未测路径。该来源记录的知识维护未执行 Atlas、Cargo、测试或 benchmark，因此不能据此宣称实现已通过执行验证。^[twisted-involution-trio.md:9-13, twisted-involution-trio.md:73-84, twisted-involution-trio.md:88-92]
