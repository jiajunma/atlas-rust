# 类型化分支节点的分派规则

`TypedExpr` 是类型化管线的可执行表达式树，其中包含 `Conditional`、`Case`、`IntCase` 与 `UnionCase` 等分支节点。来源明确给出了后三者的分派规则：`Case` 选择首个 tag 匹配分支并分发载荷，`IntCase` 按整数索引及边界情形选择分支，`UnionCase` 按变体位置应用分支函数。^[atlas-core-typed-core.md:32-32, atlas-core-typed-core.md:47-60]

## Case：首个 tag 匹配与载荷分发

`Case` 选择首个 tag 匹配的分支，再按该分支的 `shape` 分发载荷。“首个匹配”是其选择规则的一部分；载荷分发则由 `shape` 决定。来源未进一步说明无匹配分支时的行为。^[atlas-core-typed-core.md:58-58]

## IntCase：负值、越界与取模

`IntCase` 对负值选择 `then`，对越界情形选择 `else`；两者皆缺时采用取模规则。这些特殊情形构成其整数索引分派约定，详见 [[IntCase 的索引分支与越界回绕]]。^[atlas-core-typed-core.md:58-59]

## UnionCase：按变体位置应用函数

`UnionCase` 根据变体位置选择并应用对应的分支函数。同一表达式树还包含 `UnionInject` 与 `TupleProject`，分别作为 injector 与 projector 的闭包体；它们与 `UnionCase` 是不同的节点。^[atlas-core-typed-core.md:57-59]

## Conditional 与证据边界

来源将 `Conditional` 列为调用与控制节点，但没有展开其条件判定或分支求值细节，因此本页不据此补充具体执行规则。上述节点属于 [[类型化转换与求值管线]] 的表达式树结构。^[atlas-core-typed-core.md:32-32, atlas-core-typed-core.md:47-60]

本说明依据 `typed.rs` 上部数据结构的结构性阅读；`convert_expr` 转换遍、`TypedExpr` 的求值实现及测试不在该来源包的覆盖范围内。这些记录不构成语言或数学验收，上游行号对应关系也属于实现方的移植陈述，行为兼容仍以 HPC 语料门为准。^[atlas-core-typed-core.md:9-15, atlas-core-typed-core.md:108-114]
