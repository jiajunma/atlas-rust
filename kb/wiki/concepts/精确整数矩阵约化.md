# 精确整数矩阵约化

精确整数矩阵约化在 `atlas-core` 中由 `matreduc` 模块承担，为 `global.w` 批内建提供支持。该模块声明为 `pub(crate)`，属于 crate 内部实现。来源将其定位为从上游 `utilities/matreduc.h` 移植的精确整数矩阵约化模块。^[atlas-core-root.md:21-22]

## 实现定位

模块角色地图列出的约化机制包括 `gcd+recorder` 和 `column_echelon`，并将 `matreduc.rs` 描述为逐操作对应固定上游版本 `4d3e9449` 的实现。在所记录的快照中，该文件为 1559 行；模块角色描述来自各文件头的实现方自述。^[atlas-core-root.md:27-29, atlas-core-root.md:51-51]

## 与语言运行时的关系

[[atlas-core 语言门面与兼容契约]]以可观察的语言边界组织公开模块，`matreduc` 则作为内部模块服务内建运算的正确性。同一 crate 中的 `domain_builtins` 负责语言层到 `atlas-real-group` 的桥接及命名函数应用分派。^[atlas-core-root.md:11-13, atlas-core-root.md:21-22, atlas-core-root.md:52-52, atlas-core-root.md:64-64]

## 证据边界

当前来源仅覆盖 crate 门面与模块角色地图，属于结构性阅读，不声称语言或数学验收。上游移植对应关系应按实现方设计陈述理解，不能直接视为行为等值的证明；来源明确要求以 HPC 差分门判定语义等值。^[atlas-core-root.md:9-13, atlas-core-root.md:55-61]

本来源没有展开 `gcd+recorder` 或 `column_echelon` 的输入输出契约、算法步骤、数学不变量及失败行为，并明确指出 `matreduc` 因其规模和对内建正确性的作用，需要独立来源包。现有材料因此只能支持模块定位与来源说明。^[atlas-core-root.md:51-51, atlas-core-root.md:57-64]

快照记录的 Git base 为 `964f0033`，工作区干净。行数与哈希仅用于标识所读快照字节，不能证明实现正确；相关阅读限制可参见 [[结构性源码阅读的验证与覆盖限制]]。^[atlas-core-root.md:62-63]
