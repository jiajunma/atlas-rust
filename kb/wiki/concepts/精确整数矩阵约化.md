# 精确整数矩阵约化

精确整数矩阵约化在 `atlas-core` 中由 `matreduc` 模块承担，为 `global.w` 批内建提供支持。该模块声明为 `pub(crate)`，仅在 crate 内部可见；来源将其定位为从上游 `utilities/matreduc.h` 移植的精确整数矩阵约化实现。^[atlas-core-root.md:21-22]

## 模块定位与所列机制

模块角色地图列出 `gcd+recorder`、`column_echelon` 等机制，并将 `matreduc.rs` 描述为逐操作对应固定上游版本 `4d3e9449` 的实现。在该快照中，文件共有 1559 行。这些角色描述与对应关系来自文件头的实现方自述。^[atlas-core-root.md:27-29, atlas-core-root.md:51-51]

[[atlas-core 语言门面与兼容契约]]围绕可观察的语言边界组织公开模块，`matreduc` 则作为内部模块服务内建正确性。同一 crate 的 `domain_builtins` 承担语言层到 `atlas-real-group` 的桥接，并负责命名函数应用的分派。^[atlas-core-root.md:11-13, atlas-core-root.md:21-22, atlas-core-root.md:52-52, atlas-core-root.md:64-64]

## 证据与覆盖边界

当前来源是 crate 门面与模块地图的结构性阅读，不声称语言或数学验收。上游移植对应关系属于实现方的设计陈述，不能直接证明行为等值；来源要求以 HPC 差分门判定语义等值，相关背景见 [[HPC 验收证据链]]。^[atlas-core-root.md:9-13, atlas-core-root.md:57-61]

来源未展开 `gcd+recorder` 或 `column_echelon` 的输入输出契约、算法步骤、数学不变量及失败行为，并明确指出 `matreduc` 因其规模及对内建正确性的作用，需要独立来源包。本页因此仅说明模块定位、所列机制与移植来源。^[atlas-core-root.md:51-51, atlas-core-root.md:57-64]

来源记录的快照 Git base 为 `964f0033`，工作区干净。行数与哈希仅标识该快照的字节，不能证明实现正确。^[atlas-core-root.md:62-63]
