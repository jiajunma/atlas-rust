# 线性映射下降到子商的条件验证

`ModTwoSubquotient::validate_induced_map_to(target, map)` 验证环境线性映射能否下降为子商之间的映射。它分别检查源分子与源分母的基向量之像；条件不满足时，返回 `CartanFiberMapDoesNotDescend`，并通过 `relation` 区分失败的包含关系。^[mod-two.md:75-79]

## 子商模型与下降条件

`ModTwoSubquotient` 由 `numerator`、`denominator` 和 `complement_basis` 组成，表示共同环境空间中两个 $\mathbb{F}_2$ 子空间的典范商。构造时检查环境维数一致、分母秩不超过分子秩、分母的每个基向量属于分子，以及补基恰好来自分母缺少主元的位置；违反这些不变量时报 `ModTwoSubquotientInvariantViolation`。坐标约定见 [[F₂ 子商的低主元坐标（ModTwoSubquotient）]]。^[mod-two.md:64-70]

记源子商为 $N/D$、目标子商为 $N'/D'$，环境线性映射为 $f$。验证所要求的两个包含关系是 $f(N)\subseteq N'$ 与 $f(D)\subseteq D'$，实现通过逐个检查源分子、源分母的基向量之像来验证。^[mod-two.md:75-79]

分子条件失败时，错误为 `CartanFiberMapDoesNotDescend { relation: "numerator" }`；分母条件失败时，错误为 `CartanFiberMapDoesNotDescend { relation: "denominator" }`。这两项检查分别约束分子像的归属与分母关系的保持。^[mod-two.md:75-79]

## 为什么不能只检查商基代表

源码注释特别指出：只检查商基代表，会在某个源分母向量的像在目标商中非零时，让正规形选择“看似”定义了映射。因此，选定代表元上的检查不能替代对源分母的检查。^[mod-two.md:75-79]

典范代表与坐标转换是另外的操作。`canonical_representative(vector)` 先要求输入属于分子，否则返回 `NotInModTwoSubspace`；通过后，调用分母的 `quotient_representative` 计算代表元。`to_coordinates` 与 `ambient_representative` 则按补基的最低置位读写坐标。这些表示操作与下降条件验证在接口中分别提供。^[mod-two.md:72-79]

代表元所依赖的子空间归约采用最低置位主元的典范 RREF 基，且与插入顺序无关；`quotient_representative` 通过归约给出确定性商类代表。相关背景见 [[最低主元索引的典范 RREF 子空间]]。^[mod-two.md:30-43]

## 接口与封装边界

`ModTwoSubquotient` 刻意保持 crate 私有，因为它承载当前 Cartan-fiber 结构层使用的低主元打包坐标。公开 API 是数学层的 `CartanFiber` 包装，而非内部坐标的序列化格式。^[mod-two.md:64-67]

环境映射通过 `ModTwoAmbientMap` trait 提供，使领域层能够在稠密矩阵造成多余分配时直接实现映射。`ModTwoLinearMap` 仅作为 `#[cfg(test)]` 下的稠密测试辅助。^[mod-two.md:80-81]

## 测试与证据边界

来源记录了子商低主元坐标等测试锚点，但未覆盖 `ModTwoSubquotientInvariantViolation` 的五处错误、`NotInModTwoSubspace`，以及 `CartanFiberMapDoesNotDescend` 的两个 `relation` 值；`validate_induced_map_to` 在该文件内也没有调用方。^[mod-two.md:85-93]
