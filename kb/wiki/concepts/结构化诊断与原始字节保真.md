# 结构化诊断与原始字节保真

`Diagnostic` 将错误类别、消息、源跨度、警告状态与回溯信息组合为结构化诊断，并为非 UTF-8 的 Atlas 数据保留精确原始字节。错误类别与消息措辞刻意分离，使调用方能够按类别比较行为，而不依赖具体文案。^[atlas-core-support-layer.md:20-30]

## 诊断结构与消息表示

`ErrorKind` 包含 `Lexical`、`Syntax`、`Name`、`Type`、`Program`、`Runtime` 与 `Io`。其中 `Program` 表示表达式分析失败，区别于类型合一失败。`Diagnostic` 包含 `kind`、`message`、`raw_message: Option<AtlasString>`、`span`、`warning` 和 `back_trace: Vec<AtlasString>`。^[atlas-core-support-layer.md:20-27]

当消息包含非 UTF-8 的 Atlas 数据时，`new_bytes` 将消息分流：`raw_message` 保存精确字节，`message` 提供转义后的编辑器预览。`message` 不是字节输出的权威来源；这一约定与 [[AtlasString 字节保留串与原始字节打印]] 相联系。实际诊断渲染与打印由 `session_frame.rs` 中的 `describe_bytes` 承担。^[atlas-core-support-layer.md:23-27, atlas-core-support-layer.md:70-72]

## 源身份与位置

`SourceId(u64)` 表示源缓冲的稳定身份，值 `0` 表示无需区分的匿名输入。`SourcePosition` 使用从 1 开始的行号和列号；`SourceSpan` 采用含头不含尾的区间，并在构造时断言 `byte_start <= byte_end`。^[atlas-core-support-layer.md:16-19]

`SourceText { source_id, text, line_starts }` 持有源文本，并在构造时预存各行起始字节位置。`position(byte)` 先将偏移钳制到文本长度，再退到字符边界，通过 `line_starts` 上的 `partition_point` 确定行号；列号为行首到该位置的 Unicode 标量数加 1。`span(start, end)` 用于组装源跨度，相关细节见 [[源文本身份与 Unicode 位置映射]]。^[atlas-core-support-layer.md:34-38]

## 警告与运行时回溯

`warning` 标记需要向用户报告、但不使会话变脏的诊断。源材料记录的上游词法恢复行为是向 stderr 打印警告，不改变会话的 clean 标志，退出状态保持为 0。^[atlas-core-support-layer.md:25-27]

运行时错误在展开过程中累积 `back_trace`，顺序为最外层在前。`trace()` 通过前插维持这一顺序，对应上游 `error_base::trace` 的 `push_front` 行为；命令层将非空 trace 拷入 `back_trace` 系统变量。参见 [[运行时回溯的累积与暴露]]。^[atlas-core-support-layer.md:28-30]

## 测试与证据边界

源位置部分的测试锚点覆盖匿名身份稳定、源身份随跨度保留，以及按 Unicode 标量和换行计算位置、将越界位置钳制到文本末尾。这些锚点描述源位置行为的覆盖范围。^[atlas-core-support-layer.md:34-38]

本页依据的源包属于结构性阅读记录，不声称完成语言或数学验收。上游行号引用属于实现方的移植陈述，行为兼容仍以 HPC 语料门为准；快照字节数与哈希仅标识对应字节，源包记录的 Git base 为 `964f0033`。参见 [[结构性源码阅读的验证与覆盖限制]]。^[atlas-core-support-layer.md:9-12, atlas-core-support-layer.md:70-74]
