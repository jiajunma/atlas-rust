# 结构性源码阅读的验证与覆盖限制

结构性源码阅读描述可见的接口、模块职责、执行流程和测试锚点，其结论受所读文件与证据类型限制。`weyl_size.rs`、`presentation.rs` 与 `atlas-core` 门面的来源包均标为结构性阅读完成，但不声称数学验收；`atlas-core` 来源也不声称语言验收。^[weyl-size-presentation.md:9-13, atlas-core-root.md:9-13]

## 源码快照与执行验证

Weyl 群阶与实形展示来源包覆盖 `weyl_size.rs`（262 行）和 `presentation.rs`（186 行）。快照 `2026-10-06-weyl-size-presentation.json` 绑定 Git base、两文件字节 SHA-256 与 Kimi 调用记录；草案依据完整文件字节生成，再由维护者对照源码逐条核对。本次维护未执行 Atlas、Cargo、测试或 benchmark，因此这一阅读过程不构成运行验证。^[weyl-size-presentation.md:10-13, weyl-size-presentation.md:80-84]

`atlas-core` 来源包由维护者直接撰写，覆盖 `lib.rs` 及顶层模块、子目录文件的角色定位。其行数与哈希标识 Git base `964f0033` 下干净工作区的快照字节；哈希本身不证明字节所表达的实现正确。^[atlas-core-root.md:9-13, atlas-core-root.md:62-63]

## 上游引用与兼容性陈述

Weyl 群阶与实形展示包中的上游 C++、CWEB 行号仅转录自代码注释，未核对上游字节；阶数字面量和上游行号也不构成数学或正确性验收。解释这些内容时，应保留“代码注释声明”与“已核验结果”的区别。^[weyl-size-presentation.md:11-13, weyl-size-presentation.md:70-74]

`atlas-core` 模块地图同样以各文件头的自述定位角色。“移植自 axis.w/global.w 某行号”属于实现方的设计陈述，不是已核验行为；来源明确要求语义等值以 HPC 差分门为准，并仅指向 Weyl owner/dual 语义的 A1 限定验收示例。相关门面定位见 [[atlas-core 语言门面与兼容契约]]。^[atlas-core-root.md:27-29, atlas-core-root.md:55-61]

## 阅读观察与输入校验边界

`weyl_size.rs` 通过分量拆分和分支形状分析计算 Weyl 群阶，但存在校验留白：单节点分量对任意非零对角值都返回 2；符号不一致的非对角项对计入度数，却不提高最大边重数；秩大于 4 的双键链不检查双键位置。这些是源码阅读记录的行为限制，详见 [[Cartan 类型识别的输入校验边界]]。^[weyl-size-presentation.md:23-38]

`branch_lengths` 从唯一的度 3 节点向外遍历，没有环检测。来源将“含环输入可能不终止而非报错”明确标为阅读观察，本次维护未通过执行验证这一情形。^[weyl-size-presentation.md:31-34, weyl-size-presentation.md:80-84]

`presentation.rs` 的 compact/split 逐元素扫描先于 `ms_tau` 秩检查，而该检查仅检查行数。来源说明失败时结果整体丢弃，没有可观察副作用；这些顺序与失败行为属于 [[实形展示的编号顺序与不变量错误处理]] 的实现观察。^[weyl-size-presentation.md:52-56]

## 测试锚点与未覆盖分支

Weyl 群阶计算的测试锚点包括 A4、B5/C5、D5、G2、F4、E6、夹一行环面的 A1×A1，以及空系统。所有错误分支、E7/E8 分支和秩 4 的非 F4 分支 B4/C4 均无测试。另有接口观察：`factorial` 虽返回 `Result`，内部没有可失败操作，该签名属于预留。详见 [[Dynkin 分类器的测试覆盖与证据边界]]。^[weyl-size-presentation.md:40-41, weyl-size-presentation.md:72-74]

实形展示层的三个测试锚点涉及单连通 A1 的名称与顺序、伴随 A1 的 split 形不连通，以及单连通 B2 的三个实形。非恒等对合（非 split 内类）、quasisplit 但非 split 的实形，以及四个不变量错误分支均无测试；这些覆盖限制应与 [[实形展示状态的构建与判定]] 一并阅读。^[weyl-size-presentation.md:58-60, weyl-size-presentation.md:75-76]

## 架构结论与阅读范围

`weyl_size.rs` 与 `presentation.rs` 互不导入，共享的是同一 `StructureError` 类型的不同导入路径。模块注释分别说明阶商校验和展示状态位的用途，但这两份文件无法显示 `CartanClassification` 内部是否调用 `weyl_order_of_cartan`。相关依赖结论因此限于已读文件，见 [[Weyl 群阶模块与实形展示模块的架构边界]]。^[weyl-size-presentation.md:62-68]

`atlas-core` 来源包只覆盖门面与模块地图；`typed.rs`、`domain_builtins.rs`、`session.rs` 和 `syntax.rs` 的内部实现需要各自的独立来源包，来源当时标为待补。crate 私有的 `matreduc` 虽未公开，却有 1559 行并服务内建正确性，同样需要独立来源包。模块可见性与角色地图不能替代内部实现的证据覆盖。^[atlas-core-root.md:55-64]
