# 补全快照的惰性生成与精确失效

补全快照由 `frames` 私有子模块 `completions.rs` 中的 `CompletionCandidates` 管理。它为会话维护名字顺序索引，按需生成可借用的候选切片；不捕获全局缓存或运行时表，名字的可见性只由命令发表（publication）改变。^[atlas-core-completions.md:9-20]

## 存储与惰性生成

`CompletionCandidates` 使用 `names: Vec<(Rc<str>, bool)>` 保存按 intern 顺序排列的名字及其 active 位，以 `indices: BTreeMap<Rc<str>, usize>` 提供去重反查，并以 `snapshot: OnceCell<Vec<String>>` 缓存补全快照。索引与有序条目共享同一个 `Rc<str>` 分配。^[atlas-core-completions.md:17-24]

`snapshot` 通过 `get_or_init` 按需生成快照：筛选 active 名字，并保留其 intern 顺序。该顺序是名字首次词法使用的顺序，而非首次成功定义的顺序；lexer 在名字首次出现时就将其 intern，因此顺序与可见性分开维护，参见 [[会话补全顺序与名字可见性分离]]。^[atlas-core-completions.md:29-31]

## 精确失效规则

`intern` 遇到已有名字时直接返回其下标，遇到新名字时将其作为 inactive 条目追加。该操作永不使快照失效：新增的非 active 名字或局部名字不会改变既有补全结果。^[atlas-core-completions.md:25-26]

`set_active` 仅在 active 位真实变化时调用 `snapshot.take()`，使缓存失效；重复设置同一状态不会使缓存失效。失效后的快照在后续查询时按当前 active 状态重新生成，避免因无实际可见性变化的操作而重建。^[atlas-core-completions.md:27-31]

名字失效后再次激活，会回到其原有 intern 位置，而不是追加到候选末尾。可见性的撤销与恢复因此不会改变名字的既定排序位置。^[atlas-core-completions.md:29-36]

## 遗留 `replace` 接口

遗留公开 API `replace` 采用不同路径：整体重置后按调用方顺序重建，并通过 `OnceCell::from` 绕过索引直接保存所给快照。它保留调用方顺序，甚至保留重复名字，例如 `["b","a","b"]` 会原样返回；不能将常规快照的去重索引语义套用于这一直接保存的结果。^[atlas-core-completions.md:32-34]

## 测试与证据边界

三个单元测试分别锚定相关行为：`no_snapshot_until_queried` 覆盖惰性生成、指针稳定性及仅在真实状态变化时失效；`visibility_and_revival_order` 覆盖可见性恢复后的顺序与 `Rc` 共享计数为 2；`legacy_snapshot_replacement` 覆盖 `replace` 的重置与保序。重复设置相同状态不失效的行为由指针相等检查约束。^[atlas-core-completions.md:27-28, atlas-core-completions.md:38-42]

来源包只记录机制的结构性阅读，不声称语言验收。它将行为验收归于 HPC completion AFTER 门（job `3868661`，限定范围已接受）及后续 command AFTER R2（job `3868782`，过载视图修订），不重述或扩展这些证据；相关证据职责可参见 [[HPC 验收证据链]]。^[atlas-core-completions.md:9-13, atlas-core-completions.md:43-45]

关于原版 `buffer.w` 仅在查询时遍历 intern 表的描述，来源转述自模块注释与历史笔记，本次未独立重读上游；当前实现的说明依据工作区字节的结构性阅读，Git base 与哈希记录在关联快照中。^[atlas-core-completions.md:17-20, atlas-core-completions.md:47-50]
