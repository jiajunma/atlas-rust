# 补全快照的惰性生成与精确失效

`CompletionCandidates` 位于 `frames` 的私有子模块 `completions.rs`，为会话维护补全名字的顺序索引，并按需提供借用切片 API。它不捕获全局缓存或运行时表；名字可见性只由命令发表（publication）改变。^[atlas-core-completions.md:9-20]

## 存储与惰性生成

内部以 `names: Vec<(Rc<str>, bool)>` 按 intern 顺序保存名字及 active 位，以 `indices: BTreeMap<Rc<str>, usize>` 提供去重反查，以 `snapshot: OnceCell<Vec<String>>` 缓存快照。索引与有序条目共享同一个 `Rc<str>` 分配。^[atlas-core-completions.md:17-24]

查询快照时，`snapshot` 通过 `get_or_init` 按需筛选 active 名字，并保持 intern 顺序。该顺序是名字的首次词法使用顺序，而非首次成功定义顺序：lexer 在名字首次出现时就进行 intern，顺序与可见性分别维护，参见 [[会话补全顺序与名字可见性分离]]。^[atlas-core-completions.md:29-31]

## 精确失效规则

`intern` 遇到已有名字时直接返回下标；遇到新名字时追加 inactive 条目。该操作永不使快照失效，非 active 名字或局部名字不会改变既有快照。^[atlas-core-completions.md:25-26]

`set_active` 仅在 active 位实际变化时调用 `snapshot.take()`，使缓存失效；重复设置同一状态不会使其失效。失效后的快照由后续查询通过 `get_or_init` 重新生成，重复设置状态时的快照稳定性则由指针相等测试约束。^[atlas-core-completions.md:27-31]

名字失效后再次激活，会恢复到其原有 intern 位置，而不会移到候选末尾；`early`／`late` 交替的测试锚定了这一恢复顺序。^[atlas-core-completions.md:29-36]

## 遗留 `replace` 接口

遗留公开 API `replace` 整体重置状态后，按调用方顺序重建，并通过 `OnceCell::from` 绕过索引直接保存所给快照。这条路径保留调用方顺序，甚至保留重复名字，例如 `["b","a","b"]` 会原样返回。^[atlas-core-completions.md:32-34]

## 测试与证据边界

三个单元测试分别覆盖不同约束：`no_snapshot_until_queried` 覆盖惰性生成、指针稳定性及仅在真实状态变化时失效；`visibility_and_revival_order` 覆盖可见性与恢复顺序，并检查 `Rc` 共享计数为 2；`legacy_snapshot_replacement` 覆盖 `replace` 的重置与保序。^[atlas-core-completions.md:38-42]

来源包属于结构性阅读，不声称语言验收。它将惰性快照机制的行为验收归于 HPC completion AFTER 门（job `3868661`，限定范围已接受）及后续 command AFTER R2（job `3868782`，过载视图修订），本包只记录机制，不重述或扩展这些证据；相关背景见 [[HPC 验收证据链]]。^[atlas-core-completions.md:9-13, atlas-core-completions.md:43-45]

当前实现的说明依据工作区字节，Git base 与哈希见来源关联的阅读快照。关于原版 `buffer.w` 仅在查询时遍历 intern 表的描述，转述自模块注释与历史笔记，本次未独立重读上游。^[atlas-core-completions.md:17-20, atlas-core-completions.md:47-50]
