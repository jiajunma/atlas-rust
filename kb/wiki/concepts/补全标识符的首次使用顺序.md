# 补全标识符的首次使用顺序

补全标识符的首次使用顺序，是 Atlas 会话层在消费 token 时记录标识符所保持的顺序约束。`next_session_token` 调用 `context.note_completion_token` 完成记录，使被包含文件与后续命令中的标识符保留原始的首次使用顺序。^[atlas-core-session.md:44-46]

## 记录时机与逐命令执行

Atlas 的词法分类依赖先前命令留下的状态，因此 `session.rs` 拥有逐命令执行的外层循环，且不预切分整个源文件。补全记录也发生在实际消费 token 的时刻，与这一 [[有状态的逐命令会话执行]] 机制相配合。^[atlas-core-session.md:9-14, atlas-core-session.md:44-46]

`run_source` 为每个源创建全新的 `TypedContext`，`run_source_with_context` 则支持调用方持有的上下文。循环遇到换行时调用 `execute_tokens` 处理当前命令缓冲，遇到文件结束时执行剩余缓冲并退出；其余普通 token 进入命令缓冲。^[atlas-core-session.md:29-40]

## 多行命令与文件包含

标识符记录与命令求值处于不同环节。在 [[多行命令的增量解析]] 中，换行终止符使 `allow_more` 为真；当 `parse_command_fragment_in` 返回 `Ok(None)` 时，会话保留命令前缀，不求值，也不产生诊断，继续在同一缓冲中累积输入。标识符仍按 token 的消费时机记录。^[atlas-core-session.md:44-50]

文件包含由 `session_frame.rs` 负责。原始会话循环遇到包含指令时，会产生 Io 诊断 `file inclusion is only available through a session frame`。因此，跨被包含文件与后续命令的顺序约束应结合 [[会话循环与文件会话帧的职责边界]] 理解；`next_session_token` 的记录纪律明确要求保留两者的原始首次使用顺序。^[atlas-core-session.md:37-39, atlas-core-session.md:44-46]

## 测试与证据边界

该源码快照的回归库包含 5 个以 `completion` 为前缀的测试。来源未列出这些测试的具体断言，不能仅凭计数认定所有跨文件或多行命令场景均已覆盖。该包属于结构性阅读记录，本身不声称语言或数学验收；测试名与家族计数仅对应所记录的源码快照。^[atlas-core-session.md:9-14, atlas-core-session.md:58-68, atlas-core-session.md:78-80]
