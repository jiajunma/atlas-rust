# 表达式转换器的十二族分派

表达式转换器以 `convert_expr` 为入口，由 `convert_expr_context` 按 `Expr` 种类分派至十二个族助手。转换过程在单遍中同时进行类型检查与类型合成，使用仅经 `specialise` 变异的 in/out 类型模式；十二族划分是保持语义的机械分区。^[atlas-core-convert-expr.md:9-17, atlas-core-convert-expr.md:21-29]

## 入口与共享上下文

`convert_expr(expression, required: &mut Type, analysis)` 将所需类型 `required` 装入共享的 `ConversionType`，采用当前 `analysis.type_floor`，并在转换结束后写回类型。该接口对应 [[convert_expr 的 in/out 类型模式与单遍转换]]。^[atlas-core-convert-expr.md:21-22]

`convert_expr_context` 负责调整 `type_floor`：当 `return` 操作数位于类型抽象内部时，它仍可引用外层函数的类型要求，其中的变量按该要求实际的 fixed 下限解读。各族助手接收已经调整的共享转换上下文。^[atlas-core-convert-expr.md:23-29]

## 十二族的职责

分派覆盖以下十二族；族名与所处理的表达式种类对应如下。^[atlas-core-convert-expr.md:31-38]

| 族助手 | 处理的表达式种类 |
|---|---|
| `atom` | 标量、lambda、`OperatorCast`、return、group、标识符、break、dont、die |
| `type_context` | `TypeAbstraction`、`Cast` |
| `display` | tuple、list、barlist |
| `binding` | let |
| `assignment` | 六种赋值形 |
| `subscription` | 下标访问 |
| `slice` | 切片 |
| `application` | `OperatorCall`、`Call` |
| `control` | conditional、binary、unary、sequence、do、next |
| `loop` | while、for、counted-for |
| `tagged_case` | `Case` |
| `case` | `IntCase`、`UnionCase` |

## 分区纪律与语义边界

十二个族助手全部标记为 `#[inline(never)]`，保留原有分支体及调整后的共享转换上下文。来源记录的栈问题 `original3839541` 中，GDB 陷阱命中的是分析帧，而非求值器；因此，这里的十二族描述的是转换阶段的组织方式。^[atlas-core-convert-expr.md:26-29]

`loop` 族中的 while 转换体现了分派必须保留的上下文边界：循环层位于整棵 do 树之外，压平守卫不能移出该边界。条件先做 a-priori 转换，再检查 bool；所需上下文决定 `WhileMode`：void 模式允许循环体具有异构分支，int 模式计数，其余走带 reversed 标志的 row 模式。row 路径先尝试 `[*]` 特化，失败后回退到 `row_coercion`，详见 [[while 转换的上下文模式与循环边界]]。^[atlas-core-convert-expr.md:40-44]

`assignment` 族还依赖专门的赋值助手：`set x := value` 与裸 `x := value` 共享转换路径，赋值查找遵守局部遮蔽全局的规则，并产生赋值专用诊断。分量赋值和字段投影另有约束，分别关联 [[分量赋值的类型权限]] 与 [[基于保留类型定义的投影解析]]。^[atlas-core-convert-expr.md:46-58]
