# 表达式转换器的十二族分派

表达式转换器以 `convert_expr` 为入口，由 `convert_expr_context` 按 `Expr` 种类分派到十二个族助手。转换在单遍中同时完成类型检查与类型合成，采用仅经 `specialise` 变异的 in/out 类型模式。十二族划分是保留原有语义的机械分区。^[atlas-core-convert-expr.md:9-14, atlas-core-convert-expr.md:21-38]

## 入口与共享上下文

`convert_expr(expression, required: &mut Type, analysis)` 将 `required` 装入共享 `ConversionType`，采用当前 `analysis.type_floor`，转换完成后再写回类型。相关机制见 [[convert_expr 的 in/out 类型模式与单遍转换]]。^[atlas-core-convert-expr.md:21-22]

`convert_expr_context` 调整 `type_floor`，使类型抽象内部的 `return` 操作数能够引用外层函数的类型要求；其中的变量按该要求实际的 fixed 下限解读。族助手保留这一已调整的共享转换上下文。^[atlas-core-convert-expr.md:23-29]

## 十二族的职责

十二族按表达式种类划分，具体对应关系如下。^[atlas-core-convert-expr.md:31-38]

| 族助手 | 处理的表达式种类 |
|---|---|
| `atom` | 标量、lambda、`OperatorCast`、return、group、标识符、break、dont、die |
| `type_context` | `TypeAbstraction`、`Cast` |
| `display` | tuple、list、barlist |
| `binding` | let |
| `assignment` | 六种赋值形 |
| `subscription` | 下标访问 |
| `slice` | 切片 |
| `application` | `OperatorCall`、`Call` |
| `control` | conditional、binary、unary、sequence、do、next |
| `loop` | while、for、counted-for |
| `tagged_case` | `Case` |
| `case` | `IntCase`、`UnionCase` |

## 分区与栈纪律

十二个族助手全部使用 `#[inline(never)]`，保留原有分支体与共享转换上下文。来源记录的栈问题 `original3839541` 中，GDB 陷阱命中的是分析帧，而非求值器；这一经验是族划分纪律的背景。`typed.rs` 全文件共有 19 处 `#[inline(never)]`，不能将其全部等同于十二个族助手。^[atlas-core-convert-expr.md:26-29]

## 分派后保留的转换契约

`loop` 族的 while 转换将循环层置于整棵 do 树之外，压平守卫不得移出该边界。条件先进行 a-priori 转换，再检查 `bool`。`WhileMode` 由所需上下文决定：`void` 使循环体采用 `void` 上下文并允许异构分支；`int` 选择 count 模式；其余选择 row 模式，带 `reversed` 标志。row 路径先尝试 `[*]` 特化，失败后回退到 `row_coercion`。详见 [[while 转换的上下文模式与循环边界]]。^[atlas-core-convert-expr.md:40-44]

赋值助手中，`convert_simple_assignment` 让 `set x := value` 与裸 `x := value` 共享同一路径。`lookup_assignable` 遵循局部遮蔽全局的规则；两种查找均使用赋值专用的未定义或常量诊断，并引用整个表达式的紧凑渲染。^[atlas-core-convert-expr.md:46-51]

分量赋值支持行、`vec`、`mat` 的列或双下标项，以及 `KTypePol[KType]` 和 `ParamPol[Param]`；上游的 `ratvec` 只读。`resolve_projector` 使用保留的类型定义，而非投影函数的当前值；复制的或泛型定义也可匹配，因此具名接收方本身不能唯一确定字段选择。参见 [[分量赋值的类型权限]] 与 [[基于保留类型定义的投影解析]]。^[atlas-core-convert-expr.md:52-58]

`factor_transform_call` 不采用上游将 `x+1` 改写为 `succ(x)` 的丢参数优化，二元调用始终保留两个操作数，详见 [[变换调用中的二元操作数保留]]。^[atlas-core-convert-expr.md:59-60]
