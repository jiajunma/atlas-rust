# 词法诊断保留与命令恢复接口

Atlas 词法器采用有状态设计，允许解析器或 REPL 逐 token 消费输入。其诊断与恢复接口支持保留可恢复的 token、缓存词法错误，以及丢弃当前命令所在物理行的余部后重置扫描状态。`tokenize` 是获取完整 token 流的兼容便利接口。^[atlas-core-lex.md:9-13, atlas-core-lex.md:74-83]

## 诊断与 token 保留

`tokenize` 提供全有或全无的结果；`tokenize_with_diagnostics` 返回 `LexOutput{tokens, diagnostics}`，按遭遇顺序保留诊断，并保留所有可恢复的 token。后者允许调用方同时取得诊断信息与恢复后的词法输出。^[atlas-core-lex.md:81-83]

[[TokenCursor 单 Token 前瞻|TokenCursor]] 提供 `peek` 与 `bump` 接口。词法错误像 token 一样被缓存，因此前瞻与随后消费看到的是同一结果。^[atlas-core-lex.md:79-80]

## 字符串与注释异常

字符串通过双写引号表示引号转义，换行会使字符串被判为未闭合。未闭合时，词法器报告 Lexical warning，消息为 `"Closing string denotation."`，并将恢复出的 `String` token 放入 `pending`。报告异常后，该 token 与后续命令仍可供解析器使用；相关机制见[[字符串转义与未闭合恢复]]。^[atlas-core-lex.md:74-77]

注释支持 `{}` 嵌套。未闭合注释产生 Lexical 错误，消息为 `"Comment that started on line X, column Y is never closed."`，指出注释起始位置；相关扫描规则见[[可嵌套注释]]。^[atlas-core-lex.md:72-73]

## 命令恢复与换行边界

正常扫描时，只有能够终止当前命令的换行才成为可观察 token。`skip_space` 仅在 `nesting` 为空且 `prevent_termination` 为空时透出换行，否则会内部消费换行。分组与续行 token 对这一边界的影响见[[换行抑制状态机]]。^[atlas-core-lex.md:40-46]

遇到不支持的字符时，词法器清空嵌套与换行抑制状态，使下一个换行能够终止命令。源材料将其描述为词法死胡同，并对应到 oracle 报语法错误、在下一换行恢复的表现。^[atlas-core-lex.md:63-64]

`recover_command` 是显式恢复接口：丢弃当前物理行的剩余内容，并重置续行、嵌套和命令首状态。其丢弃范围以当前物理行为边界。^[atlas-core-lex.md:78-78]

## 职责与证据边界

词法器本身不做语义判定。文法适配位于 `syntax.rs`，使用 LALRPOP 带跨度 token 流；逐命令消费位于 `session.rs`；指令的包含与重定向语义位于 `session_frame.rs`，相关职责见[[SessionFrame 会话帧与文件包含语义]]。^[atlas-core-lex.md:87-89]

源材料记录了覆盖所述状态机分支的 23 个测试，但其证据性质是结构性阅读，不构成语言验收。上游 `lexer.w` 等行号引用属于实现方的移植陈述；词法兼容仍以 HPC 语言语料门为准。^[atlas-core-lex.md:9-13, atlas-core-lex.md:85-91]
