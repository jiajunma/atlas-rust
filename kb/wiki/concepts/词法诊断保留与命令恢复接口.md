# 词法诊断保留与命令恢复接口

Atlas 词法器通过诊断保留、恢复 token 和命令状态重置，支持解析器或 REPL 在词法异常后继续消费输入。扫描器刻意采用有状态设计，允许逐 token 消费；`tokenize` 则是获取完整 token 流的兼容便利接口。^[atlas-core-lex.md:9-13]

## 诊断与 token 的保留

`tokenize` 提供全有或全无的结果；`tokenize_with_diagnostics` 返回 `LexOutput{tokens, diagnostics}`，按遭遇顺序保留诊断，并保留所有可恢复的 token。后者使调用方能够同时获取诊断信息与恢复后的词法输出。^[atlas-core-lex.md:81-83]

[[TokenCursor 单 Token 前瞻|TokenCursor]] 提供 `peek` 与 `bump` 单 token 前瞻接口。词法错误像 token 一样被缓存，因此前瞻与随后消费会看到同一结果。^[atlas-core-lex.md:79-80]

## 字符串与注释异常

字符串通过双写引号转义；遇到换行时，字符串被判为未闭合。词法器报告 Lexical warning，消息为 `"Closing string denotation."`，同时将恢复出的 `String` token 放入 `pending`。因此，报告异常后，该 token 与后续命令仍可供解析器使用，支撑 REPL 的恢复行为，详见[[字符串转义与未闭合恢复]]。^[atlas-core-lex.md:74-77]

注释允许 `{}` 嵌套。未闭合注释产生 Lexical 错误，消息为 `"Comment that started on line X, column Y is never closed."`，指出注释开始的位置，相关机制见[[可嵌套注释]]。^[atlas-core-lex.md:72-73]

## 命令恢复与换行边界

正常扫描时，只有能够终止当前命令的换行才成为可观察 token。`skip_space` 仅在 `nesting` 为空且 `prevent_termination` 为空时透出换行；分组与续行状态会使换行被内部消费。这些状态决定异常发生后能否重新获得命令边界。^[atlas-core-lex.md:38-46]

遇到不支持的字符时，词法器将其视为词法死胡同，清空嵌套与换行抑制状态，使下一个换行能够终止命令。源材料将这一行为对应到 oracle 报语法错误并在下一换行恢复的表现。^[atlas-core-lex.md:63-64]

`recover_command` 提供显式的命令恢复接口：丢弃当前物理行剩余内容，并重置续行、嵌套和命令首状态。它处理的是当前行剩余输入及扫描状态的恢复。^[atlas-core-lex.md:78-78]

## 职责与证据边界

词法器本身不做语义判定。文法适配由 `syntax.rs` 的 LALRPOP 带跨度 token 流承担，逐命令消费位于 `session.rs`，包含与重定向语义位于 `session_frame.rs`。这些职责可结合[[Atlas 语法前端与运算符优先级归约]]和[[SessionFrame 会话帧与文件包含语义]]理解。^[atlas-core-lex.md:87-89]

源材料记录了覆盖上述状态机分支的 23 个测试，但该材料属于结构性阅读，不构成语言验收。上游 `lexer.w` 行号是实现方的移植陈述；词法兼容仍以 HPC 语言语料门为准。^[atlas-core-lex.md:9-13, atlas-core-lex.md:85-91]
