# 语法前端的测试覆盖与验收边界

Atlas 语法前端的测试覆盖表达式、命令与诊断形状，但这些测试和源码结构性阅读不等同于语言验收。文法与上游 `parser.y` 的逐条对应属于实现方的移植陈述；语法兼容性仍以 HPC 语言语料门为准。^[atlas-core-syntax.md:104-110]

## 测试覆盖与职责划分

本源包覆盖 `syntax.rs` 与 `grammar.lalrpop`：前者共 4659 行，其中生产代码为第 1–3261 行，随后包含 51 个测试；后者是 1096 行的 LALRPOP 文法源。源包的编辑状态为结构性阅读完成，明确不声称语言验收。^[atlas-core-syntax.md:9-14]

51 个测试从 `syntax.rs` 第 3262 行起，覆盖表达式、命令和诊断形状。语法前端之外，AST 节点的语义判定由 `typed.rs` 的转换与求值承担，词法处理位于 `lex.rs`，逐命令驱动位于 `session.rs`，重定向与包含处理位于 `session_frame.rs`。理解覆盖范围时，需要保留这些模块的职责边界，可结合 [[Atlas 语法前端与运算符优先级归约]]、[[TypedExpr 可执行表达式树]] 与 [[会话帧驱动的 CLI 执行模型]] 阅读。^[atlas-core-syntax.md:106-109]

## 解析与诊断的关键契约

语法适配层将有状态的 Atlas 词法流惰性转换为 LALRPOP 的带位置 token 流，使词法器的上下文敏感规则不进入文法动作。命令边界仍由词法器拥有，适配层不得预先切分剩余源码，因为会话状态可能在下一条命令之前改变；带环境的命令解析还必须通过活跃 `TypeTable` 看到先前的类型声明。^[atlas-core-syntax.md:11-14, atlas-core-syntax.md:77-82, atlas-core-syntax.md:93-96]

会话使用的 `parse_command_fragment_in` 对未完成输入有明确条件：仅当 `allow_more` 且存在解析器持有的虚拟分组时返回 `Ok(None)`，保留前缀供下一行重试。物理换行不会终止这种未闭合的类型规格，完整解析前也不会求值任何 AST；EOF 与非 EOF 语法错误仍按正常路径诊断。相关机制见 [[多行命令的增量解析]]。^[atlas-core-syntax.md:83-86]

诊断适配函数将 LALRPOP 的 `ParseError` 渲染为 Bison 风格的 `syntax error, unexpected … [expecting …]`。其兼容边界包括诊断类别，而具体措辞允许在 oracle 比对后继续精化；因此，诊断形状覆盖不能直接表述为措辞已完全对齐。相关主题见 [[Bison 风格语法诊断兼容层]]。^[atlas-core-syntax.md:97-100, atlas-core-syntax.md:106-110]

## 验收与证据限制

应区分结构性阅读、测试覆盖、移植对应陈述与语言兼容验收。源包报告了前端结构和测试范围，同时明确将语法兼容交由 HPC 语言语料门判定；其中的字节数与哈希仅标识基于 Git base `964f0033` 的快照字节，不构成兼容性验收结论。相关证据要求可参见 [[HPC 验收证据链]]。^[atlas-core-syntax.md:9-14, atlas-core-syntax.md:104-110]
