# 赋值表达式的目标约束与语法分析边界

Atlas 语法前端将赋值相关表达式区分为 `Assignment`、`MultiAssignment`、`ComponentAssignment`、`ComponentTransform`、`FieldAssignment` 与 `FieldTransform`，各 AST 变体均携带源位置跨度（span）。这些节点保留赋值形式及其目标结构，AST 节点的语义判定则由 `typed.rs` 的转换与求值层负责。^[atlas-core-syntax.md:16-30, atlas-core-syntax.md:106-108]

## 模式赋值与变量声明

`MultiAssignment` 对应 `set pattern := value`，目标是**已存在的变量**；这与通过 `let` 引入新变量不同。来源将这一语法对应到上游 `parser.y:264`。^[atlas-core-syntax.md:25-27]

表达式中的 `MultiAssignment` 还应与命令层的 `Command::Set` 区分：后者使用与 `let` 相同的声明形式，并行绑定到全局表；函数型叶子进入重载表，其余进入标识符表。两者虽然都出现 `set`，但承担的绑定职责不同。^[atlas-core-syntax.md:25-27, atlas-core-syntax.md:68-72]

模式结构包括名字、元组解构、匿名丢弃及省略槽。`Discard` 写作 `type .`，不能作为元组模式成员；`Omitted` 对应 `(a, , c)` 中的空槽，消费一个元组分量，但不约束类型，也不绑定名字。元组模式还可通过 `: t` 或 `: !t` 额外绑定整体，文法保证该整体绑定必为 `Name`。^[atlas-core-syntax.md:52-58]

## 分量与字段赋值的目标约束

`ComponentAssignment` 表示 `a[i] := c`，文法要求被下标访问的目标为**裸标识符**。这一约束属于语法层；但并非所有不受支持的下标形式都在解析阶段拒绝：`M[i,j]` 会按元组下标解析，随后由类型分析拒绝。^[atlas-core-syntax.md:25-28]

`ComponentTransform` 表示 `a[i] op:= e`；字段操作则分别由 `FieldAssignment` 和 `FieldTransform` 表示，对应 `p.f := e` 与 `p.f op:= e`。来源明确列出这些独立节点，但没有进一步说明字段赋值目标的完整文法限制。^[atlas-core-syntax.md:29-30]

## 语法分析与语义判定的边界

`M[i,j]` 的处理体现了语法结构识别与语义合法性检查的分工：解析器可以构造元组下标的 AST，而类型分析仍会拒绝该赋值形式。因此，解析成功不能作为赋值目标在类型层面合法的依据；分量赋值的类型权限可结合 [[分量赋值的类型权限]] 阅读。^[atlas-core-syntax.md:27-28, atlas-core-syntax.md:106-108]

前端通过独立适配层将有状态的 Atlas 词法流转换为 LALRPOP 的带跨度 token 流，使词法器的上下文敏感规则不进入文法动作。`TokenStream` 惰性生成 `(offset, ParserToken, offset)`，相关词法背景见 [[Atlas 词法 Token 模型]]。^[atlas-core-syntax.md:11-14, atlas-core-syntax.md:91-96]

命令边界仍由词法器管理，适配层不预先切分剩余源文本，因为会话状态可能在下一条命令前改变。`parse_command` 与 `parse_command_in` 使用活跃的 `TypeTable`，让分类能够看到先前的类型声明；逐命令执行背景见 [[会话帧驱动的 CLI 执行模型]]。^[atlas-core-syntax.md:77-82]

## 诊断与证据范围

语法错误由 `syntax_error` 及相关辅助函数将 LALRPOP 的 `ParseError` 转换为 Bison 风格措辞，例如 `syntax error, unexpected … [expecting …]`。这一机制描述的是语法诊断兼容边界，来源允许在 oracle 比对后进一步精化措辞。^[atlas-core-syntax.md:97-100]

来源记录了 51 个覆盖表达式、命令及诊断形状的测试，但没有给出赋值相关测试的独立清单或执行结果。本页依据结构性阅读；文法与上游 `parser.y` 的对应属于实现方移植陈述，语法兼容仍以 HPC 语言语料门为准，参见 [[CLI 兼容性的证据边界]]。^[atlas-core-syntax.md:9-14, atlas-core-syntax.md:104-110]
