# 跨引擎基准的执行与一致性纪律

跨引擎基准以统一执行条件和完整输出一致性约束计时比较。`tests/math/benchmarks.json` 使用 `atlas-math-benchmarks-v1` schema，登记 E7、D6、D8 三个 KGB 计时用例；每引擎超时为 300 秒，运行 4 轮。^[tests-math-library.md:31-34]

## 执行条件与一致性门槛

基准必须使用新鲜进程，在同一节点运行，并交替安排引擎执行顺序。每轮完整输出必须一致，首次出现不一致即停止；完整输出一致性因此是继续基准流程的必要条件。^[tests-math-library.md:31-34]

计时须按引擎进行分钟窗标定，不得把短用例人为填充成分钟级负载。该要求与超时、轮数及执行环境约束共同构成基准的执行纪律。^[tests-math-library.md:31-34]

## 基线版本与 oracle 来源

`tests/math/baseline.json` 记录双仓库版本钉定：来源所记 oracle 当前 pin 为 `7e1b958c`，Rust 侧为 `05625c5d`。Rust 版本是基准建立时存档的 main 分支历史基线字节，不代表当前 HEAD。^[tests-math-library.md:35-37]

原版可执行文件是语言 oracle。用于[[基于原版金标的差分回归]]的金标必须在新鲜进程中捕获原版完整流，包括拒绝与恢复标记；不得以 Rust 输出充当金标。^[tests-math-library.md:52-56, tests-math-library.md:91-92]

## 证据范围与验收边界

来源包记录目录结构、JSON schema 与证据纪律，属于结构性阅读，不声称数学验收。取证时 `tests/math/catalog.json`、`tests/math/generics/catalog.json` 和 `tests/math/README.md` 含未提交修改，`tests/math/rank6/catalog.json` 尚未跟踪；这些记录反映当时工作区字节，不能作为已提交内容呈现。^[tests-math-library.md:9-18]

库规模与 HPC 记录数量属于覆盖清单，不能解释为正确率。基准条目提供的是用例与执行约束，本来源未给出这些用例的计时结果或性能提升结论。^[tests-math-library.md:18-18, tests-math-library.md:31-34, tests-math-library.md:93-94]

harness 失败，例如 checker 自检失败或标签错配，不等于数学失败，也不能充当数学证据；不可变失败阶段须保留冻结。验收状态以账本与 HANDOFF 为准，README 的运行历史遵循“最新 HANDOFF／回执优先于旧记录”的规则。^[tests-math-library.md:16-17, tests-math-library.md:95-97]

正式验收依赖[[HPC 验收证据链]]。`tests/reference/hpc/math_acceptance_index_2026_10_01.json` 是只追加验收账本的种子：每条验收追加哈希链记录，绑定确切源码、报告、独立审查、选用例 ID、断言与限制。每个已发布后缀必须具备永久前缀检查点，否则仍属草稿；相关机制见[[数学验收账本的哈希链与永久前缀检查点]]。^[tests-math-library.md:79-87]
