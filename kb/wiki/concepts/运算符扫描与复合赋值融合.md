# 运算符扫描与复合赋值融合

Atlas 的有状态词法器将普通运算符表示为 `Operator(String)`，将 `+:=` 这类复合赋值拼写表示为 `OperatorBecomes(String)`。运算符与 `:=` 之间允许存在空白和注释，扫描器仍将其融合为一个 token；`Token.lexeme` 保留精确源拼写。相关类型见 [[Atlas 词法 Token 模型]]。^[atlas-core-lex.md:17-27]

## 融合与回退规则

`finish_operator` 在扫描运算符后，跨过空白和注释检查是否紧随 `:=`。若匹配成功，则生成 `OperatorBecomes`，并将换行抑制状态设为 `:`；否则回退扫描偏移，输出普通运算符并携带相应续行状态。探测过程中注释消费失败也会触发回退。^[atlas-core-lex.md:55-57]

注释使用 `{}` 定界且允许嵌套；未闭合注释产生词法错误，诊断指出注释起始的行、列。这也是融合探测需要处理的扫描边界，参见 [[可嵌套注释]]。^[atlas-core-lex.md:55-57, atlas-core-lex.md:72-73]

## 运算符类别与例外

关系符按字符集合 `<=>` 中的极大连续段扫描为一个运算符，并且永不与 `:=` 融合。单个尖括号同时承担类型参数定界符的作用，不抑制换行；独立的 `:=` 则将换行抑制状态设为 `:`。^[atlas-core-lex.md:59-61]

裸 `!` 是 const 模式标记，既不是公式运算符，也不能作为复合赋值的头部。`->`、`~[`、`\%` 和 `##` 各由专门分支处理。^[atlas-core-lex.md:58-62]

尖括号的解释还取决于命令位置：仅在命令首 token 位置，`<`、`<<`、`>`、`>>` 分别识别为包含、强制包含、截断输出和追加输出指令。文件名扫描不会消费该行其余部分，后续校验交给会话帧处理，参见 [[命令首指令与文件名扫描]]。^[atlas-core-lex.md:21-25, atlas-core-lex.md:68-71]

## 与换行终止的关系

词法器只输出能够终止当前命令的换行。`skip_space` 仅在嵌套栈为空且 `prevent_termination` 为空时让换行成为可观察 token，否则将其消费。因此，运算符设置的续行状态会直接影响命令边界，参见 [[换行抑制状态机]]。^[atlas-core-lex.md:40-46]

`operator_termination` 有一项明确例外：若前一个终止符为 `.`，随后扫描到的运算符不再抑制换行，即 `.` 加运算符的序列不会吞掉换行；其他情况下则以相应运算符字符设置抑制状态。^[atlas-core-lex.md:53-54]

遇到不支持的字符时，词法器会清空嵌套与换行抑制状态，使下一个换行能够终止命令。显式调用 `recover_command` 则会丢弃当前物理行的剩余内容，并重置续行、嵌套和命令首状态，参见 [[词法诊断保留与命令恢复接口]]。^[atlas-core-lex.md:63-64, atlas-core-lex.md:78-78]

## 测试与证据范围

源材料记录了覆盖上述状态机分支的 23 个测试。词法器本身不做语义判定：文法适配位于 `syntax.rs`，逐命令消费位于 `session.rs`，包含与重定向语义位于 `session_frame.rs`。^[atlas-core-lex.md:85-89]

本材料属于结构性阅读，不构成语言验收；其中上游 `lexer.w` 行号属于实现方的移植陈述，词法兼容性仍以 HPC 语言语料门为准。^[atlas-core-lex.md:9-13, atlas-core-lex.md:90-91]
