# 递归类型组的名字解析与校验分离

`typed/type_groups.rs` 是 `typed` 的私有子模块，在 `types/recursive.rs` 构造递归类型图之前完成组内名字解析。`resolve_spec` 分两遍处理：先验证名字与类型应用，再改写表达式并解析类型。模块将递归组的验证顺序与诊断同普通别名的既有契约分开保持。^[atlas-core-type-groups.md:9-13, atlas-core-type-groups.md:17-34]

## 第一遍：广度优先校验

验证以别名的右侧表达式（RHS）或 struct、union 的各字段类型为根，按广度优先顺序遍历。`Function` 先将 result 入队，再将 argument 入队；`Applied` 先将参数入队，随后立即校验应用本身，因此应用本身先于其参数接受校验。^[atlas-core-type-groups.md:19-22]

名字判定区分裸名与显式应用：`Named` 按 `supplied=0` 的非显式应用处理，`Applied` 携带显式参数；`Row`、`Tuple`、`Union` 只递归处理子表达式。名字查表失败时，报告 `Identifier '{name}' does not refer to any type`。^[atlas-core-type-groups.md:23-25]

正在定义的局部名字（`locals`）不接受显式类型参数，即使参数个数恰好等于 arity，也报告 `Type '{name}' being defined cannot be given type arguments`。非局部名字则检查构造器 arity，不匹配时报告 `Type constructor '{name}' called with {supplied} type arguments, expected {expected}`。这两类错误与名字查找失败均属于 `Program` 类诊断。^[atlas-core-type-groups.md:26-30]

## 第二遍：形参转发与解析

第二遍由 `resolve` 克隆表达式，先调用 `forward_formals`，再调用 `resolve_in`；`resolve_in` 返回的错误种类统一改写为 `Program`。^[atlas-core-type-groups.md:31-32]

`forward_formals` 的重写条件是：节点为 `Named`、arity 非零，且查表所得编号属于 `locals`。满足条件的组内裸引用被改写为 `Applied`，参数依次为索引 `0..arity` 的 `Variable{index}`，从而转发所在组的全部形参。例如，`MathGenericList` 被改写为 `MathGenericList<A>`，并非作为无参构造器调用。^[atlas-core-type-groups.md:36-43]

形参转发递归进入 `Row`、`Function`、`Tuple`、`Union` 和 `Applied` 的子表达式，其他叶节点保持不变。第一遍禁止局部名字接受显式参数，与第二遍为符合条件的裸引用自动补入形参，是不同阶段的规则。^[atlas-core-type-groups.md:26-28, atlas-core-type-groups.md:38-44]

## 类型结果与字段名

最终，Alias 直接解析，Struct 转换为 `Type::tuple`，Union 转换为 `Type::union_of`；字段名另以 `Vec<Option<String>>` 返回。类型表示的相关背景可参见 [[Type 类型表示与语义等值]]。^[atlas-core-type-groups.md:33-34]
