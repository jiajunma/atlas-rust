# 递归类型组的名字解析与校验分离

`typed/type_groups.rs` 是 `typed` 的私有子模块，负责在 `types/recursive.rs` 构造递归类型图之前解析组内名字。模块将递归组的验证顺序与诊断同普通别名的既有契约分开保持；其内部 `resolve_spec` 又分为先校验、后解析的两遍处理。相关后续阶段见 [[递归类型定义的图级安装]]。^[atlas-core-type-groups.md:9-15, atlas-core-type-groups.md:17-34]

## 第一遍：广度优先校验

校验以别名的右侧表达式（RHS）或 struct、union 的各字段类型为根，按广度优先顺序遍历。遇到 `Function` 时，先将 result 入队，再将 argument 入队；遇到 `Applied` 时，虽先将参数入队，但立即校验应用本身，因此应用的校验先于其参数。这个顺序决定诊断的先后，详见 [[递归类型组的广度优先验证顺序]]。^[atlas-core-type-groups.md:19-22]

名字校验区分裸名与显式应用：`Named` 按 `supplied=0` 的非显式应用处理，`Applied` 携带显式参数，`Row`、`Tuple`、`Union` 则只递归处理子表达式。名字查表失败时，报告 `Identifier '{name}' does not refer to any type`。^[atlas-core-type-groups.md:23-25]

正在定义的局部名字（`locals`）不接受显式类型参数，即使参数个数恰好等于 arity，也报告 `Type '{name}' being defined cannot be given type arguments`。非局部名字则检查构造器 arity，不匹配时报告 `Type constructor '{name}' called with {supplied} type arguments, expected {expected}`。这两类错误与名字查找失败均属于 `Program` 类诊断，参见 [[递归类型组的显式类型实参限制]]。^[atlas-core-type-groups.md:26-30]

## 第二遍：形参转发与名字解析

通过校验后，`resolve` 克隆表达式，依次执行 `forward_formals` 和 `resolve_in`，并将 `resolve_in` 返回的错误种类改写为 `Program`。这样，验证遍历与实际表达式改写、解析具有明确的阶段边界。^[atlas-core-type-groups.md:31-32]

`forward_formals` 处理组内泛型裸引用：当节点为 `Named`、arity 非零，且查表所得编号属于 `locals` 时，将其改写为 `Applied`，参数依次为索引 `0..arity` 的 `Variable{index}`。因此，裸名转发所在组的全部形参，例如 `MathGenericList` 被改写为 `MathGenericList<A>`，而不是作为无参构造器调用。详见 [[泛型递归组裸引用的形参转发]]。^[atlas-core-type-groups.md:36-43]

形参转发递归进入 `Row`、`Function`、`Tuple`、`Union` 和 `Applied` 的子表达式，其他叶节点保持不变。最终 Alias 直接解析，Struct 转换为 `Type::tuple`，Union 转换为 `Type::union_of`；字段名另以 `Vec<Option<String>>` 返回，参见 [[递归类型规格的结构降解与字段名分离]]。^[atlas-core-type-groups.md:33-34, atlas-core-type-groups.md:44-44]
