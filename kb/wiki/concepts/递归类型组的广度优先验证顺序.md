# 递归类型组的广度优先验证顺序

递归类型组的组内名解析由 `crates/atlas-core/src/typed/type_groups.rs` 实现，发生在递归图构造之前。`resolve_spec` 分两遍处理类型规格：先按广度优先顺序验证名字与类型实参，再进行形参转发和解析。^[atlas-core-type-groups.md:9-13, atlas-core-type-groups.md:17-34]

## 遍历顺序

第一遍以别名的右侧表达式（RHS），或 struct／union 的各字段类型为遍历根，执行广度优先验证。遇到 `Function` 时，先将结果类型 `result` 入队，再将参数类型 `argument` 入队，保持“结果先于参数”的访问顺序。^[atlas-core-type-groups.md:19-22]

遇到 `Applied` 时，实现先将类型实参入队，再校验当前应用自身。入队不等于立即访问，因此实际校验顺序是**应用本身先于其参数**；不能将代码中的入队顺序理解为参数先受校验。^[atlas-core-type-groups.md:20-22]

## 名字与实参校验

`Named` 被视为 `supplied = 0` 的非显式应用；`Applied` 表示携带显式类型实参的应用；`Row`、`Tuple` 与 `Union` 只递归访问子表达式。名字查表失败时，报告 `Identifier '{name}' does not refer to any type`。^[atlas-core-type-groups.md:23-25]

对于正在定义的局部名，即编号位于 `locals` 中的名字，验证一律禁止显式类型实参，即使实参数量恰好等于 arity，也报告 `Type '{name}' being defined cannot be given type arguments`。这一限制见 [[递归类型组的显式类型实参限制]]。^[atlas-core-type-groups.md:26-28]

对于非局部名，验证检查类型构造器的 arity；数量不匹配时，报告 `Type constructor '{name}' called with {supplied} type arguments, expected {expected}`。名字不存在、局部名显式传参及构造器实参数量不匹配这三类诊断均属于 `Program` 类。^[atlas-core-type-groups.md:23-30]

## 与第二遍解析的衔接

验证完成后，第二遍 `resolve` 克隆表达式，先执行 `forward_formals`，再调用 `resolve_in`，并将后者的错误种类改写为 `Program`。因此，广度优先验证与后续解析是两个明确分开的阶段，参见 [[递归类型组的名字解析与校验分离]]。^[atlas-core-type-groups.md:31-32]

`forward_formals` 对 arity 非零、查表编号属于 `locals` 的裸 `Named` 引用进行重写：将其变为 `Applied`，实参依次为索引 `0..arity` 的 `Variable`。这使组内裸引用转发所在组的全部形参，而不是作为无参构造器调用；它与第一遍禁止显式传参的规则共同定义了 [[泛型递归组裸引用的形参转发]]。^[atlas-core-type-groups.md:26-28, atlas-core-type-groups.md:36-44]

## 证据边界

本说明依据当前工作区源码的结构性阅读，不构成语言或数学验收。模块关于保持上游 `global.w:1632-1860` 验证顺序与诊断的表述来自模块注释，来源未独立重读该上游区间；验证顺序和诊断措辞的行为权威仍是 HPC 语料门，泛型递归组的端到端验收属于其独立证据链。^[atlas-core-type-groups.md:9-15, atlas-core-type-groups.md:46-50]
