# 递归类型组的广度优先验证顺序

递归类型组的组内名解析由 `crates/atlas-core/src/typed/type_groups.rs` 实现，发生在递归图构造之前。`resolve_spec` 分两遍处理：第一遍按广度优先搜索（BFS）顺序验证类型表达式，第二遍进行形参转发和类型解析。^[atlas-core-type-groups.md:9-13, atlas-core-type-groups.md:17-34]

## 广度优先验证顺序

验证以别名的右侧表达式（RHS），或 struct／union 的各字段类型为根。遇到 `Function` 时，先将结果类型 `result` 入队，再将参数类型 `argument` 入队，保持结果先于参数的访问顺序。^[atlas-core-type-groups.md:19-22]

遇到 `Applied` 时，先将类型实参入队，再校验当前应用自身。入队后的实参等待后续访问，因此实际校验顺序是**应用本身先于其实参**，不能将入队顺序理解为立即校验的顺序。^[atlas-core-type-groups.md:20-22]

## 名字与实参数量检查

`Named` 被视为 `supplied = 0` 的非显式应用；`Applied` 携带显式类型实参；`Row`、`Tuple` 与 `Union` 只递归处理子表达式。名字查表失败时，报告 `Identifier '{name}' does not refer to any type`。^[atlas-core-type-groups.md:23-25]

正在定义的局部名由 `locals` 标识，**一律不接受显式类型实参**。即使实参数量恰好等于 arity，也会报告 `Type '{name}' being defined cannot be given type arguments`。^[atlas-core-type-groups.md:26-28]

对于非局部名，验证检查类型构造器的 arity；数量不匹配时，报告 `Type constructor '{name}' called with {supplied} type arguments, expected {expected}`。名字不存在、局部名显式传参和构造器实参数量不匹配这三类诊断均属于 `Program` 类。^[atlas-core-type-groups.md:23-30]

## 第二遍：形参转发与解析

第二遍 `resolve` 克隆表达式，先执行 `forward_formals`，再调用 `resolve_in`，并将 `resolve_in` 的错误种类改写为 `Program`。^[atlas-core-type-groups.md:31-32]

`forward_formals` 重写满足以下条件的裸 `Named` 引用：arity 非零，且名字查表所得编号属于 `locals`。重写结果为 `Applied`，实参依次为索引 `0..arity` 的 `Variable`，从而转发所在组的全部形参。例如，单形参组中的裸名 `MathGenericList` 会变为 `MathGenericList<A>`，并非按无参构造器调用处理。^[atlas-core-type-groups.md:38-43]

形参转发递归进入 `Row`、`Function`、`Tuple`、`Union` 和 `Applied` 的子表达式，其他叶节点保持不变。最终，Alias 直接解析；Struct 构造成 `Type::tuple`，Union 构造成 `Type::union_of`；字段名另以 `Vec<Option<String>>` 返回。^[atlas-core-type-groups.md:33-34, atlas-core-type-groups.md:44-44]
