# 递归类型规格的结构降解与字段名分离

`typed/type_groups.rs` 是 `typed` 的私有子模块，在递归图构造之前完成组内名解析。其 `resolve_spec` 将声明规格转换为类型表示：Alias 直接解析，Struct 转为 `Type::tuple`，Union 转为 `Type::union_of`；字段名通过独立的 `Vec<Option<String>>` 返回。^[atlas-core-type-groups.md:9-13, atlas-core-type-groups.md:31-34]

## 结构转换与字段名分离

Alias 的右侧表达式直接解析为类型；Struct 和 Union 的字段类型分别组成 tuple 与 union。字段名另行返回，因此类型结构与字段名信息在返回结果中分开表示。类型表示的相关背景可参见 [[Type 类型表示与语义等值]]。^[atlas-core-type-groups.md:31-34]

`Vec<Option<String>>` 以可选字符串表示字段名。来源记录了这一容器及其独立返回方式，但未说明字段名在后续递归图构造或其他消费方中的具体用途。^[atlas-core-type-groups.md:33-34]

## 转换前的验证与解析

`resolve_spec` 采用两遍处理。第一遍进行广度优先验证，以 Alias 的 RHS 或 Struct、Union 的各字段类型为根。`Function` 先将 result 入队，再将 argument 入队；`Applied` 虽然先把参数入队，但会在访问这些参数之前校验当前应用本身。^[atlas-core-type-groups.md:17-22]

名字验证将 `Named` 视为 supplied=0 的非显式应用，将 `Applied` 视为携带显式参数的应用；`Row`、`Tuple` 和 `Union` 只递归检查。查表失败时报 `Identifier '{name}' does not refer to any type`。^[atlas-core-type-groups.md:23-25]

正在定义的局部名不接受显式类型参数，即使参数个数恰好等于 arity，也报 `Type '{name}' being defined cannot be given type arguments`。非局部名则检查构造器 arity，不符时报 `Type constructor '{name}' called with {supplied} type arguments, expected {expected}`。这两类错误与名字查找失败均属于 Program 类。^[atlas-core-type-groups.md:25-30]

第二遍 `resolve` 克隆表达式，先执行 `forward_formals`，再调用 `resolve_in`，并将 `resolve_in` 的错误种类改写为 Program。Alias、Struct 与 Union 按各自规则形成类型结果，字段名独立返回。^[atlas-core-type-groups.md:31-34]

## 泛型裸引用的形参转发

`forward_formals` 的重写条件是：表达式为 `Named`、arity 非零，且查表所得编号属于正在定义的局部集合 `locals`。满足条件时，裸名被改写为 `Applied`，参数依次为索引 `0..arity` 的 `Variable{index}`。因此，组内泛型裸引用转发所在组的全部形参，例如 `MathGenericList` 转为 `MathGenericList<A>`，而不是作为无参构造器调用。^[atlas-core-type-groups.md:36-43]

这一转发发生在第二遍解析中，与第一遍禁止局部名显式类型参数的规则共同构成处理流程。重写递归进入 `Row`、`Function`、`Tuple`、`Union` 和 `Applied` 的子表达式，其他叶节点保持不变。^[atlas-core-type-groups.md:26-32, atlas-core-type-groups.md:38-44]
