# 顶层会话事件的输出规则

`SessionFrame` 的 `execute` 层负责将会话事件转换为可见输出，包括值打印、报告缩进和诊断处理，并维护会话的 `clean` 状态。表达式解析位于 `syntax.rs`，执行位于 `typed.rs`，会话帧承担输出框架职责。^[atlas-core-session-frame.md:50-58, atlas-core-session-frame.md:94-95]

## 值与报告输出

`SessionEvent::Value` 携带非 void 值时，打印 `Value: <display>`；void 即空元组，不产生值打印。^[atlas-core-session-frame.md:52-53]

`ReportLine` 与 `ReportBytes` 按**当前包含深度**缩进，每层增加两个空格。`ReportBytes` 经 `SessionEvent::output` 保留原始字节；定义报告的缩进统一在框架层处理。参见 [[SessionEvent 与字节保留输出]]。^[atlas-core-session-frame.md:54-58]

## 诊断与会话状态

处理 `Diagnostic` 时，若 `kind != Io`，则设置 `clean=false`，并使当前命令进入 Abort；Io 诊断不使会话变脏。文件打开失败与 abandon 级联本身也不改变 clean 状态，因此中止包含读取并不必然意味着会话不再 clean。参见 [[会话 clean 标志与诊断分流]]。^[atlas-core-session-frame.md:43-46, atlas-core-session-frame.md:56-58]

词法 warning（例如未闭合字符串提示）只报告，不使会话变脏，也不触发 abort；真正的词法错误会使会话变脏，并在包含深度大于零时触发 abandon 级联。^[atlas-core-session-frame.md:69-70]

带源码跨度的诊断由 `describe_bytes` 输出为 `{Kind} error at {origin}:{physical}:{column}: {msg}`，随后附源行和 caret 指示符。预处理会先剥除每行尾部空白，再将以 `\` 结尾的行与下一行直接拼接；生成的 `line_map` 将重写行映射到首个物理行，用于诊断行号换算。没有 span 的诊断只有裸 `{Kind} error:` 头。^[atlas-core-session-frame.md:72-79]

## 单命令重定向

`>file EXPR` 与 `>>file EXPR` 的命令体先按**表达式**解析；解析成功后、求值之前才打开 sink。语法错误不会创建文件，求值失败仍会留下文件及已产生的部分输出。参见 [[单命令输出重定向的执行纪律]]。^[atlas-core-session-frame.md:23-25, atlas-core-session-frame.md:59-62]

重定向仅将命令产生的 `Output` 和 `OutputBytes` 事件写入 sink，其余事件照常向上层传递。打开失败只输出一行裸 stderr：`Failed to open {name}`，会话保持 clean；`sink.close()` 无条件执行。^[atlas-core-session-frame.md:63-65]

## 文件包含的框架消息

实际进入文件读取时，框架打印 `Starting to read from file …`；读取返回 Finished 时，记录 completed 并打印 `Completely read file …`。因 include-once 或活动包含栈循环守卫而跳过的包含保持静默。参见 [[SessionFrame 会话帧与文件包含语义]]。^[atlas-core-session-frame.md:12-14, atlas-core-session-frame.md:36-40]

放弃读取时，框架通过 `lexer.offset()-1` 回退到正在读取的行，再经 `line_map` 换算物理行号，输出 `Abandoning reading of file '{origin}' at line {physical}`。嵌套包含的各外层依次补发自己的消息，顺序为最内层在先。参见 [[嵌套包含的 abandon 级联]]。^[atlas-core-session-frame.md:66-68]

## 测试与证据边界

源文件内的 18 个测试提供单元级行为锚点，覆盖原始字节输出、重定向字节保留、包含框架行、级联顺序、深度缩进、void 抑制和物理行报告等行为。这些测试锚点不等于端到端兼容结论；文件命令兼容仍以 HPC 差分语料为准。^[atlas-core-session-frame.md:81-90]

来源属于结构性阅读，不声称语言或数学验收。对 `buffer.w`、`main.w` 和 `parser.y` 的上游位置引用是实现方的移植陈述，端到端可见行为仍需以 HPC 差分语料核实。^[atlas-core-session-frame.md:9-16, atlas-core-session-frame.md:94-97]
