# 领域内建函数派发契约

领域内建函数派发契约规定 `domain_builtins.rs` 如何接收调用、检查参数、执行领域操作、包装返回值并报告错误。其核心是 `match name` 派发；所给源码快照包含 166 个派发臂，本资料仅覆盖入口与组织方式，不逐臂解释数学内容。^[atlas-core-domain-dispatch.md:9-13, atlas-core-domain-dispatch.md:27-38]

## 调用入口与求值纪律

`call(name, arguments, span)` 通过 `call_with_printed` 执行调用，并丢弃打印侧通道。`call_with_printed` 接收 `printed: &mut Vec<String>`；资料覆盖的实现中，只有 `partial_extended_KL_block` 使用该通道记录计算中途的输出，对应上游 `ext_kl.cpp:945-948` 的 stdout 行为。^[atlas-core-domain-dispatch.md:17-25]

`call_owned_with_printed` 为三种饥饿乘积提供专门路径：`LieType×LieType`、`WeylElement×Vector` 与 `Vector×WeylElement`。它们经 `hungry_product_owned` 先检查组合秩是否满足 `RANK_MAX`，或检查权、余权的大小是否匹配，再消费输入，分别执行 factors 合并、`word_act_weight` 或逐生成元 `simple_coreflect`。其余调用走普通借用适配路径；这一安排与 `typed.rs` 的 `HungryBuiltinCall` 求值纪律配对，相关求值模型见 [[TypedExpr 六族求值与值需求层级]]。^[atlas-core-domain-dispatch.md:18-23]

## 派发臂的统一结构

每个派发臂依次执行参数个数检查 `arity(name, arguments, n, span)?`、按类型提取参数、调用领域操作、将结果包装成 `Value`。类型提取使用 `as_lie_type`、`as_integer`、`as_matrix` 等适配器；错误通过 `type_error`、`runtime`、`structure_diagnostic` 或 `relation_diagnostic` 发出。该结构与 [[函数调用分派与内建参数解包]] 相关。^[atlas-core-domain-dispatch.md:29-32]

校验顺序也是契约的一部分。源码臂内注释说明：`build_KGB_element_wrapper` 在无值门之前完成全部构造检查；`KL_block_wrapper` 先执行 `test_standard`；`classify_involution_wrapper` 先检查矩阵为方阵且满足 \(M^2=I\)，再进行整数格分类。这些顺序分别关联 [[BuildAndDrop 领域内建验证策略]] 与 [[对合类型的分层构造验证与错误优先级]]。^[atlas-core-domain-dispatch.md:32-35]

整数收窄先经过 `signed32`，再映射到 `unsigned32`；超出转换范围时使用错误信息 `Integer value too big for conversion`。部分同名函数按参数个数选择包装器，例如 `real_form` 区分 `(InnerClass,int)` 与 `(InnerClass,mat,ratvec)` 两种调用。语言层重载解析位于 `typed.rs`，领域派发与之配对。^[atlas-core-domain-dispatch.md:36-38, atlas-core-domain-dispatch.md:70-72]

## 强制转换的领域侧契约

`coerce(tag, value, span)` 按标签选择领域转换。`LT` 与 `IcRf` 分别调用 `Lie_type`、`inner_class` 派发臂；`RdIc` 与 `RdRf` 则直接从 `InnerClass` 或 `RealForm` 句柄导航到根数据，不经过函数调用。`SpI` 与 `Sp(I,I)` 将整数或整数对转换为 `Split`，转换前先收窄到机器位宽，相关系数模型见 [[SplitInteger 分裂整数系数]]。^[atlas-core-domain-dispatch.md:40-46]

多项式转换包含展开、合并与排序。`KpolK` 将 `KType` 经 `finals_for` 展开为 final 组分，逐项调用 `merge_ktype_term`，再按 canonical `K_type_pol` 项序排序；`PolP` 将 `Param` 经 `expand_final` 展开为 final 标准组分，合并后按 `SR_poly` 项序排序。相关概念见 [[finals_for 带号重数展开]] 与 [[可约点与标准参数 final 化]]。^[atlas-core-domain-dispatch.md:47-52]

未知转换标签产生运行时错误 `conversion '<tag>' is not implemented`。强转表的语言侧注册位于 `coercions.rs`，此处的 `coerce` 提供相应的领域侧实现。^[atlas-core-domain-dispatch.md:53-53, atlas-core-domain-dispatch.md:70-72]

## 实形式构造与属主身份

`build_real_form` 通过 `parent.order.internal(external)` 将外部实形式编号转换为内部编号；非法编号产生 `Illegal real form number: n`。父级弱缓存 `canonical_forms` 使规范构造共享一个上下文，与 `same_real_form_owner` 的指针判定规则配对。自定义构造即使在数学上相等，也会建立新的属主，详见 [[实形式的规范弱缓存与属主身份]]。^[atlas-core-domain-dispatch.md:55-61]
