# 领域内建函数派发契约

领域内建函数派发契约描述 `domain_builtins.rs` 如何接收调用、检查参数、执行领域操作、包装返回值并报告错误。核心是 `match name` 派发；所述快照包含 166 个派发臂，来源仅覆盖入口与组织方式，不逐臂解释数学内容。^[atlas-core-domain-dispatch.md:9-13, atlas-core-domain-dispatch.md:27-38]

## 调用入口与求值纪律

`call(name, arguments, span)` 通过 `call_with_printed` 执行调用，并丢弃打印侧通道。`call_with_printed` 接收 `printed: &mut Vec<String>`；所述实现中，只有 `partial_extended_KL_block` 使用这一通道，对应上游 `ext_kl.cpp:945-948` 的中途 stdout 输出。^[atlas-core-domain-dispatch.md:17-25]

`call_owned_with_printed` 为三种饥饿乘积提供 `hungry_product_owned` 路径：`LieType×LieType`、`WeylElement×Vector` 与 `Vector×WeylElement`。该路径先检查组合秩的 `RANK_MAX` 限制，或权、余权大小是否匹配，再消费输入，分别执行 factors 合并、`word_act_weight` 或逐生成元 `simple_coreflect`。其余调用走普通借用适配路径；这一安排与 `typed.rs` 的 `HungryBuiltinCall` 求值纪律配对，可结合 [[TypedExpr 六族求值与值需求层级]] 阅读。^[atlas-core-domain-dispatch.md:18-23]

## 派发臂的统一结构

每个派发臂依次执行参数个数检查 `arity(name, arguments, n, span)?`、按类型提取参数、调用领域操作、将结果包装成 `Value`。类型提取使用 `as_lie_type`、`as_integer`、`as_matrix` 等适配器；错误通过 `type_error`、`runtime`、`structure_diagnostic` 或 `relation_diagnostic` 发出。相关调用机制见 [[函数调用分派与内建参数解包]]。^[atlas-core-domain-dispatch.md:29-32]

校验顺序也是契约的一部分。臂内注释说明：`build_KGB_element_wrapper` 在无值门之前完成全部构造检查；`KL_block_wrapper` 先执行 `test_standard`；`classify_involution_wrapper` 先检查矩阵为方阵且满足 \(M^2=I\)，再进行整数格分类。相关主题包括 [[BuildAndDrop 领域内建验证策略]] 与 [[对合类型的分层构造验证与错误优先级]]。^[atlas-core-domain-dispatch.md:32-35]

整数收窄先经过 `signed32`，再映射到 `unsigned32`；超出转换范围时使用错误信息 `Integer value too big for conversion`。部分同名调用按参数个数选择包装器，例如 `real_form` 区分 `(InnerClass,int)` 与 `(InnerClass,mat,ratvec)`。语言层重载解析位于 `typed.rs`，此处提供领域侧配对。^[atlas-core-domain-dispatch.md:36-38, atlas-core-domain-dispatch.md:70-72]

## 强制转换的领域侧契约

`coerce(tag, value, span)` 按标签选择领域转换。`LT` 与 `IcRf` 分别调用 `Lie_type`、`inner_class` 派发臂；`RdIc` 与 `RdRf` 则直接从 `InnerClass` 或 `RealForm` 句柄导航到根数据，不经过函数调用。`SpI` 与 `Sp(I,I)` 将整数或整数对转换为 `Split`，转换前先收窄到机器位宽，相关系数模型见 [[SplitInteger 分裂整数系数]]。^[atlas-core-domain-dispatch.md:40-46]

多项式转换包含展开、合并与排序。`KpolK` 将 `KType` 转为 `KTypePol`：经 `finals_for` 展开为 final 组分，逐项调用 `merge_ktype_term` 合并，再按 canonical `K_type_pol` 项序排序。`PolP` 将 `Param` 转为 `ParamPol`：经 `expand_final` 展开为 final 标准组分，合并后按 `SR_poly` 项序排序。相关概念见 [[finals_for 带号重数展开]] 与 [[可约点与标准参数 final 化]]。^[atlas-core-domain-dispatch.md:47-52]

未知转换标签产生运行时错误 `conversion '<tag>' is not implemented`。强转表的语言侧注册位于 `coercions.rs`，与这里的领域实现配对，参见 [[有序强制转换注册表]]。^[atlas-core-domain-dispatch.md:53-53, atlas-core-domain-dispatch.md:70-72]

## 实形式构造与属主身份

`build_real_form` 通过 `parent.order.internal(external)` 将外部实形式编号转换为内部编号；非法编号产生 `Illegal real form number: n`。`canonical_forms` 是父级弱缓存，使规范构造共享同一个上下文，并与 `same_real_form_owner` 的指针判定规则配对。自定义构造即使在数学上相等，也会建立新的属主。^[atlas-core-domain-dispatch.md:55-61]

## 证据范围

来源属于结构性阅读，不构成语言或数学验收。166 个派发臂与 697 行注释的计数仅标识 Git 基线 `964f0033` 对应的快照字节；校验顺序契约属于实现方陈述，行为仍以 HPC 语料门为准，参见 [[HPC 验收证据链]]。^[atlas-core-domain-dispatch.md:9-13, atlas-core-domain-dispatch.md:68-69]

各派发臂的数学内容，以及 `relation_*`、`merge_*`、`sort_*` 等适配器的实现，不在本包覆盖范围内。`InnerClassContext impl`、`RootNumbering`、`CenterClassifier`、`RootTable` 等区域也需由其他来源说明，不能从本页推定其实现细节或验收状态。^[atlas-core-domain-dispatch.md:63-67]
