# 领域包装器的校验顺序契约

领域包装器的校验顺序契约描述 `domain_builtins.rs` 中领域内建函数的检查与执行次序。派发臂的就地注释记录上游出处和校验顺序要求；这些要求属于实现方陈述，实际行为仍以 HPC 语料门为准。^[atlas-core-domain-dispatch.md:29-38, atlas-core-domain-dispatch.md:68-69]

## 派发的共同结构

`match name` 的各派发臂遵循共同流程：先通过 `arity(name, arguments, n, span)?` 检查参数个数，再用 `as_lie_type`、`as_integer`、`as_matrix` 等提取类型，随后调用领域操作并将结果包装成 `Value`。错误通过 `type_error`、`runtime`、`structure_diagnostic` 或 `relation_diagnostic` 发出。这是[[函数调用分派与内建参数解包]]的领域侧流程。^[atlas-core-domain-dispatch.md:27-35]

部分名字还按参数个数区分包装器。例如，`real_form` 分别接受 `(InnerClass,int)` 与 `(InnerClass,mat,ratvec)`。语言层的重载解析位于 `typed.rs`，这里记录的是与其配对的领域侧派发。^[atlas-core-domain-dispatch.md:36-38, atlas-core-domain-dispatch.md:70-72]

## 关键校验顺序

`build_KGB_element_wrapper` 在无值门之前执行全部构造检查，其注释指向 `atlas-types.w:4580-4607`。这一要求可结合 [[BuildAndDrop 领域内建验证策略]]与 [[KGB 构造的前置门控与不变量]]理解。^[atlas-core-domain-dispatch.md:32-34]

`KL_block_wrapper` 先执行 `test_standard`；`classify_involution_wrapper` 先检查矩阵为方阵且满足 \(M^2=I\)，再进行整数格分类。后者关联[[对合类型的分层构造验证与错误优先级]]。^[atlas-core-domain-dispatch.md:34-35]

整数收窄遵循固定次序：先收窄到 `signed32`，再映射到 `unsigned32`。来源同时记录了转换错误文本 `Integer value too big for conversion`。^[atlas-core-domain-dispatch.md:36-37]

## 消费参数前的检查

`call_owned_with_printed` 对三种同结果类型的饥饿乘积采用 `hungry_product_owned`：`LieType×LieType`、`WeylElement×Vector` 和 `Vector×WeylElement`。该路径先检查组合秩的 `RANK_MAX` 限制或权、余权大小是否匹配，再就地消费参数，分别进行 factors 合并、`word_act_weight` 或逐生成元 `simple_coreflect`。其他情况走普通借用适配路径；这一安排与 `typed.rs` 的 `HungryBuiltinCall` 饥饿求值纪律配对。^[atlas-core-domain-dispatch.md:18-23]

## 证据范围

来源仅完成结构性阅读，覆盖派发入口与巨型 `match name` 的组织方式，没有逐臂说明全部数学内容，也不声称语言或数学验收。166 个派发臂与 697 行注释的计数只对应 Git base `964f0033` 所标识的快照；这些记录不能作为全部包装器通过行为验证的依据。相关验收范围可参见 [[HPC 验收证据链]]。^[atlas-core-domain-dispatch.md:9-13, atlas-core-domain-dispatch.md:63-69]
