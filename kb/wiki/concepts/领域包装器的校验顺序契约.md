# 领域包装器的校验顺序契约

领域包装器的校验顺序契约描述 `domain_builtins.rs` 中领域内建函数的检查与执行次序。派发臂的就地注释记录上游出处及校验顺序要求；这些要求属于实现方陈述，实际行为仍以 HPC 语料门为准。^[atlas-core-domain-dispatch.md:29-38, atlas-core-domain-dispatch.md:68-69]

## 派发的共同流程

`match name` 的派发臂遵循共同结构：先通过 `arity(name, arguments, n, span)?` 检查参数个数，再用 `as_lie_type`、`as_integer`、`as_matrix` 等提取类型，随后调用领域操作，并将结果包装成 `Value`。错误通过 `type_error`、`runtime`、`structure_diagnostic` 或 `relation_diagnostic` 发出。相关背景见 [[函数调用分派与内建参数解包]]。^[atlas-core-domain-dispatch.md:27-35]

部分名字按参数个数区分包装器。例如，`real_form` 的两种参数形式为 `(InnerClass,int)` 与 `(InnerClass,mat,ratvec)`。语言层的重载解析位于 `typed.rs`，这里描述的是领域侧配对流程。^[atlas-core-domain-dispatch.md:36-38, atlas-core-domain-dispatch.md:70-72]

## 关键检查次序

`build_KGB_element_wrapper` 在无值门之前执行全部构造检查，其注释对应上游 `atlas-types.w:4580-4607`。这一约定可结合 [[BuildAndDrop 领域内建验证策略]] 和 [[KGB 构造的前置门控与不变量]] 阅读。^[atlas-core-domain-dispatch.md:32-34]

`KL_block_wrapper` 先执行 `test_standard`。`classify_involution_wrapper` 则先检查矩阵为方阵且满足 \(M^2=I\)，再进行整数格分类；相关主题见 [[对合类型的分层构造验证与错误优先级]]。^[atlas-core-domain-dispatch.md:34-35]

整数收窄遵循固定次序：先收窄到 `signed32`，再映射到 `unsigned32`。来源记录的转换错误文本为 `Integer value too big for conversion`。^[atlas-core-domain-dispatch.md:36-37]

## 消费参数前的校验

`call_owned_with_printed` 对三种同结果类型的饥饿乘积采用 `hungry_product_owned`：`LieType×LieType`、`WeylElement×Vector` 和 `Vector×WeylElement`。该路径先校验组合秩的 `RANK_MAX` 限制，或权、余权大小是否匹配，再就地消费参数，分别执行 factors 合并、`word_act_weight` 或逐生成元 `simple_coreflect`。其余情况走普通借用适配路径；这一纪律与 `typed.rs` 的 `HungryBuiltinCall` 配对。^[atlas-core-domain-dispatch.md:18-23]

## 证据范围

来源完成的是结构性阅读，覆盖派发入口及巨型 `match name` 的组织方式，没有逐臂说明全部数学内容，也不声称语言或数学验收。166 个派发臂与 697 行注释的计数仅对应 Git base `964f0033` 所标识的快照，不能据此认定全部包装器已通过行为验证；验收背景见 [[HPC 验收证据链]]。^[atlas-core-domain-dispatch.md:9-13, atlas-core-domain-dispatch.md:63-69]
