# 领域调用的无值门策略

领域调用的无值门策略由 `DomainNoValue` 表示，决定领域内建函数在 `NoValue` 求值级别执行多少工作：跳过、校验，或完整构造后丢弃结果。因此，不需要返回值并不意味着调用必然跳过执行。^[atlas-core-builtin-registry.md:42-47]

## 策略与实现分发

`BuiltinImpl::Domain { name, no_value: DomainNoValue }` 将领域调用名称与无值门策略绑定，并桥接到 `domain_builtins.rs`。无值策略是实现分发中的显式信息，相关结构见 [[内建函数元数据与实现分发]]。^[atlas-core-builtin-registry.md:26-30]

`DomainNoValue` 包含三种策略：`Skip` 跳过执行；`Validate` 执行校验；`BuildAndDrop` 完整构造后丢弃结果。最后一种策略可结合 [[BuildAndDrop 领域内建验证策略]] 阅读。^[atlas-core-builtin-registry.md:42-47]

## 与补全清单及打印包装的区别

**补全名称清单不是无值策略清单**，不能据此推导领域调用在 `NoValue` 级别的行为。来源明确举例：`orientation_nr` 注册为 `BuildAndDrop`，而非 `Skip`。注册范围与补全清单的关系见 [[内建注册表的启动清单与覆盖边界]]。^[atlas-core-builtin-registry.md:44-47]

领域打印包装采用独立的 `BuiltinImpl::DomainPrinter { name }` 分支。它在两个求值级别都会写报告，在 `single_value` 时产出空元组，且无值门之前没有诊断。其行为需按打印包装的约定理解，参见 [[打印、字符串转换与运行时错误的输出契约]]。^[atlas-core-builtin-registry.md:31-33]
